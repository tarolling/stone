# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

stone is a small Python-like language implemented in Rust (edition 2024, only dependency: `clap`, except for the opt-in `self-update` feature). The workspace also holds `lsp/`, the `stone-lsp` language server, which has its own dependencies, and `editors/vscode/`, a VS Code extension that runs it. One binary provides both a tree-walking interpreter and a compiler for x86-64 and arm64 Linux and arm64 macOS. Blocks open with `:` as in Python (e.g. `if x:`, `fn f(a: int, b: int) -> int:`), and `;` is not a token at all (`unexpected character ';'`); functions return with `ret`, and `continue` is `cont`. Every function parameter has a type, and a function that returns a value writes `-> T` (without it, it returns no value, and its call can only be a statement); nothing else is ever annotated. Enums are Rust's algebraic data types (`enum Shape:` with a variant per line, `Shape.Circle(1.0)`, `match s:` with `case Shape.Circle(r):`), and `option[T]` (`some(x)` or `none`) is an ordinary generic enum that `src/prelude.stn` defines and every program is linked with, its variants written alone; `none` is only an option. `result[T, E]` (`ok(x)` or `err(e)`) is another prelude enum, and postfix `?`, the only syntax it adds, gives an `ok`'s or a `some`'s value or returns the `err` or `none` from the enclosing function, which must return a result with the same error type (or an option). The prelude also defines one struct, `output` (`status: int`, `stdout: str`, `stderr: str`), which `os.run(cmd, args) -> result[output, str]` returns; like `result`, its name may be taken by a variable (the checker's `value_struct`), but not by a function. Structs are Rust's structs, data only for now: `struct Point:` with a typed field per line (`x: float`), made with a named value for every field in any order (`Point(x=1.0, y=2.0)`), read as `p.x`, and changed in place as `p.x = v`, `ps[i].x += v`, or `p.items.append(v)`; like lists they are values. An `impl Point:` block, in the struct's own file, holds its functions: a method takes `self`, untyped, first and is called as `p.norm()`, and an associated function is called as `Point.origin()`; a method that changes `self` changes its receiver in place, as `append` does, with no keyword, and its call is a statement or the whole value of an assignment. Functions can be generic, with type parameters in brackets after the name (`fn first[T](xs: list[T]) -> T:`), which each call infers; the body is checked once with `T` opaque (it can be moved, stored, and printed, but has no operators, comparisons, or methods), and `stone build` compiles a copy per set of types. Structs and enums can be generic the same way (`struct Pair[A, B]:`, `enum Tree[T]:`), written with their types filled in (`Tree[str]`); an `impl` block of a generic struct takes no brackets, and its methods are generic over the struct's parameters. Maps are `map[K, V]` with `int`, `str`, or `bool` keys, written `{"a": 1}` (`{}` empty), read as `m[k]` (failing with `key not found: 'k'`), set as `m[k] = v` or changed through any place (`m[k] += 1`, `p.m[k].append(x)`), with `len`, `contains`, `get`, `pop(k)` (an option), `keys`, `values`, and `items`, iterated by key (`for k in m`), kept in insertion order, and values like lists. `in` and `not in` (`CompOp::In`/`NotIn`) test a map's keys, a list's elements (by `==`), or a string's text, as `contains` does on all three, and never chain with other comparisons (a checker error); the checker's `membership` (deferred through `Membership` when the container is unknown), the interpreter's `contains`, and the lowering's `contains_values` (an inline loop over borrowed elements for a list) serve both forms. Traits are Rust's, with static dispatch only: `trait Shape:` lists methods, body-less (`fn area(self) -> float`) or with a default body, `impl Shape for Circle:` implements them for a struct or for `int`, `float`, `bool`, or `str`, and bounds (`fn total[T: Shape + Named](xs: list[T])`) give a type parameter its traits' methods; `Self` names the type in a trait or `impl` block. The prelude's traits `eq` (automatic for every type `==` compares part by part, overridable by a struct's `fn eq(self, other: Self) -> bool`) and `ord` (`int`, `float`, `str`, or a struct's `fn cmp(self, other: Self) -> ordering`) back `==`, `<`, and `sort`, and `ordering`'s variants `less`, `equal`, `greater` are written bare like `some`. A trait may have type parameters (`trait add[R]:`), which a type implements once per set of arguments (`impl add[int] for V:`, `impl add[V] for V:`), a call picking the impl its arguments fit, and a bound gives them (`[T: add[U], U]`). Conversions are the prelude's generic traits `from[T]` (`fn from(value: T) -> Self`) and `try_from[T]` (`fn try_from(value: T) -> result[Self, str]`), the only trait functions without `self`: a type called with one positional value, `T(x)` (`int(s)`, `Fahrenheit(c)`, `T(n)` under `[T: from[int]]`), converts it, giving a `T` or a `result[T, str]`. Builtin: every type from itself and to `str` (through `display`), `float` from `int`, and through `try_from` (so results) `int` from `float` or `str`, `float` from `str`, and `bytes` from `list[int]`; there are no `parse_int`/`parse_float`. Every string literal interpolates with no prefix: `"{name} has {xs.len()}"` writes each braced expression (any expression, strings of its own included) as `print` writes it, `{{` and `}}` are braces, and `:` in a hole is reserved for format specs, not supported yet. `str(x)` takes any value, and the prelude trait `display` (`fn display(self) -> str`, automatic for every type, overridable by a struct as `eq` is) backs `print`, `str`, `x.display()`, and interpolation, wherever a value appears. Functions are values: a top-level function's name without parentheses (`apply(double, 3)`, `geo.area`, a generic one taking its types from its use) has the type `fn(int) -> int` (`fn(str)` for one without `->`), and any value of a function type is called (`f(x)`, `fs[0](x)`, `p.run(x)` for a struct field holding one); a lambda writes one in place, `|x| x * 2` or `|p: Point| p.x` (bars around the parameters, whose types are inferred from where it is used unless written, and one expression on the same line), using no variable but its own parameters (a global or an enclosing function's variable is an error, since there are no closures yet); builtins, methods, and variants are not values, function values are never compared, and they print as their type (`type_text`), so inside generic code a function named as a value may not have a type that depends on the type parameters (the interpreter makes no copies to tell). Lists' methods `map`, `filter`, `any`, `all`, `sort_by_key` (changes the list), `min_by_key`, and `max_by_key` (options) take a function and are prelude functions (`stdlib::PRELUDE_METHODS`), as are `a.min(b)`, `a.max(b)`, and `x.clamp(lo, hi)` on every `ord` type (`stdlib::ORD_METHODS`; a struct's own method or a bound's of the same name wins), where the prelude's `clamp` returns `(in_order, value)`, a tuple so nothing is allocated, and both backends fail with `stdlib::CLAMP_RANGE` at the call when `in_order` is false (the interpreter's `call_method_of_struct`, lowering's `struct_call`). The `net` module (`use net`) makes TCP connections: `net.connect(host, port) -> result[socket, str]`, `net.listen(host, port) -> result[listener, str]` (port 0 picks one), and `net.resolve(host) -> result[list[str], str]`; `socket` (`send`, `read_line`, `read`, `read_all`, `close`) and `listener` (`accept`, `port`, `close`) are builtin types a signature names like `str`, handles rather than values (copies share the connection, they are never compared or map keys, and they print as their type), and each closes right after the last statement that uses it, at the same point in both backends. `net` is written in stone (`src/stdlib/net.stn`), finding addresses itself from `/etc/hosts`, `localhost`, and DNS servers in `/etc/resolv.conf` (`STONE_HOSTS` and `STONE_RESOLV_CONF` override the paths; a `nameserver` may give a port, as `127.0.0.1:5353`), so both backends agree; no TLS. Sockets also send and read `bytes` (`send_bytes`, `read_bytes(max)`, `read_exact(n)`, `read_all_bytes()`, sharing one buffer with the text reads), and `set_timeout(seconds: float)` on a socket or listener, or `net.connect_timeout(host, port, seconds)`, makes each wait give up with `err("timed out")` (milliseconds rounded up, `<= 0` or nan forever). `bytes` is a builtin type for data that is not text: literals `b"a\x00\xff"` (`\x00`-`\xff`, ASCII otherwise, no interpolation), `b[i]` an int, slices, `+`, `==`/`<`, `in`, `for` over ints, `sort`, printed as Python's repr (`stdlib::repr_bytes`), never changed or a map key; `s.bytes()`, `b.text() -> result[str, str]`, `bytes(xs: list[int])` (a result, `err("byte out of range (value 300)")`), and `fs.read_bytes`/`write_bytes`/`append_bytes`. See `examples/basics.stn` for a sample program.

## Philosophy

`docs/philosophy.md` is the source of truth; read it before designing a feature. In short: Python's simplicity with Rust's memory safety, speed, and error reporting, achieved by moving all complexity into the compiler, and compiled programs that depend on no libc (raw syscalls on Linux, the thinnest system layer on macOS and Windows) and no gcc, since `stone build` assembles and links itself. If the compiler can infer something (types, ownership, laziness, copies), the language never asks the programmer to write it, with one exception: function signatures are written, for readable contracts and errors at the place a mistake is made, and everything inside them is inferred, as in Rust; prefer changing semantics so the fast, safe choice is always valid over adding a keyword. stone has value semantics: assignment, argument passing, and storing in a list behave as copies, implemented with copy on write and in-place updates of uniquely owned values, so a function changes its caller's list only by returning it (`xs = f(xs)`, which both backends turn into an in-place update by moving `xs` into the call, as they move any value at its last use). When goals conflict, rank safety, then programmer simplicity, then clear errors, then speed, then compiler simplicity. Keep the page's "Status" notes current as work lands.

## Architecture

The crate is a library (`src/lib.rs`) plus a thin CLI (`src/main.rs`, clap only). Pipelines are wired in `src/driver.rs`:

- **load** (`driver::load`, used by `run` and `build`): `project::link` (`Lexer` → `Parser` for the entry file and every module it uses, then linking) → `TypeChecker`, returning a `Checked` (the linked `Mod`, any warnings, which `run` and `build` print before going on, and the checker's `Calls` (`Analysis::calls`: the `Methods`, every function value with its printed type, and every call of a value), which `run_module` gives the interpreter) and a `SourceMap` for rendering diagnostics from any file
- **run** (`driver::run_module`): load → `Interpreter`. `driver::interpret` does the same for a single source string with no other files
- **build** (`driver::compile_module`, given the `Checked` and a `Target`): load → `Target::generator` (`X64Generator`, or `Arm64Generator` for the target's `Os`), given `Checked::analysis` through `set_analysis` so `Context::check` does not check the module again → `compile` (check, scan pass lowers to IR, inlines small leaf functions (`ir::inline`) and optimizes it (`ir::opt`), generate pass allocates registers and emits, then `codegen::link` writes the `.s` file, and `codegen::executable` encodes it with `asm::assemble` and links it with `elf::link` or `macho::link`)
- **repl** (`driver::repl`): `repl::run` on a `Limits::STACK_SIZE` thread with one `Interpreter` for the whole session. Each entry is checked through `driver::load` together with the text of every earlier kept statement (`Session`), minus any function the entry defines again, then only its statements run (`Interpreter::run_entry`, which echoes non-`none` expression values). An entry is read until `repl::needs_more` says it is complete (a `:` ending a line opens a block, closed by a blank line); prompts go to stderr only when stdin is a terminal A `Chunk` lists what it defines (an `impl` block each of its functions, as `S.get`), and an entry replaces every kept chunk that defines any of the same.
- **fmt** (`format::format`, `main.rs`'s `fmt`): a token formatter, since every statement is one line (newlines end statements inside brackets too) and the AST loses comments, parentheses, and literal spelling. It lexes with `Lexer::keeping_comments` (comments recorded with their spans in `Lexer::comments`, tokens unchanged), parses as the prelude (so a variant may be `none`) to refuse what does not parse, groups tokens into `CodeLine`s by `Newline` with a level from `Indent`/`Dedent`, and writes each at four spaces per level, its tokens joined by `Spacer` (a stack of `Group`s: `Index` for a `[` after a value, whose `:`s stay tight, `Square` for others including a definition header's type parameters, `Paren` for `x=1` named values, `Hole` for a string's values; a `Kind` per token, `-` unary after anything that does not end a value) and literals copied from the source by span. A comment-only line takes the deepest level whose source width is at most its own, or the next level right after a block opener; runs of blank lines become one, none after a block opener. Before returning it lexes the result and requires the same token types and comment texts, else an error naming it a bug. `driver::stone_files` lists a directory's `.stn` files (skipping hidden and marked build directories) for the CLI and `tests/format.rs`, and the LSP's `features::formatting` answers `textDocument/formatting` with one whole-document edit
- **check** (`driver::check_program`): `project::link` → `TypeChecker`, returning every `Diagnostic` instead of running. `driver::analyze_linked` is the entry point for editor tooling

Key pieces:

- `src/span.rs`: `Pos` (1-based line and col, counted in chars), `FileId` (the entry file is `FileId(0)`, and the prelude `FileId::PRELUDE`, which `SourceMap::file` answers but `files` leaves out), and half-open `Span`, which holds a `FileId`. Every token and AST node carries one. `Span::new` puts a span in the entry file, and `Lexer::with_file` lexes another file.
- `src/prelude.stn`: the prelude (`stdlib::PRELUDE`), which `project::link` parses in `FileId::PRELUDE` and puts first in every linked module, keeping its names (`option`); the parser lets only it name a variant `none`. `Rewriter::prelude_variant` rewrites a bare `some`/`none` (not a local) to `option.some`/`option.none` with a zero-width span on the unwritten `option`, `pattern` does the same to `["some"]`, and a written `option.x` is an error. Code that parses without linking (unit tests through `driver::parse_program`, the `codegen` fuzz target) must link, or options do not exist. `none` parses to `ExprKind::Name`, since `Constant` has no `None`. It also defines `enum result[T, E]` (tags 0 `ok`, 1 `err`, which `stone.parse_int_result` and `stone.parse_float_result` make by tag), `enum ordering` (tags 0 `less`, 1 `equal`, 2 `greater`, which builtin `cmp` makes by tag), the traits `eq`, `ord`, `display`, `from[T]`, and `try_from[T]`, and `fn sort[T: ord]`, a stable merge sort in stone that `xs.sort()` uses for anything but int/float/str (`stdlib::PRELUDE_SORT`). Since a prelude enum's name never comes before a written variant, a value may take it (`result = []`): the linker writes the enum's name before a bare variant with an empty span, which `Expr::is_unwritten` recognizes and `Expr::children`, `last_use::expr_names`, `AssignmentCheck`, and `ParameterUse` skip, `checker::may_name_enum` tells the backends whether a name before a dot may be an enum (never a written prelude enum name), the checker's `value_enum` keeps only other enums' names from variables, and `Rewriter::globals` (the entry file's top-level names) and `locals` exempt a variable from the `result.ok` error. `stdlib::PRELUDE_VARIANTS` pairs each bare variant with its enum (`stdlib::prelude_variant`), which `prelude_variant`, `pattern` (a bare `PatternKind::Name` such as `case less:` too), and `prelude_qualified` use, and `prints_bare` covers `ordering`. `project::prelude` renames each prelude `fn` to `prelude.<name>` (`PRELUDE_MODULE`, so a root `prelude.stn` is an error); a prelude function calls no other, so nothing else is rewritten. `Context::types` skips prelude spans, so the unused `sort` body pulls in no runtime.
- `src/project.rs`: multi-file programs. The entry file's directory is the root, and `a/b.stn` is the module `a.b`; directories are only parts of names, so there are no barrel files. `use a.b` binds the module (called as `b.f()`), `use a.b.f` binds a `pub fn` of `a.b` (a module file wins over a function of the same path), and `as` renames. Library modules hold only `use`, `fn`, and `enum`, so importing runs nothing and cycles are fine, and their functions cannot see the entry file's names, types and traits included: the entry file's types and traits keep their plain names, so `checker::visible_type` (a qualified name, a prelude type or trait, or code in `FileId::ENTRY`) hides them from other files in the checker's `resolve_name`, `value_enum`, `value_struct`, `written_type`, `declare_type_params`, `bounds`, and `impl_trait`, and in both backends through `may_name_enum` and `may_name_struct`, so the prelude's local `keys` stays a variable beside a `struct keys`. `pub enum` is imported like a function (`use zoo.Animal`, `Target::Enum`, `public_enums`), and `Rewriter` renames enums to `<module>.<Name>` in signatures and variants (`type_expr`), in front of a variant (`name`, `qualified_enum` for `zoo.Animal.Fish`), and in patterns (`pattern`). `link` loads files through `Sources` (`FsSources`, or `MapSources` in tests), reports `use`/`pub` errors with the checker's wording, and merges every file into one `Mod` in which each library function is renamed to `<module>.<name>` and each use of it rewritten to that name, so the checker and both backends run unchanged (`fn.geometry.shapes.area` is a valid label). `link_in` picks another root, for editors. `pub struct` works as `pub enum` does: `public_types` lists a file's enums and structs together, `is_struct` tells `use geo.Point` to give `Target::Struct` rather than `Target::Enum` (both bind `Binding::Type`), and `module_member` rewrites `geo.Point(x=1)` to a call of the linked name `geo.Point`. `os`, `math`, `random`, `time`, and `fs` are builtin modules with no file (`stdlib::MODULES`, `Loader::resolve_builtin_module`, `Target::BuiltinModule`): `use math`, `use math.sqrt`, and `use math as m` work anywhere, calls are rewritten to linked names such as `math.sqrt` like library functions, and a `math.stn` (or `os.stn`, ...) in the root is an error. The checker reports any `use` left in the module, which can only be a nested one. Tests in `src/project/tests.rs`. An `impl` block must name a struct of its own file (`own_structs`; an enum or an imported struct is an error), is renamed like the struct in a library, and its functions are rewritten as `fn`s are (`Rewriter::function`) but keep their names, since their linked name is the struct's plus theirs; `report_method_collisions` reports a module function with the same linked name as a method. `Rewriter::set_type_params` keeps a generic definition's type parameters (and, for the functions of an `impl` block, its struct's, from `own_structs`) in `type_params`, which `type_expr` never renames, and reports one named like a type the file imports or, in a library, defines (the checker reports the rest). Traits: `public_types` lists `trait`s too, `use geo.Shape` gives `Target::Trait` (bound as `Binding::Type`), a library's traits are renamed `<module>.<Name>`, and `Rewriter::trait_name` rewrites bounds (`Rewriter::bounds`, from `function`) and an `impl` block's trait (`geo.Shape` through `module_type`). `impl Tr for Ty` must be in the file of `Ty` (a struct) or of `Tr` (`Rewriter::impl_type`, with `struct_params`/`trait_names` of every file, for an imported struct's type parameters and a builtin type), except a prelude trait on a builtin type, which the checker reports; `type_expr` never renames `Self`. `report_method_collisions` covers trait default methods (`Trait.m`). A module of `stdlib::SOURCE_MODULES` (only `net`, whose source is `stdlib::net::SOURCE`) is part of stone but written in stone: `Loader::module` adds its embedded source as the library module of that name, at the path `<net>` (`SourceFile::is_builtin`), so it links, checks, and runs like a user's library (functions `net.connect`, ...), `check_builtin_name` rejects a root `net.stn`, and `is_entry` never matches it. Such files, and only they (`Loader::own`), may `use` an internal builtin module of `stdlib::INTERNAL_MODULES` (`net_sys`, whose functions `stdlib::module` and `module_function` find but `MODULES`, the docs test, and editors do not list); anywhere else it is `no module named 'net_sys'`.
- `src/diagnostic.rs`: `Diagnostic` (severity, span, message) with `render` for the CLI, and `Diagnostics` for returning several as one error. Every stage's errors convert to it.
- `src/token.rs`: `Token`/`TokenType` and `RESERVED_KEYWORDS`. `Keyword` and `Operator` hold `&'static str`s (the lexer hands out the entry of `RESERVED_KEYWORDS` or its operator table), so `expect(TokenType::Keyword("fn"))` allocates nothing. The lexer (`src/lexer.rs`) emits Python-style `Indent`/`Dedent`/`Newline` tokens, and `->` as `Arrow`, lexes a string with values as `StringStart(text)`, each value's own tokens, `StringMiddle(text)`, ..., `StringEnd(text)` (`lex_text`, with a `holes` stack of bracket depths so `}` ends a value only at depth 0, and errors for `{}`, a lone `}`, a depth-0 `:`, and a newline inside a value), a string without as `String`, and reads string escapes (`\"`, `\'`, `\\`, `\n`, `\t`, `\r`, `\xhh` up to `\x7f`, never `\x00`, since compiled strings are null-terminated). `Lexer::lex` stops at the first error; `Lexer::lex_recovering`, which `project::Loader::add` uses, records each error, skips the rest of its line (closing any open values), and goes on, and `Loader::add` drops parser errors on a line the lexer cut short, so an unfinished value such as `print("{xs.` keeps the rest of the file analyzed. `context::escape` writes other control characters into `.string` directives as three octal digits, which `asm::parse_string` reads.
- `src/ast.rs`: AST (`Mod`, `Stmt`, `Expr`, `Constant`, `ParserError`, `TypeExpr`, a type written in a signature, which `Arg::annotation` and `FunctionDef`'s `returns` hold, …), modeled on the ASDL in `docs/grammar/stone.asdl`. `ExprKind::JoinedStr { values }` is a string with values (`parse_string`; `parse_strings_loop` joins adjacent literals and their text pieces), each value a `Constant::Str` text piece or a hole expression; a string without values stays a `Constant`. `ExprKind::Tuple` is a tuple of two or more values (`(1, "a")`, ctx `Load`) or, as an `Assign` or `For` target, names to unpack into (`q, r` or `a, (b, c)`, ctx `Store`), whose names `target_names` collects; `TypeExprKind::Tuple` is `tuple[int, str]`. `constant_int` reads an int literal, possibly negated. `Expr` and `Stmt` are structs of a `kind` (`ExprKind`/`StmtKind`, the ASDL variants) plus a `span`, so match on `&expr.kind`. A method call such as `xs.len()` is a `Call` whose `func` is an `Attribute`; attributes mean nothing outside a call. A slice `xs[a:b:c]` is a `Subscript` whose `slice` is an `ExprKind::Slice` (each bound optional), which appears nowhere else; `stdlib::slice_indices` turns its bounds into Python's `slice.indices` for both backends. An augmented assignment `target op= value` is its own `StmtKind::AugAssign`, not rewritten to `Assign`, because an element's indexes are evaluated once: indexes, then the old element (an index out of range fails before the value runs), then the value. The checker records the operation's type at the statement's span; the interpreter's `augmented` and `element` compute it, and `Lowerer::aug_assign` lowers a name target as the equivalent `Assign` (so `a += b` writes over `a` in place) and an element as a borrowed `ListLoad`, the operation (`Lowerer::binary` or `elementwise_tree`), then `store_element`. `StmtKind::EnumDef` holds `Variant`s (name and field `TypeExpr`s), and `StmtKind::Match` holds `MatchCase`s, each a `Pattern` (`PatternKind::Wildcard` for `_`, `Name` to bind, or `Variant` with a `path` such as `["Shape", "Circle"]`, or `["some"]` and `["none"]`, which linking turns into `["option", "some"]`, and field patterns; `Pattern::names` lists what one binds) and a body. Any written type other than `int`/`float`/`bool`/`str`/`list`/`tuple` is `TypeExprKind::Named` (an enum, maybe dotted, or `option[T]`). Variant values need no new expression kind: `Shape.Circle(1.0)` is a `Call` of an `Attribute` and `Shape.Empty` an `Attribute`, which the checker, interpreter, and lowering recognize because the name before the dot is an enum. `StmtKind::StructDef` holds `Field`s (name and `TypeExpr`). `ExprKind::Call` has `keywords`, the named values (`Keyword`) after the positional ones, which only a struct takes; the checker reports them anywhere else. An `Attribute` outside a call is a struct's field, and as a target (ctx `Store`) a change. Parser tests build expected trees with `.into()` and compare them through `without_spans`. `StmtKind::ImplDef` holds an `impl` block's `FunctionDef`s (`parse_impl_def`, `parse_methods`, which hints at `pub fn`). `FunctionDef::type_params`, `StructDef::type_params`, and `EnumDef::type_params` hold the `TypeParam`s of a generic definition (`parse_type_params`, after the name); a use of `T` in a signature is a plain `TypeExprKind::Named`. `ExprKind::Try { value }` is `value?` (`PrimaryOp::Try`, a fourth alternative in `parse_primary_loop0`, so it chains like a call), and `Expr::without_try` strips it, so a statement's or assignment's call is still found through `x = f(x)?`. `StmtKind::TraitDef` holds `FunctionDef`s whose `body` is empty when written without one (only `parse_trait_def` makes such), `ImplDef::trait_name` is the trait before `for`, and `TypeParam::bounds` the `TraitName`s after a colon (dotted for `geo.Shape`).
- `src/parser.rs`: hand-written recursive-descent PEG parser. Rules fail constantly while it backtracks, so failing allocates nothing: `ParserError` is a rule name and a span (`error_here`), `expect` compares before cloning, and an `Expected` holds a `Wanted` token or static text that only `syntax_error` describes. A statement tries only the alternatives its tokens allow (`parse_compound_stmt` by `compound_keyword`, `parse_simple_stmt` by a leading `ret`/`use`/`break`/`cont` and by `assignment_shapes`, a `=` or augmented operator outside brackets); a statement that fails is parsed again with `exhaustive` set, trying everything, so its error is what the full grammar reports, and `shortcuts_parse_every_program_alike` and `shortcuts_report_errors_alike` in the parser tests check both modes agree (and that no rerun succeeds, `rescued`). Syntax errors come from the furthest token any rule failed at: `expect`, `expect_name`, `expect_block_start` (the `:` that opens a block, never quiet, though `Colon` elsewhere is), and `record_expected` note what was wanted there, and "quiet" expectations (operators, keywords, and other optional continuations) only show when nothing else was expected. A rule that recognizes a common mistake notes a `hint` at the token where it stopped, which replaces the message if parsing fails there: values separated by commas without parentheses (`x = 1, 2`, `ret a, b`; `parse_expressions` parses one expression and hints at a comma list), `()`, `(x,)`, `a, = t`, `tuple[int]`, `none` as a type, `Circle()`, and a literal as a pattern. `parse_enum_def` and `parse_match_stmt` read their own `NEWLINE INDENT ... DEDENT` blocks of variants and of `case pattern ':' block`s (`parse_pattern`); `case` is the one keyword besides `in` that is not a quiet expectation. `parse_struct_def` and `parse_fields` read a struct's `NAME ':' type` lines, `parse_args` reads `NAME '=' expression` as a keyword (`parse_kwarg`, looking ahead for `=`) and hints at a positional value after one, and `parse_target_with_star_atom` accepts `t_primary '.' NAME` as a target. `parse_tuple_or_group` parses `'(' expression` once and then decides, so nesting stays linear, and `parse_star_targets` takes names separated by commas, nested in parentheses through `parse_star_atom`. The struct, token helpers, and `parse()` entry are here; rules live in `src/parser/expressions.rs` and `src/parser/statements.rs` as `pub(super)` methods so siblings can call each other. Functions mirror rule names in `docs/grammar/stone.gram` (derived from CPython's grammar), e.g. `parse_t_primary`, `parse_star_targets`, `*_loop0` for repetition. Keep the `.gram`/`.asdl` docs in sync when changing syntax. Traits: `parse_trait_def`, `parse_methods(in_trait)`, `parse_function_def_in(in_trait)` with `parse_function_body` (a `NEWLINE` instead of `':' block` in a trait), `parse_impl_def` with `parse_trait_name` and `parse_impl_target` (`for` is a quiet expectation after the first name), and `parse_type_param` for `T: A + b.B`.
- `src/checker.rs`: `TypeChecker::analyze` infers types (`int`, `float`, `bool`, `str`, `list[T]`, tuples, enums and `option[T]` as `Type::Enum`/`Ty::Enum` with type arguments, structs, and functions, possibly generic) by unification, taking each function's parameter and return types from its signature (`declare_function`, `Inference::written`; no `->` is `Type::Unit`, no value, which `infer` reports anywhere but an expression statement: `'f' returns no value`). The parser accepts a parameter without a type so editors keep working, and `finish` reports it, and a value returned from a function without `->`, suggesting the type inference found, resolves names Python-style (a function's params and assigned names are local, other names are globals or top-level functions, which are visible before their definition), and returns an `Analysis`: sorted diagnostics, the `Type` of every expression keyed by span, and `Symbol`s with every `Reference`. It only accepts what both backends run identically, e.g. conditions must be `bool` (`if 1 or 0:` is an error), arithmetic never mixes `int` and `float` (convert with `int()` or `float()`), even element by element, `==` cannot compare lists or maps, even inside a tuple, struct, or enum (`equalities`, which `finish` settles through `check_equality`; `uncomparable` finds the list or map and the struct field holding it, for the error), `range` only appears as a `for` iterable, functions must be top level, a method must be called (`xs.len`, without parentheses, is an error), and top-level code and functions must assign a variable on every path before reading it (`AssignmentCheck`). Since lists are values, a change (`xs[i] = v`, or a method that `stdlib::changes_receiver`, i.e. `append`) is a statement of its own, made to a variable or an element of one (`check_change`; `place` and `place_root` split such a target), and a function cannot change a global. `lost_change` warns when a function changes a parameter it never otherwise reads, and `collect_changed` lists the variables a body changes, for lowering. A change that returns a value (`pop`, or a method that changes `self`) may be anywhere in an expression: `check_changing_call`/`note_changing_call` record each in `changing_calls`, and `check_stmt` (around `check_stmt_kind`) reports any other use of what an inner one changes in the same statement's own expressions (`Stmt::exprs`, `place_mentions`, `first_conflict`, overlapping field paths from `changed_path`), unless it is another changing call's receiver or the call is a statement or the whole value of an assignment (`statement_call`, `assigned_call`); `collect_changed`, `ParameterUse`, and `block_changes_self` find changing calls anywhere in a statement through `Expr::visit`. Arithmetic works on numbers or, element by element, on `list[int]`/`list[float]` with a number broadcast to every element, so an operator becomes an `Arithmetic` that `solve_arithmetic` settles once its operands are known to be lists or numbers, and `finish` forces the rest (an unknown operand becomes a number); meanwhile `Bound`s on its unknown operands (`n` in `n * 2` is `int` or `list[int]`) make `unify` reject a wrong argument at the call, as before. `[x] * n` warns, since Python would repeat it. A tuple (`Type::Tuple`, `Ty::Tuple`, `Kind::Tuple`; `Type::leaves` flattens nested tuples and `field_leaves` finds a field's) is indexed only by a constant in range (`tuple_field`; `subscript_of` returns what it `Indexed`), only once its type is known, except that a constant index into a global a function reads before the code assigning it is checked is settled in `finish` (`DeferredIndex`). Tuples never change (`TUPLE_CHANGE`, also for a list inside one, through `indexed_tuples` in `check_change`), cannot be ordered, iterated, converted, or used in arithmetic or conditions, and unpack into names only, each once, as many as the tuple has values (`check_unpacking_names`, `unpack`, which records each nested pattern's type). A list element may hold at most `MAX_ELEMENT_VALUES` values (`check_element_width`, on list literals and written types). Enums: `declare_enums` registers every top-level `EnumDef` before functions (names first, so variants can hold any enum), with `SymbolKind::Enum` and `SymbolKind::Variant` symbols (a variant's `scope` is its enum, and `visible_at` hides it); `option` is the prelude's enum like any other (`OPTION` names it for the builtins that return one; tag 0 `none`, tag 1 `some`, which `stdlib`'s prelude test pins), declared from its `EnumDef` in `FileId::PRELUDE`, where `declare_enum_names` and `declare_type_params` skip the reserved-name checks; `prints_bare` makes its variants print and appear in errors alone, and `variants`/`variant_display` give any enum type's variants and printed names from `Analysis::enums`. `add_reference` ignores zero-width spans, the names linking wrote. `infer_variant` checks `Shape.Circle(...)` and `Shape.Empty`, and so `option.some(x)` and `option.none`, and `is_some`/`is_none`/`unwrap`/`unwrap_or` are option methods. Reserved names go through `stdlib::is_reserved` (`BUILTINS` plus `PRELUDE_VARIANTS`). `check_match` checks each `Pattern` against the subject (`check_pattern`, `variant_of_pattern`; names bind through `check_target`, and `collect_assigned` collects them, so they are ordinary variables), and `finish` runs `check_cases`, Maranget's usefulness check over `Space`s (`useful`, `missing`, `specialize`), for a missing pattern (an error naming it) and unreachable cases (a warning). Enums and options cannot be converted with `str`, iterated, or used as conditions; a match whose cases all exit `always_exits`. Structs: `declare_types` declares every enum's and struct's name before any variants or fields (`declare_struct_names`, `declare_fields`), so they can name each other, with `SymbolKind::Struct` and `SymbolKind::Field` symbols (a field's `scope` is its struct, and `visible_at` hides it), then reports a struct that `reaches` itself through fields and tuples alone (it may hold itself through a list or enum). A struct is `Type::Struct { name, args }`/`Ty::Struct`, nominal; `Analysis::structs` (`Structs`) holds each one's fields, which `Type::leaves` and `Type::struct_field` (a field's leaf range and type) need, since structs flatten like tuples (`Type::is_flat`), and `values`/`check_element_width` count their leaves. `infer_struct` checks `Point(x=..., y=...)` (every field once, named, no positional values) and records a reference on each keyword's name, `field_of` checks `p.x` (deferred like a tuple index for a global a function reads before its assignment, `DeferredField`), and `struct_display` is the printed name without the module. Places are steps (`Step::Index`/`Step::Field`): `place` splits `ps[i].x` into `ps`, the index `i`, and the field `x`, `place_spans` gives a span per step, and `check_change`, `collect_changed`, and `ParameterUse` treat a field target as a change to its root variable, so a function owns a struct parameter whose field it assigns. Methods: `declare_methods` declares each function of an `impl` block in `functions` under `<struct>.<name>` (`signature` gives a first untyped `self` the struct's type and reports `self` anywhere else), with a `SymbolKind::Method` symbol whose `scope` is the struct, and `struct_methods` records whether it has `self` and, from `find_changing_methods`, whether it changes `self` (a fixpoint over the bodies that types places in `self` from the fields' written types alone). `infer_associated` checks `Point.origin()` (`struct_named`), and `infer_struct_method` a method on a struct, before any builtin method of the same name, applying `append`'s rules (`check_change_of`) to one that changes `self`; a receiver of unknown type is settled in `finish` (`DeferredMethod`, after `DeferredField`s). Every resolved call goes in `Analysis::methods` (`Methods`, a `Method` per call span), which `changed_receiver`, `collect_changed`, and `lost_change` take so a changing method counts as a change. Generics: `declare_type_params` gives each type parameter a `TypeParamInfo` (`Inference::type_params`, indexed by the rigid `Ty::Param`, which unifies only with itself) and a `SymbolKind::TypeParam` symbol scoped to its function, and puts it in `scope_params` while `written_type` reads the signature; `FunctionInfo::type_params` lists them. `Kind::Param` is in no constraint set, `solve_arithmetic` treats it as a known non-number, `check_equality`/`uncomparable` reject it, and `infer_method` reports any method on it. `infer_call` instantiates a generic callee with fresh variables (`substitute`) and records a `PendingInstance` (call span, caller, args); `finish` runs `check_instances` (a cycle through a call that nests a type parameter, found over (parameter -> parameter) edges, is an error; then every concrete instantiation is walked to check list elements and map entries in the generic bodies' `expr_types` against `MAX_ELEMENT_VALUES`) and `check_captured_params` (a global whose type holds a type parameter), then gives lowering `Analysis::instances` (an `Instance` per call span, whose args may be the caller's own `Type::Param`) and `Analysis::type_params` (names by generic function, struct, or enum). Generic types: `Ty::Struct` carries type arguments like `Ty::Enum`, and `EnumInfo`/`StructInfo` hold `type_params`; `declare_types` declares every type's parameters after all names, then fields and variants with them in scope (`enter_type_params`), then `check_growing_types` reports a type that holds itself with nested type arguments (`enum Bad[T]: X(Bad[list[T]])`). `own_type` is a type with its own parameters as arguments (`self` in its `impl` block, whose methods' `FunctionInfo::type_params` are the struct's), `field_type`/`field_types` and `ty_variants` substitute a type's arguments, construction and variants start from `fresh_args`, and `instantiate` fills in a callee's type parameters for every call, function or method, recording the instance. `reaches`, `values`, and `uncomparable` look through type arguments; `stored`/`held_width` and `check_variant_widths` check list elements, map entries, and generic enum variants against `MAX_ELEMENT_VALUES` once filled in. Publicly, `Type::Struct { name, args }`, `Analysis::structs` holds a `StructDef` (`params`, `fields`) and `Analysis::enums` an `EnumDef` (`params`, `variants`); `Type::struct_fields`, `Type::leaves`, `Type::struct_field`, and `variants` substitute arguments, through `Type::substitute`. Methods cannot have type parameters of their own yet. Traits: `declare_trait_names` (in `declare_types`; each trait gets a `TypeParamInfo` named `Self` whose symbol is the trait's and whose bounds are the trait), `declare_traits` (each method a function `<Trait>.<m>` generic over `Self`, `self` first, no type parameters; a body-less method's parameters get symbols here, for editors), then `declare_methods`, which declares every block's own functions (`declare_method`, which also reports `eq`/`cmp` outside their trait's block, a builtin method's name on a builtin type, and a signature unlike the trait's, `check_implemented_signature`) before giving each type the defaults it keeps (`MethodInfo::default`, whose `function` is the trait's); `impl_trait` and `report_missing_methods` check the block. `impls` maps (trait, type key) to each method's function, a type key being a struct's linked name or `int`/`float`/`bool`/`str` (`ty_key`, `builtin_key_type`), which share `struct_methods`. `TypeParamInfo::bounds` come from `bounds` (functions only; structs and enums report them). `find_changing_methods` also runs over default bodies, forces a type's method to change `self` when its trait's does, and reports one that changes it when the trait's does not. A call on a `Ty::Param` goes through `infer_trait_call` (the one bound with the method, or an error naming both), recorded as a `Method` whose `implementations` maps each implementing type to its function, plus an `Instance` with the receiver's type as `Self`; `method_function` gives a default's `Self` instance for a call on a known type, and `check_method_args`/`check_changing_call` are shared. `check_instances` runs `check_bounds` (`satisfies`) and follows a trait method to the type's own through `implementation_of`. `infer_try` types `?` from `FunctionScope::ret`: a result's error type must unify with the function's, an option needs an option-returning function, and anything else (top level, no `->`) is an error; `infer_method` picks the result rules for `unwrap`/`unwrap_or` only once the receiver is known to be a `result` (as `pop` does for maps), else the option rules, and `RESULT` names the enum. `DISPLAY` names the prelude's `display`, which `satisfies` makes automatic for every type, `str` accepts any value, and `infer_method` treats as a builtin method on any receiver (a `Ty::Param` included, before `infer_trait_call`) unless the struct has its own. `EQ`/`ORD`/`ORDERING` name the prelude's: `satisfies` makes `eq` automatic for comparable types (and `uncomparable` accepts a struct with an `eq` impl and a `T: eq`), `ord` automatic for int/float/str, `require_ordered` (a `Constraint` with `ord`) lets `<` and `sort` take an `ord` struct or `T: ord`, and the builtin methods `eq` and `cmp` (a struct without its own `eq` falls through to the builtin). `Method::resolve` (public) gives the function and copy types a call through a bound makes for a receiver type, and `Analysis` has `bounds` (by type parameter symbol) and `implemented` (traits by type key) for lowering and the LSP.
- Lambdas: `TokenType::VBar`, `ExprKind::Lambda` (`parse_lambdef`, from `parse_expression`, with hints for a body on the next line, a `:` after the bars, and Python's `lambda x:`), which only code that parses without linking sees: `Loader::add` runs `ast::lift_lambdas` on every file right after parsing, turning each lambda into a `FunctionDef` named `ast::lambda_name` (`lambda.<line>.<col>`, renamed `<module>.lambda.<line>.<col>` in a library; `ast::is_lambda` recognizes both) with an empty `name_span` and a body of one `ret`, placed before the top-level statement holding it, inner ones first, and the lambda into a `Name` of it, so everything after linking sees a function named as a value and lowering needs nothing of its own. The checker declares a lambda's unwritten parameter types and its return type as fresh variables (`declare_function`, no `untyped_params` report, `ret_written`), keeps its body in `lambdas`, skips its `FunctionDef`, and checks the body where the lambda is named (`function_value` pushes it on `pending_lambdas`, adding no reference): at the end of the call it is an argument of (`check_lambdas_from` after `infer_call`) or else of its statement (`check_stmt`), so the call's other arguments have typed its parameters, with the code around it saved and pushed on `lambda_outer`. `captured` reports any variable of `globals` or of an enclosing scope (`FunctionScope::lambda`), in `infer_kind`'s `Name` and in `infer_call`, giving it the variable's type so nothing else is reported, and `check_function_values` words its rule for a lambda. The LSP leaves `is_lambda` functions out of the outline, completion, and `Document::function`.
- Generic traits: `TraitDef::type_params` (`parse_type_params` after the name) and `TraitName::args` (`parse_trait_name` reads `from[int]`, in bounds and `impl` blocks, its span the name's alone). The linker rewrites types in trait arguments (`Rewriter::trait_name`), keeps a trait's parameters unrenamed (`set_type_params`), allows `impl Tr[...] for int` in the file of a struct its arguments name (`names_struct`), leaves a prelude conversion trait on a builtin type to the checker, and renames each function of an `impl` block of a generic trait to its key, the name plus `project::method_suffix` (`add..int`, the arguments mangled as labels write them, `Self` as the owner), so every stage names it `V.add..int` with no further work. The checker's `TraitInfo::params` are its methods' type parameters after `Self` (`<Trait>.<m>` is generic over both), `TypeParamInfo::bounds` are `TraitBound`s (name and argument `Ty`s, read once every parameter is declared, `trait_args` checking the count), `impl_args` lists each block's arguments by (trait, type key) with `args_overlap`/`may_match` (a non-destructive unification where unknowns, and an impl's parameters, match anything) rejecting overlap, and `impls` maps every key to its function. `MethodInfo` has `name` (its key in `struct_methods` may be `add..int`), `trait_`, and `trait_args`; `has_struct_method` and `struct_method` look methods up by name. A call with several fitting methods goes through `Candidate`s (`struct_candidates`, or one per bound in `infer_trait_call`): `call_candidates` takes the one the arguments fit (`fitting`), else defers it (`DeferredOverload`, `settle_overload` in `finish`), or reports `report_no_fit`. `Method::trait_args` (the bound's, in the caller's parameters) and `Implementation`s (type key, the struct's parameter names, the impl's trait arguments, the function) feed `Method::resolve(ty, trait_args)`; `satisfies_bound`, `impl_for`, and `implementation_of` match arguments; `Analysis::method_functions` (and `Analysis::method_function`) name a generic trait's methods by symbol for the LSP. The interpreter keeps the running copy's type arguments (`Interpreter::types`, a `Types` map by parameter name, set from `next_types` by `invoke_body`, from `instance_types` of `Calls::instances` at each call, captured by a `FunctionRef`), since it makes no copies, and `implementation` resolves a call through a bound from them.
- Conversions: `infer_call` sends a call of a builtin type's name, a struct's with one positional value and no keywords, or a type parameter of the function being checked (`conversion_target`) to `infer_conversion`, which settles at once or, for an unknown source, in `finish` (`PendingConversion`, `settle_conversion`): the checker's `builtin_conversion` (and the public `checker::builtin_conversion` over `Type`, which both backends use), else `impl_conversion` (an impl of `from`/`try_from` for the target's key through `impl_for`, recorded as an instance at the call, or a type parameter's bound). `conversion_conflict` and the orphan check in `impl_trait` reject a conversion a type already has, `impl from[X] for str` (use `display`), and one of both traits for one source. `Analysis::conversions` (`Conversion`: target, source, `fallible`, the impl's `function`, or `implementations` through a bound) and `Conversion::resolve` (`Converter::Builtin` or `Function` with copy arguments) drive the interpreter's `eval_conversion`/`convert` (`result` for `try_from`) and lowering's `conversion` (`builtin_conversion`, `float_to_int_result` with two float comparisons, `bytes_result` building `stdlib::BYTE_RANGE`'s text with `stone.str_concat`, `user_call` of the impl, a bound's through `request` and `dispatched`).
- Function values: the checker's `Ty::Fn`/`Kind::Function` (`Type::Function`, written as `TypeExprKind::Function`) unify part by part, are uncomparable (`uncomparable`), and never map keys. `infer_kind` gives a `Name` that resolves to a function `function_value` (through `instantiate` at the name's span, so a generic one records an instance there), recorded in `Analysis::function_values` (span to linked name), and `check_function_values` in `finish` rejects one whose type holds a `Ty::Param`. `infer_call` sends a variable or any non-name, non-attribute callee to `infer_value_call`, and `infer_struct_method` and `settle_method` a struct field of a function type to `field_call` (a method can never share a field's name); each such call's span goes in `Analysis::indirect_calls`. `project::Rewriter::module_member` rewrites `geo.area` outside a call too. `last_use::GlobalReads` treats a call of a value (`Names::calls_a_value`: a called local, a non-name callee, or a method named like a field that may hold a function, `value_fields`) as a call of every function named as a value anywhere (`of_values`). The interpreter's `Value::Function(Arc<FunctionValue>)` (linked name and printed type, from `Calls::function_values`) is called by `call_value`, which moves arguments into it like a direct call. Lowering makes one with `Inst::FunctionAddress` (`v1 = fn_addr fn.double`), its function's copy's label, or a thunk `stone.fn_value.<label>` (`Helper::FunctionValue`, `function_value_thunk`) that retains what the function owns, since a call through a value (`value_call`, `Callee::Value`, `call value v1(v2)`) borrows every argument; `print_flat` writes a function's `type_text` as a literal, and `mangle` writes `fn1_int_int`. A call that passes a function by name, or a parameter a copy binds, to a parameter the callee never assigns (`specialized_label`) calls a copy of the callee (a `Request` of an `Instance` plus `BoundFunction`s, labeled `apply..fn0.double`) that takes no argument for it and calls it directly (`Lowerer::constants`). x64 calls a value through r11 (in the argument moves, `call r11`), arm64 through x17 (`blr x17`), both checking the call depth. The prelude's list helpers are checked as calls of their prelude function with the receiver first (`infer_prelude_method`, recording a `Method`, so both backends call them as methods), except `sort_by_key`, which changes its list as `sort` does through the prelude (the interpreter's change path and lowering's `changing_call`, which requires the function to own its receiver); `project::prelude` runs a `Rewriter` over the prelude's functions so they can write `some`/`none`.
- `src/interpreter.rs`: evaluates programs over runtime `Value`s, walking not the AST but the tree `src/interpreter/code.rs` makes of each body once, when it is defined (`code::Resolver`: a function's in `Interpreter::define`, the program's and each REPL entry's in `define_all`, which runs enum and struct definitions before functions so construction and variants resolve): every variable is a `code::Var`, a slot of the running call's `Frame` (a `Vec<Option<Value>>` laid out by the function's `Layout`, parameters first, then `collect_assigned`'s names) or a global's id, and every call a `code::Call` saying what it calls (`User` by function id, `Builtin` by name, `Struct`, `Method` with its `Rc<Method>`, `Value`, `Conversion`, `Change` for `stdlib::changes_receiver`, `BuiltinMethod`), so running a body hashes no span or name. Functions, globals, structs, and enums live in `Vec`s by id (`Interner` gives a name an id the first time code mentions it, so a call resolved before its callee is defined, or redefined in a later REPL entry, still finds the current one), and `StructDef` keeps the ids of its `display`, `eq`, and `cmp` functions. (`Value::Tuple` is an `Rc<[Value]>`, which `assign_target` unpacks after the whole value is evaluated; lists are `Rc<Vec>` values that a change copies first through `Rc::make_mut` if anything else shares them; `eval_place` evaluates a change's indexes and `place_list` walks to the list it changes, counting in `copies` each shared list a change copies, which tests check; after each statement it drops the list variables the statement used for the last time (`code::Stmt::last_uses`, from `LastUses` when the body is resolved), and the statement's top call carries `code::Move`s (the resolver's `top_call` and `moves`) that take its arguments from them first, so a list nothing else holds changes in place, though never a global in the REPL); `ControlFlow` carries break/continue/return, and a function sees only its own frame and the globals. An enum value is `Value::Enum(Rc<EnumValue>)` (its printed name, tag, and fields), made by `Interpreter::variant` from the `enums` table that `EnumDef`s fill before anything runs, and matched by `pattern_matches`, and compared by `Value::equals`, which fails with `stdlib::COMPARE_DEPTH` past `MAX_PRINT_DEPTH` nested enum values as compiled code does; `EnumValue`'s `Drop` empties uniquely held values into a worklist, so a long chain drops without recursion. `Value::write` prints values, failing with `stdlib::PRINT_DEPTH` past `stdlib::MAX_PRINT_DEPTH` nested enum and struct values, and offering each struct to a `custom` hook first; `Interpreter::write_value` is the hook that runs a struct's `<linked>.display`, and serves `print` (which builds its whole line, so a failing print writes nothing), `str`, `display`, the REPL echo, and `JoinedStr` (every value evaluated first, then written), while `Value::display` (no hook) serves error messages. `Value::Unit` is what a call without a value gives. A struct value is `Value::Struct(Rc<StructValue>)`, its `StructDef` (printed name and field names) filled from `StructDef` statements before anything runs; changes walk `PlaceStep`s through `walk_place` (`place_value`, and `place_list` for a list), copying a shared struct with `Rc::make_mut` (only list copies count in `copies`), `read_place` reads an augmented target's old value, `take_field` moves a field such as `b.items` into a call that replaces it, and `drop_values` frees enum and struct values with one worklist. Arithmetic goes through `Interpreter::arithmetic`, which computes operations on two numbers at once and leaves those with a list operand as a `Lazy` tree that `elementwise` checks for equal lengths and then evaluates one index at a time, which defines the order of runtime errors for compiled code too. `Limits` bounds fuel (loop iterations plus calls), total evaluation depth, and active calls (`max_calls`, the language's `stdlib::MAX_CALL_DEPTH`), and `print` writes to an injectable writer, `input`/`eof` read an injectable `BufRead`, and `args` returns injected arguments (`driver::interpret_with_io`; `interpret_with` gives empty input and no arguments). It flushes the writer before reading, so prompts show first. The driver runs it on a thread with `Limits::STACK_SIZE` of stack so 1,000 nested calls fit. `with_calls` (and `run_entry`) take the checker's `Calls`; each `Function` keeps the table of the check that saw its body (`resolved`), since REPL entries move. `call_method_of_struct` calls a resolved method: an associated function or a method that does not change `self` like any call, and one that does by `eval_place`, the arguments, taking the receiver out of its place (a clone if it is a global the method may read, or in a session), `invoke(.., keep_self)`, which returns what the method left in `self`, and storing that back. Traits: `StructDef::linked` is the type key, a trait's default methods are functions `<Trait>.<m>` (body-less ones are not defined), and `call_through_bound` runs a call through a bound as the receiver's type's method (`implementation`: the `Method`'s table, else `<type>.<m>` if defined, since a REPL entry's table may predate an impl, else the default), with `eq.eq`/`ord.cmp` on a type without its own falling back to the builtin `call_method`. A `?` that finds an `err` or `none` returns `Err(Propagate(value))`, which `located` passes through and `eval_stmt` turns into `ControlFlow::Return`; `is_result` tells a result's `unwrap` from an option's by the variant's printed name. `values_equal` and `order` replace `Value::equals`/`compare` for `==` and `<`, calling `<struct>.eq`/`<struct>.cmp` when defined; `ordering`/`ordering_of` make and read the prelude's orderings; `sort` of struct values calls `stdlib::PRELUDE_SORT` on a copy of the list.
- Runtime errors must match between backends, and print like checker errors (`file:line:col: error: message`, the source line, and carets) under both. The interpreter turns an error into a `Diagnostic` at the innermost expression that raised it (`interpreter::located`, in `eval_expr` and `arithmetic`; a change's index points at its subscript, `checker::place_spans`), and compiled code prints the same text: lowering records the span of every instruction (`Block::spans`, `term_span`), and each backend's `fail_here` asks `Context::fail_at` for a stub that stores a site record (the location and excerpt `SourceMap::site` renders, in `.rodata`) in `stone.site` before jumping to `stone.fail`. A call to one of `context::FALLIBLE_ROUTINES` stores its site first, for the routine's own siteless `fail_label`s. `recursion is too deep` points at the call, so each call to a stone function checks `stone.call_depth` before calling, and the prologue only counts. Without sources (`AssemblyGenerator::set_sources`, which `driver::compile_module` calls), failures print only `error: message`. A message with `{}` holes (`stdlib::INDEX_RANGE`, `STRING_INDEX_RANGE`, `LENGTHS_DIFFER`) gets ints written into them: the interpreter through `stdlib::fill`, and compiled code by putting them in the backend's `FAIL_VALUES` registers, from `Terminator::Fail`'s values (`fail "...", v1, v2`) or, for the inline list index check, setup lines that a `Context::fail_at_after` stub runs first, then jumping to `stone.fail_detail`, which writes the pieces of text (`Failure::pieces`) and the ints in turn without allocating. The interpreter's error message is what compiled code prints after `error: ` (e.g. `division by zero`, `integer overflow in division`, `recursion is too deep (more than 1000 nested calls)`, `'x' is used before it is assigned`, `list index out of range (index 5, length 2)`, `cannot convert float to int (nan or out of range)`), with exit status 1. Floats follow IEEE 754 except that dividing by 0.0 is `division by zero`, as in Python. Golden programs check them with `.err` files.
- Every stage must return an error, never panic, on bad input: `LexError` for bad literals, a `Diagnostic` from `Parser::parse`, `parser::MAX_DEPTH` for nesting, `Limits` in the interpreter, and `Err(String)` from codegen (`AssemblyGenerator::assemble` generates assembly text) and from the assembler and linker.
- `src/codegen.rs`: `AssemblyGenerator` trait (`compile`/`assemble`/`scan`/`generate`/`emit`/`target`), `Architecture` (`X64`/`Arm64`, the processor: `host`, and `generator` for Linux), `Os` (`Linux`/`MacOs`), `Level` (the processor features a target may assume, `v1`-`v4` on x86-64 and `v8`-`v9.5` on arm64; codegen ignores it for now), `Target` (an architecture, a `Level`, and an `Os`, named `<arch>[<level>]-<os>` with no vendor since programs use no libc: `X64_LINUX`, `ARM64_LINUX`, `ARM64_MACOS`, `ALL`, `host`, `generator`, `Display` as the canonical name such as `x86_64-linux` or `x86_64v3-linux`, and `FromStr` for `--target` names: a processor `x86_64`/`x64`/`aarch64`/`arm64` with an optional level, then optionally `-linux` or `-macos` (none means Linux), plus Rust's names such as `aarch64-apple-darwin` and `x86_64-unknown-linux-musl`; x86-64 macOS is the error `INTEL_MACOS`). Release archives use the same names for the machine the stone binary runs on, plus `x86_64-macos`), `executable`, which assembles and links in memory for a target, and `link`, which writes `<output>.s` and the executable beside `<output>` before renaming it over, so a running copy keeps working (macOS also kills a signed binary rewritten in place).
- `src/codegen/device.rs`: `Device`, a GPU named as its vendor does (`gfx1100`/`gfx90a` for amdgcn, `sm_90`/`sm_90a` for NVIDIA). GPUs are never part of a `Target`: a build will take one target plus any number of devices (`--gpu`, not added until a device backend exists).
- `src/codegen/asm.rs`: the built-in assembler. `assemble(text, arch)` parses the GNU as text both backends emit (labels, comments, `.text`/`.data`/`.bss`/`.section .rodata`, `.globl`, `.p2align`, `.balign`, `.zero`, `.quad`, `.string`; anything else is an error naming the line) and returns an `Object`: the bytes of `.text`, `.rodata`, and `.data`, the size of `.bss`, every label as a `Symbol`, and `Fixup`s (`FixupKind`) for addresses only the linker knows. An `Encoder` per target turns one instruction into `Encoded::Fixed` bytes or, on x64, an `Encoded::Branch` that starts short (2 bytes) and grows to rel32 until nothing grows, as GNU as relaxes jumps. `src/codegen/asm/x64.rs` (Intel syntax operands: registers by width, `QWORD PTR [base + index * scale + disp]`, `[rip + label]`, immediates including sums such as `8 + 4095`) and `src/codegen/asm/arm64.rs` encode exactly the instructions the backends emit, choosing GNU as's encoding where there are several (store-form `89` for `mov reg, reg`, `83` for small immediates, `movz`/`movn`/`orr` for `mov #imm`, `ldur` for unscaled offsets, `sub` for `add #-n`), so `tests/assembler.rs` can compare bytes exactly. A backend change that emits a new instruction form needs the encoder to learn it: get the bytes from GNU as (or `aarch64-linux-gnu-as`), add the line to the encoder's table test, then implement it.
- `src/codegen/elf.rs`: the built-in linker. `layout` places `.text` on the first 64-byte boundary after the ELF and program headers at `BASE` (`0x400000`), so loops sit in their cache lines as they would under GNU ld (a 16-byte start made `collatz` 20% slower), then `.rodata` and `.data` plus `.bss` each on a new page (`page_size`: 4 KiB on x64, 64 KiB on arm64) at the same offset within the page as in the file, and `link` resolves every fixup with `asm::apply_fixup` (shared with the Mach-O linker; an undefined symbol is the linker's error, not the assembler's) and writes an `ET_EXEC` with `PT_LOAD` segments (R+X, R, RW), a non-executable `PT_GNU_STACK`, section headers, and a `.symtab` of every label except `.L` ones (functions sized to the next symbol), entering at `_start`.
- Sockets and listeners: the checker's `Type::Handle(Handle)`/`Ty::Handle`/`Kind::Handle` (`Handle::Socket`, `Handle::Listener`, `Handle::named` for `written_type`), uncomparable (`uncomparable`, `check_equality`), never map keys, in `BUILTIN_TYPES`. Their methods are `stdlib::HANDLE_METHODS` (also in `METHODS`), typed by `handle_method` through `check_handle_method`, which a receiver of unknown type defers (`settle_method`), and none changes its receiver. `net_sys.connect(address: list[int], port, name)`, `net_sys.listen`, and `net_sys.exchange(address, port, name, query: list[int], timeout_ms)` (one UDP packet with a random ID written into its first two bytes, and the first reply with that ID, as `list[int]`) take an address as 4 or 16 bytes, which `net.stn` parses, and quote `name` in errors (`reason: 'name'`; errors on an open connection are the reason alone, as `connection reset by peer`). The interpreter's `stdlib::net` (`Socket`, `Listener`, over `std::net`, so no `unsafe`; `complete_prefix` keeps an unfinished UTF-8 character for the next `read`; every call fails under `cfg(fuzzing)`) backs `Value::Socket`/`Value::Listener` (`Rc<RefCell<..>>`), and `Value::drops_early` (formerly `holds_list`) drops a variable holding one at its last use. Compiled, a handle is an enum-shaped object (`RcKind::Enum`, `contains_enum`) with a negative tag (`x64::net::SOCKET_TAG`, `LISTENER_TAG`), no counted slots, and slots for the descriptor, a socket's read buffer (start, end, size, ended), or a listener's port; `enum_runtime(handles)` (`Context::needs_handles`) checks the tag where `stone.free_enum` is entered and where it queues a nested value, before the tag becomes the queue's link, and calls `.Lfree_handle` to close the descriptor and free the buffer. `Lowerer::release_handles` releases and nulls, after each statement, every variable `holds_handle` says may hold one and the statement used for the last time (not ones it moved), when `Context::handles`. The routines (`context::NET_ROUTINES`, `x64/net.rs`, `arm64/net.rs`) come with `fs_runtime`, sharing `.Lfs_err` (which writes the reason alone for a null subject, with `INVALID_ADDRESS_CODE`, `TIMED_OUT_CODE`, `SOCKET_CLOSED_CODE`, `LISTENER_CLOSED_CODE`, and network error numbers in `stdlib::fs`'s tables), `.Lfs_ok`, and `.Lfs_utf8`. Linux passes `SOCK_CLOEXEC`, `accept4`, and `MSG_NOSIGNAL`; macOS has none, so `.Lnet_prepare` sets close-on-exec with `fcntl` and `SO_NOSIGPIPE` on every new socket, and its addresses start with their length (AF_INET6 is 30). arm64's `Sys` has `Socket`, `Connect`, `Bind`, `Listen`, `Accept` (`accept4` on Linux), `Getsockname`, `Setsockopt`, `Sendto`, and `Recvfrom`, which `macho::SYSTEM_FUNCTIONS` lists. Handles print as their type (`print_flat`, `holds_function`). A handle's seventh slot, `[p + 64]`, is its timeout in milliseconds (-1 forever), set by `stone.net_set_timeout` (the float rule of `stdlib::net::timeout_ms`, which `net.stn`'s `milliseconds` repeats for `connect_timeout`); `.Lnet_wait` (fd, `poll` events, ms; the interpreter's `stdlib::net::wait` over libc's `poll`, the second `unsafe` declaration after `os.rs`'s) waits on a monotonic deadline before each `recvfrom` in `.Lnet_receive`, each `accept`, and each `sendto`, which then passes `MSG_DONTWAIT` and loops on `EAGAIN`, returning the negative of `TIMED_OUT_CODE` (4000, positive and above every error number so it travels like one). `net_sys.connect` takes a timeout: with one, `fcntl` makes the socket non-blocking, `EINPROGRESS` waits for writable, `getsockopt(SO_ERROR)` (`Sys::Getsockopt`; `Sys::Fcntl` now has a Linux number) reads the outcome, and the flags go back. Byte reads take from the same buffer through `.Lnet_take_bytes` (no UTF-8 check), `read_exact` fails with `CLOSED_EARLY_CODE`. `net.connect_unix(path)` (`net_sys.connect_unix`, the interpreter's `Stream::Unix`, `stone.net_connect_unix` with a `sockaddr_un` as long as the path plus its 0, and `sun_len` first on macOS, where both backends report `ENOTSOCK` as `ECONNREFUSED`, Linux's error for a path that is not a socket, through `stdlib::fs::MACOS_ENOTSOCK`/`MACOS_ECONNREFUSED`) and `net.ready(s, seconds)` (`net_sys.ready(s, ms)`, -1 forever: true if the buffer holds bytes, the socket ended or is closed, or `poll` finds input; `stone.net_ready` retries `EINTR` with the whole time, as `Socket::ready` does) are what `gui` speaks X11 over.

- `src/codegen/macho.rs`: the built-in Mach-O linker for arm64 macOS. `link(object, identifier)` writes a PIE `MH_EXECUTE` at `BASE` (`0x1_0000_0000`) with 16 KiB pages: `__PAGEZERO`, `__TEXT` (headers, `__text` on a 64-byte boundary, `__stubs`, `__const` from `.rodata`), `__DATA` (`__got`, `__data`, `__bss`), and `__LINKEDIT` (chained fixups, an export trie of `__mh_execute_header`, the symbol and indirect symbol tables, strings, then the signature), each at the same file offset as in memory except `__LINKEDIT`, which follows `__bss`. It loads `/usr/lib/dyld` and `/usr/lib/libSystem.B.dylib`, enters at `_start` through `LC_MAIN`, and requires macOS 12 (`LC_BUILD_VERSION`) for chained fixups. Each `bl` to a name in `SYSTEM_FUNCTIONS` (undefined in the object) resolves to a stub that jumps through a GOT slot holding a `DYLD_CHAINED_PTR_64_OFFSET` bind; nothing else holds an absolute address, so nothing is rebased. The `LC_UUID` is a hash of the contents, so builds are reproducible, and the file ends with an ad hoc, linker-signed code signature (SHA-256 of each 4 KiB page) because arm64 macOS runs only signed code. Tests in `src/codegen/macho/tests.rs` parse the output back.

- `src/codegen/ir.rs`: a small IR between the AST and assembly. A `Function` is blocks (in layout order) of `Inst`s over vregs, each ending in a `Terminator`; it is not SSA, so each stone local is one vreg for the whole function. `Display` prints a readable dump (`v1 = add v0, 1`, `br_lt v1, v0 -> b2, b3`), which tests compare and `STONE_DEBUG` prints. `Inst::Call` writes several `dsts` and `Terminator::Return` returns several values when a stone function returns a tuple (`v2, v3 = call divide(v0, v1)`, `ret v0, v1`), and `Inst::defs` lists what an instruction writes. `Retain` and `Release` (`retain v1`, `release_str v1`, `release_enum v1`) adjust a string's, list's, or enum value's reference count (`RcKind`, whose `codes` writes the 2-bit kinds of slots), and `ListStore` can return the element it replaces (`v3 = list_store v0, 1, v2`). `ListUnique` (`v0 = list_unique v0`) gives a list nothing else refers to before it changes, copying it if its count is above 1; `maybe_null` (`list_unique_or_null`, which only the optimizer makes) lets a null list through. `Terminator::Fail` (`fail "math domain error"`) stops the program with a runtime error, which each backend emits as a jump to a `fail_at` stub, and `FloatSqrt` is `sqrtsd` or `fsqrt`. `ListGet` and `ListSet` read and store a slot known to be in range, `offset` slots past `index` (`list_get v0, v4 + 3`), `ElementSlot` (`v5 = element_slot v0, v3, 7`) is the one checked step that gives where element `v3` of a list of `7`-slot elements starts (failing with `stdlib::INDEX_RANGE`), `DepthCheck` is the call-depth check of a call that was inlined, `ListData` loads a list's element pointer, and `Packed` (`v9 = packed v5, v3, fadd(fmul([v6], v2), [v7])`) runs a `Kernel` over pairs of elements with SIMD, writing the position where it stopped. `FunctionAddress` is a function value, and `Callee::Value` calls one, its operand read after the arguments. `EnumTag` (`v1 = enum_tag v0`), `FieldGet` (`v2 = field_get v0, 1`), and `FieldInit` read an enum value's tag and slots, and `VariantStatic` (`v3 = variant 0`) is the static, immortal value of a variant without values, `stone.variant_<tag>`, which every enum shares by tag (`context::variant_statics`). A `Function` with `helper` is one lowering made, named by its label and called through `Callee::Helper`, which neither counts toward nor checks the call depth, and records the caller's site for its siteless `Fail`s.
- `src/codegen/ir/lower.rs`: `lower` turns a checked AST into a `Program` (every function, then `main`, plus the global names), resolving names like the checker (`checker::collect_assigned`). Tuples are never stored as one value: each value of a tuple variable `t` is a variable of its own, `t.0`, `t.1`, ... across nested tuples (`ir::leaf_name`, `ir::variable_of`, `Lowerer::leaf_names`), a local or a global (`g.t.0`, of which only the first is checked before a function reads it), so counting, moves, and releases work per value, while liveness stays keyed by stone names. `expr_flat` lowers any expression to its values (one, or one per value of a tuple), `tuple_field` picks `t[k]`'s, `user_call` passes a tuple argument as its values and receives a tuple result as several `dsts`, `assign_tuple` copies local values first so `a, b = (b, a)` swaps, `ret (s, s)` gives a local's own reference only once, and `print_flat` prints a tuple, and a list holding one (`print_elements`), a value at a time, with strings quoted. An element of a list of tuples is `width` slots read with `ListGet` and written with `ListSet` at `position * width + field` after one `ElementSlot` (`element_slot`; `element_values`, `store_values`, `load_slots`), which the backends expand inline, comparing the index and then its first slot with the slot count and dividing by the width only for the failure message; `pairs[i][0]` reads only its slot. Evaluation is left to right, so runtime errors happen in the interpreter's order. `x = <expr>` writes `x`'s vreg directly, unless `x` is counted. A global that one top-level statement (not in a block) assigns an int, float, or bool literal, that nothing else assigns or calls a method on (`method_receivers`), and that no earlier statement can call a function reading (`constant_globals`, through `GlobalReads::of_statements`), reads as an immediate, with no load and no check, so `% modulus` divides like a literal. `if`/`while` tests go through `Lowerer::cond`, so comparisons, `and`, `or`, and `not` become `CmpBranch`/`Branch` terminators instead of materialized bools. A `for` loop counts with hidden vregs that the body cannot assign, and copies a variable bound or list first. It also places every `Retain` and `Release` (see "Memory" below), which needs each variable's type, so it takes the checker's `symbols` as well as `types`. A change evaluates its value, the indexes (`place_indexes`), and any arguments, then `unique_place` makes each list from the variable down unique with `ListUnique`, writing it back to the local, the global (only in `main`), or the parent slot, before the store or `stone.list_append`. A function owns the parameters it assigns or changes (`owned_params`), and `give_references` gives each such argument a reference before the call: a temporary's, a retained one, or, for a variable in `movable` (the variables the statement uses for the last time, `Lowerer::last_uses`, from `last_use::live_after`, plus an assigned target), the variable's own, which moves it in so the callee sees a count of 1. `take_from` moves a variable the same way into `ys = xs` or `rows.append(row)` at its last use. A moved variable that its statement does not assign again is left null (`clear_moved`), so releasing it later does nothing. A global moves only into a function that cannot read it, directly or through its calls (`last_use::global_reads`). Enums: `Lowerer::variant` makes a value with `stone.enum_new(tag, kinds, slots)` and `FieldInit`s each value of its fields (taken like a list literal's elements), or `VariantStatic` for one without values (and `none`), and `option_value` lowers `unwrap` (a `Fail` on tag 0) and `unwrap_or`. `match_stmt` evaluates the subject once (through a copy if it is a variable, since a case may assign it), holds a temporary subject in `held` so `ret`, `break`, and `cont` release it (`release_held`), then per case runs `pattern_test` (`EnumTag` and `CmpBranch` down the variants the pattern names) and `pattern_bindings`, retaining every bound value before assigning any. Printing an enum, or a list or tuple holding one (`holds_enum`), calls a helper per enum type, `stone.print_enum.<type>` (`Helper::Print`, `Helper::label`, `enum_printer`), which `lower` makes after every function until none is left asked for (`Lowerer::helper` asks), passing `print_depth` on and failing past `MAX_PRINT_DEPTH`. Structs lower like tuples: each struct variable is leaf variables (`leaf_names`, gated by `is_flat`), `construct` evaluates a struct's keyword values in written order and gives its leaves in field order, and `struct_field` reads a field's leaves (only its slots, for a list element). A change through a field goes through `locate`, which walks a place's steps to a `Location` (a variable's leaves, or slots of a list made unique on the way, each index checked against the element count), then `store_location` or, for `p.x += v` and `ps[i].x += v`, `aug_assign_place`; `unique_place` uses it for any place with a field, and a field assigned the result of a call is movable, so `p.items = f(p.items)` moves the list in. Structs print through a helper per struct type, `stone.print_struct.<name>`, taking the leaves and the depth, since a struct can hold a list of itself; struct values count toward `MAX_PRINT_DEPTH` in both backends. `==` and `!=` on tuples, structs, and enum values (`is_compound`) compare their leaves in turn, stopping at the first that differs (`equal_branch`, `equal_leaves`: `CmpBranch`, `stone.str_eq` for strings, and for an enum value a helper per enum type, `stone.eq_enum.<type>` (`Helper::Equal`, `enum_comparer`), which compares tags and then the variant's slots, passing `compare_depth` on and failing past `MAX_PRINT_DEPTH` with `stdlib::COMPARE_DEPTH`); `compare` writes 1 or 0, and `cond` branches on a single one directly, releasing temporaries on both ways out. `lower` takes the whole `Analysis`. A non-generic function or method from any file but the entry file (the prelude, a library, `net`, `gui`) is lowered only once lowered code reaches it: `lower` keeps such bodies in `deferred`, and its worklist scans each newly lowered function for `Callee::User` calls and `FunctionAddress` labels (`referenced_functions`), so unused library code, and the runtime routines only it calls, is never emitted. Generic functions are never lowered as themselves: `lower` collects them, and `user_call` asks `callee_label` for the label of the copy a call needs (the call's `Analysis::instances` args with the current copy's types filled in), which queues an `Instance` in `Context::requested`; the loop that makes helpers also lowers each requested copy with `Lowerer::new_instance`, labeled by `instance_label` (`first..list_int`, the function then each `mangle`d type after `..`). The functions of a generic struct's `impl` block are collected the same way, as `<struct>.<method>`, and `changing_call` labels its callee through `callee_label` too. Helpers are per type with arguments (`mangle` writes `Pair.int_str`). A copy's `Lowerer` has `name` (the label), `base` (the stone name, for `owned_params`, `global_reads`, and variables), `substitution`, and `instance_variables` (its symbols' types filled in, with leaves); every type read goes through `span_type`/`fill`, so counting, flattening, and printing see concrete types. Functions of `impl` blocks lower as functions named `<struct>.<name>`; a method that owns `self` (`returns_self`, since it changes it) returns its values after its result from every `leave`. `struct_call` lowers a resolved call: `user_call` for an associated function or, with the receiver first, a method that borrows `self`, and `changing_call` for one that changes it (`place_indexes`, the arguments through `give_references` from parameter 1, `locate`, then the receiver's values moved into the call, or retained if it is a global the method reads, and `store_location` of the returned values). Traits: `lower` collects a trait's default methods as generic functions over `Self`, and `struct_call` resolves a call with `implementations` from the copy's receiver type (`Method::resolve`), requesting the copy (`request`) and leaving its label in `dispatched` for `callee_label`, or lowers `eq.eq`/`ord.cmp` on a type without its own as the builtin method. `==` is structure-aware: `compared` splits a type into values and structs that implement `eq` (`Compared`, `implements` reading `Context::implemented`), which `equal_leaves` (also in `enum_comparer`) compares with `compare_call` (a call of `<struct>.eq`, retaining what it owns); `compare` orders an `ord` struct by its `cmp`'s tag, and `cond`'s compound fast path is for `==`/`!=` only. The builtin `cmp` (`ordering`) branches to the static variant of each tag, floats by `float_key`'s order (nan checks, then compares, then zeros' sign bits as ints), and `sort` of anything but int/float/str is a `changing_call` of `prelude.sort`'s copy.

- Maps: the lexer's `LBrace`/`RBrace`, `ExprKind::Dict { keys, values }` (`parse_dict`), and `TypeExprKind::Map`. The checker's `Type::Map`/`Ty::Map` requires `MAP_KEYS` of the key through a `Constraint`, indexes a map in `subscript_of` (`Indexed::Map`, recording `indexed_maps`, and deferring an index into a global a function reads before its assignment through `DeferredIndex::index_ty`), iterates its keys in `for` (`MAP_PAIRS` for `for k, v in m`), gives `keys`/`values`/`items` lists and `pop(key)` an option in `infer_method`, and lets a change step through an entry like a list index, since `place`'s `Step::Index` is a key when the value indexed is a map; `check_entry_width` bounds an entry at `MAX_ELEMENT_VALUES`. The interpreter's `Value::Map(Rc<MapValue>)` keeps entries in a `Vec<Option<_>>` with a `HashMap<MapKey, usize>` of positions: `MapValue::remove` leaves a hole, and `close_up` removes the holes once they are more than half, so `pop` is constant time on average; `iter` skips holes. Its `PlaceStep::Index` holds the evaluated `Value`, which `walk_place` and `read_place` use as a list index or a map key by what they step into (a missing key fails at the step's span), `store_at` stores into either, and `change_map` runs `pop` on a map. Compiled, a map is a list object (`RcKind::List`) whose elements are entries, the key then the value's leaves (`Lowerer::element_kinds`), plus a hash index at `[p + 40]`, a slot every list header now has (48 bytes, 0 unless a map), which `free_list` frees and `list_copy` leaves 0 so a copy rebuilds it on first use. `builtins::map_runtime` (both backends, `context::MAP_ROUTINES`) has `stone.map_find` (first slot of a key's entry or -1), `stone.map_add` (appends an entry, retaining a string key, growing the open-addressing index at half load), `stone.map_take` (marks a key's entry removed and returns its first slot: its index slot becomes -1, which probing passes, and the index's count of removed entries grows, the index being `[capacity, removed, string keys, slots...]`), `stone.map_settle` (closes up when removed entries are more than half), `stone.map_compact` (closes up: `.Lmap_squeeze` moves every entry whose key still finds it, a removed string key being zeroed, over the removed ones, then `.Lmap_rebuild`), and `stone.map_holes` (removed entries not closed up yet, which `len` subtracts); `map_add` closes up before growing, `list_copy` before copying a map (when the program calls `stone.map_take`), and `free_list` skips the zeroed slots, and `stone.map_missing_str` (in `parse_runtime`, a `FALLIBLE_ROUTINES` entry) fails through `stone.fail_quoted`. Lowering: `map_values` (reads, failing per key type through `fail_missing_key`), `map_store`/`map_put` (sets, through `place_indexes` and `unique_place`), the `Dict` literal, `contains`, `map_pop` (`stone.map_take`, the values moved out and the counted slots zeroed, the key released, then `stone.map_settle`), `close_up` (a call of `stone.map_compact` before anything reads a map as a list: `for`, `keys`, `values`, `items`, and printing, only when `Context::shrinks_maps`, from `pops_maps`), `map_column` (`keys`/`values`, a loop of `ListSet`s), `items` (the map itself, retained, since its entries are laid out as a list of tuples), `for k in m` (the flat loop, taking slot 0), and `print_entries` for printing. `locate` steps into a map's entry (`unique_location`, `map_find`, `fail_missing_key`, then the entry's value slots), and `unique_place` and `aug_assign` take that path whenever `through_map` (or `has_field`) says a place goes through one, so `m[k] += v` is `aug_assign_place`. `place_indexes` keeps the keys it evaluated to owned strings in `place_keys`, which `stmt` releases after the statement. `stone.fail_detail1` takes a message with one hole, `stone.fail_detail` two.
- Arithmetic on lists: `Lowerer::elementwise` lowers a list-typed `BinOp`/`UnaryOp` tree (`fused` evaluates its other operands once, left to right, into a `Fused` tree), checks the lengths (`fail_unless`), takes the result from `stone.list_reuse` when an operand is in `movable` (its last use, or the assigned variable) so `a = a * 2.0 + b` writes in place, else `stone.list_new`, and loops with `ListGet`, the ordinary `Binary`/`FloatBinary`/`Neg`/`FloatNeg`, and `ListSet`. When `Fused::packable` (int `+ -` and negation, float `+ - * /` and negation) and small enough, a `Packed` instruction does whole pairs first and the scalar loop starts at its `done`. The backends expand `Packed` in registers no vreg uses: SSE2 in `xmm3`-`xmm15` (with `rax`/`rcx`/`rdx`) and NEON in `v16`-`v31`; a float division stops before a pair with a zero divisor so the scalar loop reports it at the interpreter's element, and FMA is never used. `pop` and `insert` check their index in IR (`list_position`), then call `stone.list_pop`/`stone.list_insert`; slices call `stone.list_slice`; all of these, `stone.list_extend`, and `stone.list_reuse` are `context::LIST_ROUTINES`, emitted by each backend's `builtins::list_methods` only when called.
- Text: `print`, `str` of anything but int/float/bool/str (`Lowerer::display`), builtin `.display()`, and `JoinedStr` (`Lowerer::joined`, which evaluates every value before writing) all write through the same `print_flat` into a text builder (`text_runtime` in both backends' `builtins.rs`): `stone.text_begin` returns the outer text, every `stone.print_*` routine appends to `stone.text` through `stone.text_append`, and `stone.text_print(outer)` writes the line plus a newline with `stone.write_out` (a short-write loop, also for `input`'s prompt), or `stone.text_eprint(outer)` to stderr for `eprint` (emitted only when used; both share `.Ltext_write` and the loop's `.Lwrite_fd` entry, which takes the file in `rdi` or `x3`), which the interpreter mirrors by flushing stdout before writing to its `errors` writer (`Interpreter::with_errors`), so `2>&1` keeps program order while `stone.text_end(outer)` turns the block, laid out as a string, into one without copying. Nesting (a `display` that prints) works because the outer text is a vreg. `print_flat` calls a struct's own `display` (`implements(ty, DISPLAY)`, through `compare_call` with no other value) and appends its result. `Context::needs_print` also covers `stone.text_begin`, and a program that prints without counting references gets `builtins::allocator` alone.
- `src/codegen/ir/inline.rs`: `inline` splices calls of small functions (`MAX_INSTS`, `MAX_BLOCKS`) that call no stone function (`Callee::User` or `Value`), bottom-up so a function whose calls were all inlined is inlined in turn. `splice` splits the block at the call: a `DepthCheck` at the call's span (so `recursion is too deep` stays the interpreter's), copies of the arguments to renamed parameters, the callee's blocks (vregs renamed past the caller's, `loop_depth` added, spans kept, so its runtime errors point at its own lines), each `ret` turned into copies to the call's `dsts` and a jump to the rest of the block. Out-of-line copies stay, since function values take their address. Runs before `opt`.
- `src/codegen/ir/opt.rs`: `optimize`, run by `Context::lower` after inlining, over each function: `hoist_unique` moves a `list_unique` of a variable out of a natural loop (`loops`, from `dominators`, innermost first; the loop needs a `preheader` ending in a jump) that never writes the variable otherwise, calls out, retains, or releases it, as `list_unique_or_null`; `hoist_checks` checks before a call-free loop each `element_slot` whose list and index the loop never writes that every turn reaches from the header before anything that `may_fail`, in a guard block appended after a copy of the header's test (so it fails exactly as the first turn would, and not for a loop that never runs), turning the ones in the loop into copies; `eliminate` is an available-facts dataflow (`Fact::Slot`, `Fact::Unique`; `transfer` kills on any call, a retain, a release, or a write of a named vreg, but `list_unique` of a list keeps its slots) that turns a repeated `element_slot` into a copy and drops a repeated `list_unique`; `fold_offsets` rewrites a slot that is a constant past another vreg (or a copy of one) in the same block into `ListGet`/`ListSet` `offset`s; `remove_dead` drops removable instructions nothing reads; `rotate_loops` copies a header that only tests onto the end of each latch, so a turn takes one branch; and `hoist_data` gives a loop that calls nothing, makes no list unique, releases nothing, and never writes a list's vreg a block on its one way in that loads each such list's `ListData` once, turning its `ListGet`/`ListSet` into `DataGet`/`DataSet`. `hoist_checks` also hoists an invariant `list_load` in a loop that stores into no list (`a[i]` in `for k: a[i][k]`), and `eliminate` reuses a repeated `list_load` (`Fact::Loaded`, killed by any store, release, or `list_unique`). The IR is not SSA, so every fact names vregs and dies when one is written.
- `src/last_use.rs`: liveness over the AST, shared by both backends: `global_reads` (a `GlobalReads` of the globals each function, including each function of an `impl` block, may read, through its calls too; a call `x.m()` counts as a call of every method named `m`), `live_after` (the variables code after each statement may read, keyed by statement span, iterating loops to a fixed point; nothing is live after `ret` but the `exit` set, `kept_at_exit`, which keeps a method's `self` to the end, and `break`/`cont` see where they jump), and `last_uses` (what each statement mentions that is dead after it). `functions` and `is_method` include trait methods, and `expr_names` counts `==`/`!=` as calls of every method named `eq`, `<` and the others and `.sort()` as calls of `cmp`, `print`, `str`, and `JoinedStr` as calls of `display`, so a global an `eq` or `cmp` reads never moves into a call that compares.
- `src/codegen/ir/liveness.rs`: `analyze` computes live-in/live-out sets, then one interval per vreg (no holes). Each block gets a start position, then each instruction an even position where it reads and the odd one after where it writes. Intervals carry a spill weight (`10^loop_depth` per access) and whether they cross a call.
- `src/codegen/regalloc.rs`: target-independent `linear_scan` (Poletto-Sarkar, spilling the lighter interval) with `Hint`s for preferred registers (`hints` computes them from a function and its argument registers), and `parallel_moves`, which orders simultaneous moves and breaks cycles through a temporary. `float_vregs` finds the vregs that hold floats (float arithmetic, comparisons, and conversions, joined through copies) and are never used as ints, pointers, or indexes; `linear_scan` gives such a vreg one of the backend's `VECTOR` registers when its interval crosses no call and no packed loop (`Interval::touches_vector`), all of them caller-saved, and otherwise a general register as before.
- Returning a tuple: the first values come back in `RESULT_REGS` (x64 `rax`, `rdx`, `rcx`, never allocated; arm64 `x0`-`x7`) and the rest in an area the caller reserves just above the arguments it passes on the stack, which the callee writes at `[rbp + 16 + 8 * (stack params + j - 3)]` or `[x29, #16 + 8 * (stack params + j - 8)]` (`Frame::stack_params`; arm64's `outgoing` covers both). Only stone functions return several values.
- `src/codegen/x64.rs`: `X64Generator`, emitting GNU-as Intel syntax (`.intel_syntax noprefix`). `assemble` runs the checker first and lowers with its types, e.g. to pick a `print` routine per argument. Top-level statements always go in a synthesized `main`, which `_start` (`builtins::start_runtime`) calls with `argc`, `argv`, and `envp` as C would, then makes the `exit_group` syscall with its status. Globals live in `.bss` as `g.<name>`, and user functions are `fn.<name>`, so they cannot collide with runtime labels. String literals are interned and emitted in `.data` with an immortal reference count (`builtins::immortal_string`). Runtime errors jump to a `fail_at(message, span)` stub that records its site and calls `stone.fail`.
- `src/codegen/x64/emit.rs`: instruction selection from allocated IR. Vregs that cross a call get callee-saved `rbx`/`r12`-`r15` (saved in the prologue only if used); others may also use `rsi`, `rdi`, `r8`-`r11`. `rax`, `rcx`, `rdx`, and `xmm0`-`xmm2` are never allocated and serve as scratch, for `idiv`, spilled operands, and wide immediates. `hints` asks for arguments to be computed in their argument registers, parameters to stay where they arrive, and copies and two-address results to share a register. The first six arguments go in registers via `parallel_moves`; arguments past the sixth are pushed, first deepest, and the callee reads them from `[rbp + 16 + ...]`. Each function counts itself in `stone.call_depth`, which each call checks against `MAX_CALL_DEPTH` first, and each global has a `g.<name>.set` flag that `StoreGlobal` sets and that functions check before reading a global, since only top-level reads are checked statically. A float that `float_vregs` picks lives in one of `xmm3`-`xmm15` (`VECTOR`, `Value::Xmm`), where SSE arithmetic, `sqrtsd`, negation (`xorpd` with the sign bit), conversion, and element loads and stores (`movq`) work on it directly (`float_source`, `store_xmm`); any other float travels as its bits in general registers and spill slots like every other value, moving into `xmm0`-`xmm2` for each operation. `mov` moves between the two files with `movq`. The runtime routines reached without a call (free routines, `list_copy`) use only `xmm0`-`xmm2`, which a packed loop shares with `xmm3`-`xmm15` for its own, so a float live at one stays in a general register. Division checks for zero and `MIN / -1` before `idiv`, except that an immediate divisor other than 0 and -1 skips the checks, a power of two becomes shifts (`divide_by_constant`, and `remainder_by_constant`, which subtracts the shifted quotient, in both backends), and any other constant a multiplication by its magic number (`codegen::magic_signed`, Hacker's Delight 10-4, applied by each backend's `magic_quotient` with one-operand `imul` or `smulh`). `%` shares those checks but gives 0 for a divisor of -1. `**` is an inline square-and-multiply loop (`power_loop`) that matches `stdlib::int_pow` and `stdlib::float_pow` operation for operation, and float `%` uses x87 `fprem`, so neither calls libc. List indexing is inline (`list_slot`): it counts negative indexes from the end, checks the result against the list header's length, and jumps to a `fail_at` stub when out of range. `Retain` is an inline `inc`, and `Release` an inline `dec` that calls `stone.free_str` or `stone.free_list` only when the count reaches 0. Those routines preserve every allocatable register, so neither instruction counts as a call for register allocation.
- `src/codegen/arm64.rs` and `src/codegen/arm64/emit.rs`: `Arm64Generator`, emitting GNU-as for AArch64 Linux from the same allocated IR, with the same labels, runtime failures, and `.bss` globals as x64. Arguments go in `x0`-`x7` and past the eighth at the bottom of the caller's frame (`[x29, #16 + 8k]` in the callee). Vregs that cross a call get `x19`-`x28`; others may also use `x0`-`x7` and `x12`-`x15`. `x8`-`x11`, `x16`, `x17`, and `d0`-`d2` are scratch, and `x18` is never used. A float `float_vregs` picks lives in `d3`-`d7` or `d16`-`d31` (`VECTOR`, `Value::Freg`; `d8`-`d15` would need saving), where `fadd`, `fsqrt`, scalar `fneg`, `scvtf`, and `ldr`/`str` of elements work on it directly (`float_operand`, `float_target`). `sp` stays 16-byte aligned at every instruction, so `push_frame`/`pop_frame` save registers in pairs and a frame reserves its spill slots and outgoing arguments once, addressing them from `sp`. Immediate forms of `add`/`sub`/`cmp` read register 31 as `sp`, so their first operand comes from `base`, never `xzr`. Behavior that differs from x86 is checked explicitly: `sdiv` never traps (zero and `MIN / -1` are tested first), `fcvtzs` saturates (the float is range-checked first), and float `%` calls `stone.fmod` (`arm64/floats.rs`), an exact remainder on the floats' bits, as musl's `fmod` computes it, that preserves every allocatable register. Float comparisons use `fcmp` with `mi`/`ls`/`gt`/`ge`/`eq`/`ne`, which are false on nan except `ne`. `src/codegen/arm64/builtins.rs` and `src/codegen/arm64/floats.rs` port every routine of `x64/builtins.rs` and `x64/floats.rs` under the same label and contract; the free routines take the object in `x9`. Every call into the system goes through `builtins::system_call` with a `Sys`: on Linux `mov x8, #n` and `svc #0`, and on macOS a `bl` to a shim `stone.sys_<name>` (`system_shims`, emitted for the calls the text makes) that saves `x1`-`x17` around the `libSystem` function, so only `x0` changes, as with `svc`. libSystem reports failure as -1 (null from `getcwd` and `opendir`) with `errno`, so each shim turns that into `-errno` through `__error` (`ERRNO_FUNCTION`), as Linux returns, and the `*at` calls' shims drop the directory in `x0`; `open`'s shim stores the mode on the stack, since Apple's arm64 convention passes variadic arguments there, and `readdir`'s clears `errno` first so the end of a directory returns 0. The rest of the macOS runtime differs only where the systems do: `_start` is called by dyld as C calls `main`, `MAP_ANON` is `0x1002`, there is no `mremap` (large blocks move to a new mapping), `CLOCK_MONOTONIC` is 6, `os.platform` is `"macos"`, and `os.hostname`/`os.cpu_count` read `sysctl` (`kern.hostname`, `hw.activecpu`) as macOS's `gethostname` and `sysconf` do.
- Memory: compiled strings, lists, and enum values are reference counted (the interpreter's `Rc` values need nothing more, the checker's occurs check rules out cycles, and enum values never change). An enum value (`builtins::enum_runtime`, emitted when `Context::needs_enums`) is an object with its tag at `[p]`, the 2-bit kinds of its slots at `[p + 8]`, and its slots from `[p + 16]` (`ir::FIELDS_OFFSET`); `stone.free_enum` queues dead values on `stone.free_pending`, linked through their tags, and frees the queue in a loop guarded by `stone.freeing`, releasing strings and lists directly, so freeing never recurses through enum values, and `free_list` hands kind-3 elements to it. `stone.free_list` does the same for lists: a dead list joins `stone.lists_pending`, linked through its capacity slot, and the outermost call frees the queue in a loop guarded by `stone.freeing_lists`, so a struct holding a list of itself a million levels deep frees in constant stack. Every object `p` has its count at `[p - 8]`, and `stone.alloc` (`builtins::memory_runtime`) allocates one with a count of 1. Memory comes from the runtime's own allocator (`builtins::allocator`: `stone.mem_alloc`, `stone.mem_free`, `stone.mem_realloc`, which clobber only scratch registers), not libc: blocks of a power of two from 32 bytes to 64 KiB, with the exponent in an 8-byte header, are kept on a free list per size and cut from 1 MiB regions mapped with `mmap`, and larger blocks get a mapping of their own, grown with `mremap`. The constants are in `context.rs` (`SMALLEST_CLASS`, `LARGEST_CLASS`, `HEAP_REGION`). Strings stay null-terminated `char*`, and a string also holds its length in bytes at `[p - 16]`, so `stone.str_len` reads it rather than scanning (`stone.cstr_len` scans a C string, such as an argument, or a pointer into a string). Every string is made by `stone.str_new` (length, then count, then bytes and terminator), and `immortal_string` writes the same header for literals. A list is a 40-byte header `{len, cap, data, kinds, width}`: `len` and `cap` count 8-byte slots, each element is `width` slots (1, or one per value of a tuple, stored side by side), and `kinds` says, two bits per value of an element, whether it is counted (0 no, 1 strings, 2 lists, 3 enum values) so `stone.free_list` can release them; `stdlib::MAX_ELEMENT_VALUES` (32) bounds the width. `stone.list_new` makes a list of width 1 and `stone.list_new_wide` any other; `free_list`, `list_copy`, `list_extend`, and `list_slice` handle wider elements (the last three through `stone.retain_slots`), while appending, inserting, and popping an element of a list of tuples are `width` calls to the slot routines at the slot where it starts (`Lowerer::add_element`, `pop_element`). `lower.rs` keeps counts exact: variables and list slots each own a reference, expressions are borrowed (variables, globals, literals) or owned temporaries (call results, list elements, which are retained when read) that whatever uses them releases or moves into storage, parameters are borrowed unless the function assigns or changes them, in which case the caller gives them a reference, `ret` releases locals and the lists of enclosing `for` loops, and the end of `main` releases every global. A row in `a[i][k]` is borrowed rather than retained when the index makes no calls (`Lowerer::list_operand`). Before a change, `ListUnique` is an inline count check that calls `stone.list_copy` (in `list_runtime`; it preserves every allocatable register, so it is not a call either) only when the count is above 1, and the copy retains counted elements and drops the original's count by one. `stone.live` counts allocated objects, and `stone.leak_check`, called at the end of `main`, exits with `error: N objects were never freed` when `STONE_LEAK_CHECK` is set.
- Builtins: `BUILTINS` in `src/stdlib.rs` lists function names shared by both backends (`print`, `eprint`, `range`, `int`, `float`, `str`, `input`, `eof`, `args`; `some` is the prelude's variant, not a builtin). `input` returns a `result[str, str]`, `err(stdlib::END_OF_INPUT)` once the input is over: the interpreter's `read_line` gives `None`, and compiled `stone.input` returns 0, which `Lowerer::call` turns into the `err` with an immortal literal, and `BUILTIN_DOCS` documents each for hover and the LSP's builtins reference. `METHODS` (`len`, `append`, `pop`, `insert`, `extend`, `strip`, `split`, `splitlines`, `join`, `find`, `rfind`, `count`, `replace`, `lower`, `upper` (ASCII letters only), `startswith`, `endswith`, the option methods `is_some`, `is_none`, `unwrap`, `unwrap_or`, the result methods `is_ok`, `is_err`, `unwrap_err`, `ok`, `err` (plus `unwrap` and `unwrap_or`), and the map methods `contains` and `get`) and `METHOD_DOCS` do the same for builtin methods, which are called on a value (`xs.append(1)`, `s.len()`) and are not reserved names. `src/codegen/x64/builtins.rs` (and its port, `src/codegen/arm64/builtins.rs`) emits the hand-written runtime via `&mut dyn AssemblyGenerator`: `stone.print_*` routines (emitted if the program prints), the float runtime in `src/codegen/x64/floats.rs` (`stone.format_float`, shared by `stone.print_float` and `str`'s `stone.str_float`, takes the shortest digit count the way Rust's Dragon `format_shortest` does, then rounds the exact value half to even to that many digits, matching `stdlib::format_float`, which prints floats like Python's `repr`; `stone.decimal_to_float`, behind `float(str)`, multiplies or divides by an exact power of ten for up to 15 digits and 22 places, and otherwise divides two bignums exactly; both work on a small bignum library of 64-bit limbs in `.bss`, `bignum_runtime`), and the string and list runtimes (emitted if the program uses those types). Other routines are emitted only if the lowered IR calls them (`Context::uses`, over `Callee::Runtime` labels): `io_runtime` (`input` and `eof` over a 64 KiB buffer that the `read` syscall fills, `STDIN_BUFFER`), `args_runtime` (from `stone.argc`/`stone.argv`, which `main` saves on entry), `env_runtime` (`stone.getenv`, which walks the `stone.envp` that `main` saves, for `os.env` and the leak check), `parse_runtime` (`stone.parse_int_result` for `int(str)` with an overflow-checked accumulator, `stone.parse_float_result` for `float(str)` checking the grammar then calling `stone.decimal_to_float`, both mirroring `stdlib::parse_int`/`parse_float` and building `ok` or an `err` of a message built at runtime, plus `stone.fail_quoted` for `stone.map_missing_str`), `conversion_runtime`, and `string_methods` (the `context::STRING_METHOD_ROUTINES`: `strip`/`split`, mirroring `stdlib::strip`/`split_whitespace`/`split`; `stone.str_at` and `stone.str_slice_of` behind `s[i]` and `s[a:b:c]`, mirroring `stdlib::str_at`/`str_slice`, which index bytes and fail with `stdlib::CUT_CHARACTER` rather than cut a character outside ASCII, `stone.str_at` returning an entry of a table of 128 immortal one-byte strings; `stone.str_cmp` behind `<` on strings, which compares its -1, 0, or 1 with 0; `stone.str_char`, which a `for` loop over a string calls for the character at each position, stepping by its length; `join`, `find`, `startswith`, and `endswith`; `stone.str_splitlines` (mirroring `stdlib::splitlines`), `stone.str_lower`/`stone.str_upper`, `stone.str_rposition` (behind `rfind`, -1 for none), `stone.str_count`, and `stone.str_replace`, whose two passes count the matches to size the result and then copy, `replace` without a count passing -1, which as unsigned never stops it; an empty text matches at every character boundary, as Rust's `replacen` and `matches` find it in the interpreter). A string inside a printed list prints as `stdlib::repr_in_list` writes it, like Python's `repr`, through `stone.print_str_quoted`. Whitespace is the ASCII set C's `isspace` uses (`stdlib::is_space`). Compiled programs call no libc: on Linux the runtime makes syscalls itself, and on macOS it calls only libSystem's syscall wrappers through `system_call` shims, which run on the 16-byte aligned stack arm64 always keeps; on x64 the stack needs no realigning, since generated code does not keep it aligned. `input` and `args` copy their text into counted strings. The builtin modules' functions are builtins too: `stdlib::MODULES` lists each `BuiltinModule` (its name, doc, and `DOCS` by linked name, such as `os.env`, from `src/stdlib/os.rs`, `math.rs`, `random.rs`, and `time.rs`, which also hold the functions the interpreter calls), and `stdlib::is_builtin` and `stdlib::module_function` accept them. `math` lowers to plain IR in `Lowerer::math` (compares, branches, and loops, with `Terminator::Fail` for its errors, and `FloatSqrt`), matching `stdlib::math` to the bit. The others lower to the runtime call `context::MODULE_ROUTINES` names (`stone.os_env`, `stone.time_sleep`, ...), except `random.randint` and `random.choice`, which check their arguments in IR and then call `stone.random_below`, and `os.env`, whose `stone.os_env` gives 0 for a variable that is not set. Builtins that may find nothing (`find`, `pop()` without an index, `get`, `os.env`) return an option, which `Lowerer::option_if` builds: `some` of the values on one branch (`new_variant`), the static `none`, retained, on the other. `random_runtime` keeps xoshiro256** state in `.bss` and draws exactly what `stdlib::random::Rng` draws, so seeded programs agree, seeding from `getrandom` (macOS `getentropy`) on first use otherwise; `time_runtime` makes `clock_gettime` and `nanosleep` calls. The `os` routines are emitted by `os_runtime` in both backends (`src/stdlib/os.rs` holds the only `unsafe` code, for libc's `gethostname` and `sysconf`) from the syscalls behind the libc calls the interpreter makes (`uname` for the host name, `/sys/devices/system/cpu/online` for the processor count, as glibc reads it; `sysctl` on macOS). An `os` routine that differs by system branches on `gen.target().os`. The `fs` routines (`src/codegen/x64/fs.rs`, `src/codegen/arm64/fs.rs`, emitted by `fs_runtime` for the `stone.fs_*` labels) borrow their string arguments and build the whole result themselves with `stone.enum_new`, as `stone.parse_int_result` does, so lowering is the plain `module_routine` call: `ok` of a string, list, or int, or `err` of a message from `.Lfs_err`, which words an error number from the same tables as the interpreter (`stdlib::fs::errors`, per `Os`, with `INVALID_TEXT_CODE` and `NULL_IN_PATH_CODE` for stone's own two errors) or as `os error N` through `stone.str_int`; `Context::lower` adds `stone.str_int`, and `stone.list_sort_str` for `fs.list_dir`, to what is emitted. Files are read whole into a doubling `stone.mem_alloc` buffer and checked by `.Lfs_utf8` (UTF-8 with no null byte, `stdlib::fs::is_text`); flags differ by system and, for `O_DIRECTORY`, by architecture (`context::OpenFlags`). Linux lists a directory with `getdents64`, and macOS with `opendir`/`readdir`. `os.run` is `stdlib::os::run` in the interpreter (Rust's `Command` once per path of `stdlib::os::candidates`, which both backends search in the same order with `execvp`'s error rules, so neither depends on a libc's search) and `stone.os_run` compiled (`src/codegen/x64/process.rs`, `src/codegen/arm64/process.rs`), which `emit_io_runtime` passes to `fs_runtime` rather than `os_runtime` so it shares `.Lfs_err`, `.Lfs_check_path`, and `.Lfs_utf8`: it forks (`clone` with `SIGCHLD` on arm64 Linux, libSystem's `fork` on macOS), the child moves `/dev/null` and two pipes onto fds 0-2 and tries each path with `execve`, writing the final error number to a close-on-exec pipe (`pipe2` flags on Linux, `fcntl` on macOS), and the parent drains both pipes with `poll` (`ppoll` on arm64 Linux), reaps with `wait4`, and builds `ok` with `context::OUTPUT_KINDS`, the status being minus the signal's number for a killed child. Under `cfg(fuzzing)` the interpreter's `os::run` runs nothing. `os.exit` makes the interpreter return the error `interpreter::Exit`, which `driver::run_module`, `driver::repl`, and `main` turn into the exit status without printing anything, and compiled code makes the `exit_group` syscall, skipping the leak check. Adding a builtin means updating `BUILTINS` and `BUILTIN_DOCS`, its type rule in `Inference::infer_builtin`, the interpreter's `Interpreter::call`, and its lowering in `Lowerer::call` (plus an IR instruction and its emission in both backends if it is not a runtime call), plus a program in `tests/programs/`. A function of a builtin module follows the same steps with that module's `DOCS` (a new module also goes in `stdlib::MODULES`), plus either IR lowering or a `MODULE_ROUTINES` entry and a routine in each backend's runtime for the module. Its golden programs cannot be named after a builtin module, so `tests/programs/math_module.stn`, not `math.stn`. A method follows the same steps with `METHODS`, `METHOD_DOCS`, `Inference::infer_method`, `Interpreter::call_method`, and `Lowerer::method`, and both backends evaluate the receiver before the arguments. A method that changes its receiver is also listed in `stdlib::changes_receiver`, and runs through the interpreter's `place_list` and the lowering's `unique_place` instead, evaluating the receiver's indexes, then the arguments, then making the change.

Language server (`lsp/`, crate `stone-lsp`, depends on `lsp-server`, `lsp-types`, `serde_json`):

- `src/lib.rs`: `run(connection)` does the initialize handshake (preferring UTF-8 positions, falling back to UTF-16), keeps open documents with full-text sync, and dispatches requests through `Server::answer`. On every open/change/close it reanalyzes every open document, reading files through `Workspace` (open documents' text over the disk), and publishes each one's diagnostics, the changed document first.
- `src/features.rs`: one pure function per request (`diagnostics`, `hover`, `definition`, `references`, `prepare_rename`, `rename`, `document_symbols`, `completion`) over a `Document`, which holds the text, the `stone::driver::analyze_linked` result of the whole program it belongs to (`Document::in_program`: the nearest `main.stn` at or above it, or the file alone if that program does not use it), its `FileId`, the `SourceMap`, the program's imports, and a `LineIndex`. Spans in other files become locations through `Document::location`, and a library function's symbol is named `<module>.<name>`, which `Document::local_name` shortens. An enum hovers with its variants and outlines with them as children, a variant hovers as `Shape.Circle(float)`, and completion after an enum's name and a `.` offers its variants (`enum_variants`). A struct hovers with its fields and outlines with them as children, a field hovers as `Point.x: float` and renames everywhere, including `x=` in a construction, and completion after a variable holding a struct and a `.` offers its fields (`struct_fields`). Builtins have no stone source, so `run` writes `stdlib::builtins_reference()` (comment-only, documenting each builtin type from `stdlib::TYPE_DOCS`, then each builtin from `stdlib::BUILTIN_DOCS`) to `<temp>/stone-lsp-<version>/builtins.stn`, and `definition` of a builtin jumps to its line there (`Builtins`). A builtin type's name not followed by `(` (`builtin_type_at`) hovers and leads to its type's line, so `int` in `x: int` is the type and in `int(x)` the conversion, except `fn`, which is the type `fn(T1, ...) -> R` (in `TYPE_DOCS`) only when followed by `(`. `Document::tokens` (from `lex_recovering`) feed `Document::in_code`: in a string's text (strictly inside a string token's span, so a value's contents and the spot before its `}` are code) or after a `//` outside one, `hover` shows only the expression's type, `definition` gives nothing, and `completion` offers nothing. `completion` asks `slot` whether a type (`Slot::Type`: after `->`, a definition's or lambda's `name: `, a struct field's line, a variant's parentheses, or the brackets of a type, found from the line's tokens before the word, so a string's text counts for nothing, and `headers`, the lines opening its blocks) or a bound (`Slot::Bound`, after `[T: ` in a definition) comes next, and `type_completion` offers `TYPE_DOCS`, type parameters of the enclosing function and its struct or trait, `Self` in an `impl`/`trait` block, and the file's, imports', and prelude's structs and enums (or traits). After a `.`, a variable's type comes from its symbol and any other receiver's (`xs[0].`, `f(x).`, `p.items.`) from `receiver_type`, which checks the program again through an `Overlay` of `Sources` with the line minus the `.` and the member (then with a `}` there, for an unfinished string value) and takes the type of the expression ending at the dot that starts last, skipping a version with an error on that line; `member_completion` then offers the type's members, always with `display`. `use_completion` offers `SOURCE_MODULES` too, analyzing `use net` on its own for `use net.` before the program uses it. It writes `stdlib::PRELUDE` beside it as `prelude.stn`, where `definition` of `some`, `none`, or `option` goes (`Builtins::prelude_location`); `Document::location` gives nothing for a prelude span, and its symbols cannot be renamed. It writes each of `stdlib::SOURCE_MODULES` there too (`net.stn`), where `definition` of a name in such a file, or of `use net`, goes (`Builtins::builtin_location`), and those names cannot be renamed either. Add a feature here with unit tests in `src/features/tests.rs`, then wire it into `Server::handle_request` and `capabilities`. A method or associated function hovers as `fn Point.shift(self, dx: float)` (`function_signature`), outlines under its struct after the fields (`struct_methods`, `function_outline`), and completion offers a struct value's methods with `self` (`has_self`) after its fields, and a struct's associated functions after its name and a `.`. A trait hovers with its methods' signatures and outlines with them (`trait_methods`, `SymbolKind::INTERFACE`), a bounded type parameter hovers as `(type parameter) T: Shape` and signatures show bounds (`bounds_of`, from `Analysis::bounds`), completion after a value of a bounded `T` (or `Self` in a default) offers its traits' methods (`bound_methods`) and after a struct value the defaults of the traits it implements (`Analysis::implemented`), and `method_applies` offers `eq`/`cmp` on builtin types.
- `src/line_index.rs`: converts stone's 1-based char positions to LSP's 0-based UTF-16 or UTF-8 positions.
- `src/uri.rs`: converts between `file://` URIs and paths.
- Tests: unit tests for features and positions, `tests/server.rs` over an in-memory connection, and `tests/stdio.rs` against the real binary.
- `driver::analyze_linked` recovers from syntax errors statement by statement, in blocks too (`Parser::parse_recovering`, `parse_statements`), so features keep working around a typo, and it hides type errors until the syntax and `use` errors are fixed.

## Style

These apply to code, comments, docs, and commit messages.

- Never use em dashes.
- Never use emojis.
- Always use American English (e.g. "initialize", "color", "behavior").
- Doc comments (`///`, `//!`) are written in full sentences, and should include examples wherever practical:

  ```rust
  /// Rounds a frame size up to the 16-byte stack alignment required by the System V ABI.
  ///
  /// For example, `align16(20)` returns `32` and `align16(32)` returns `32`.
  fn align16(size: i32) -> i32 {
  ```

- Inline comments (`//`) start lowercase and are almost never full sentences, e.g. `// globals live in main's frame`, not `// Globals live in main's frame.`

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:

- When graphify-out/graph.json exists, run `graphify query "<question>"` before your first grep, search or source-file read for a codebase question, and put this rule in every subagent prompt that explores code. Read raw files only for lines the graph or an earlier read already located. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
- A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected. Do not flag it as churn or suggest skipping the graph rebuild or its hooks.
