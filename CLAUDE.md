# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

stone is a small Python-like language implemented in Rust (edition 2024, only dependency: `clap`, except for the opt-in `self-update` feature). The workspace also holds `lsp/`, the `stone-lsp` language server, which has its own dependencies, and `editors/vscode/`, a VS Code extension that runs it. One binary provides both a tree-walking interpreter and a compiler for x86-64 and arm64 Linux, arm64 macOS, and x86-64 Windows (without `net` or `os.run` there yet). Blocks open with `:` as in Python (e.g. `if x:`, `fn f(a: int, b: int) -> int:`), and `;` is not a token at all (`unexpected character ';'`); functions return with `ret`, and `continue` is `cont`. Every function parameter has a type, and a function that returns a value writes `-> T` (without it, it returns no value, and its call can only be a statement); nothing else is ever annotated. A top-level `const name = value` (`pub const` for other files, read as `m.name` or after `use m.name`) is a constant in any file, libraries included: its value, from literals, other constants, `math.pi`/`tau`/`e`, operators, and tuples, is worked out when the program is built (`constant::evaluate`, a failing operation or a call being error `E0050`), and code anywhere in its file reads it, tests included; it is never assigned, and no variable takes its name. Enums are Rust's algebraic data types (`enum Shape:` with a variant per line, `Shape.Circle(1.0)`, `match s:` with `case Shape.Circle(r):`), and `option[T]` (`some(x)` or `none`) is an ordinary generic enum that `src/prelude.stn` defines and every program is linked with, its variants written alone; `none` is only an option. `result[T, E]` (`ok(x)` or `err(e)`) is another prelude enum, and postfix `?`, the only syntax it adds, gives an `ok`'s or a `some`'s value or returns the `err` or `none` from the enclosing function, which must return a result with the same error type (or an option). The prelude also defines one struct, `output` (`status: int`, `stdout: str`, `stderr: str`), which `os.run(cmd, args) -> result[output, str]` returns; like `result`, its name may be taken by a variable (the checker's `value_struct`), but not by a function. Structs are Rust's structs, data only for now: `struct Point:` with a typed field per line (`x: float`), made with a named value for every field in any order (`Point(x=1.0, y=2.0)`), read as `p.x`, and changed in place as `p.x = v`, `ps[i].x += v`, or `p.items.append(v)`; like lists they are values. An `impl Point:` block, in the struct's own file, holds its functions: a method takes `self`, untyped, first and is called as `p.norm()`, and an associated function is called as `Point.origin()`; a method that changes `self` changes its receiver in place, as `append` does, with no keyword, and its call is a statement or the whole value of an assignment. Functions can be generic, with type parameters in brackets after the name (`fn first[T](xs: list[T]) -> T:`), which each call infers; the body is checked once with `T` opaque (it can be moved, stored, and printed, but has no operators, comparisons, or methods), and `stone build` compiles a copy per set of types. Structs and enums can be generic the same way (`struct Pair[A, B]:`, `enum Tree[T]:`), written with their types filled in (`Tree[str]`); an `impl` block of a generic struct takes no brackets, and its methods are generic over the struct's parameters; a method, associated function, or trait method may also have type parameters of its own after its name (`fn map[U](self, f: fn(T) -> U) -> Box[U]`), with bounds, which each call infers. Maps are `map[K, V]` with `int`, `str`, or `bool` keys, written `{"a": 1}` (`{}` empty), read as `m[k]` (failing with `key not found: 'k'`), set as `m[k] = v` or changed through any place (`m[k] += 1`, `p.m[k].append(x)`), with `len`, `contains`, `get`, `pop(k)` (an option), `keys`, `values`, and `items`, iterated by key (`for k in m`), kept in insertion order, and values like lists. Sets are `set[T]` of the same element types, written `{1, 2}`, a map whose entries hold no value (the checker's `set_of`, `Ty::Map(T, ())` with `no_value`, an empty tuple no program can write, and publicly `Type::is_set`), so `{}` is a map or a set by its use (`add` or a `set[T]` makes it a set, a read of values a map, and an unsettled one a map), with `add` and `remove(x) -> bool` (changes), `union`, `intersection`, `difference`, `is_subset`, `is_superset`, `is_disjoint`, `in`, `len`, `for`, `==`, and the conversions `set(xs)` and `list(s)`. `in` and `not in` (`CompOp::In`/`NotIn`) test a map's keys, a list's elements (by `==`), or a string's text, as `contains` does on all three, and never chain with other comparisons (a checker error); the checker's `membership` (deferred through `Membership` when the container is unknown), the interpreter's `contains`, and the lowering's `contains_values` (an inline loop over borrowed elements for a list) serve both forms. The bitwise operators `&`, `|`, `^`, `~`, `<<`, `>>` (and `&=` ... `>>=`) take ints with Python's precedence (`ast::Operator::BitAnd` ... `RShift`, `UnaryOp::Invert`; `parse_bitwise_or` down to `parse_shift_expr` between `parse_comparison` and `parse_sum`, a binary `|` being `TokenType::VBar` after a value, which `format.rs` spaces as `Kind::Binary`), `&`, `|`, `^` also two bools, and lists of ints element by element (`& | ^ ~` packed with SIMD, `~x` lowered as `xor x, -1`); shifts are strict, a count outside 0..=63 failing with `stdlib::SHIFT_RANGE` and a `<<` whose exact result does not fit with `SHIFT_OVERFLOW` (`stdlib::shift_left`/`shift_right`; compiled as IR checks around the raw, count-masking `BinOp::Shl`/`Shr` in `Lowerer::shift`), and int literals take `0x`/`0o`/`0b` and `_` between digits (`Lexer::lex_prefixed`, `lex_digits`). Traits are Rust's, with static dispatch only: `trait Shape:` lists methods, body-less (`fn area(self) -> float`) or with a default body, `impl Shape for Circle:` implements them for a struct or for `int`, `float`, `bool`, or `str`, and bounds (`fn total[T: Shape + Named](xs: list[T])`) give a type parameter its traits' methods; `Self` names the type in a trait or `impl` block. The prelude's traits `eq` (automatic for every type `==` compares part by part, overridable by a struct's `fn eq(self, other: Self) -> bool`) and `ord` (`int`, `float`, `str`, or a struct's `fn cmp(self, other: Self) -> ordering`) back `==`, `<`, and `sort`, and `ordering`'s variants `less`, `equal`, `greater` are written bare like `some`. A trait may have type parameters (`trait combine[R]:`), which a type implements once per set of arguments (`impl add[int] for V:`, `impl add[V] for V:`), a call picking the impl its arguments fit, and a bound gives them (`[T: add[U], U]`). The prelude's generic traits `add[R]`, `sub[R]`, `mul[R]`, `div[R]`, `rem[R]`, `bitand[R]`, `bitor[R]`, `bitxor[R]`, `shl[R]`, and `shr[R]` (each `fn <name>(self, other: R) -> Self`) and `neg` and `invert` (`fn neg(self) -> Self`) back `+ - * / % & | ^ << >>` (and their `+=` forms) and unary `-` and `~` on a struct or a type parameter, the left operand as `self` picking the impl by the right operand's type; `int` implements each with its own type, `float` the arithmetic ones, `bool` `bitand`/`bitor`/`bitxor`, and `str` and `bytes` `add`, builtin (`checker::builtin_operator`, `unary_trait`), a program cannot implement one for a builtin type, a program's trait cannot take their names but a function can, and lists keep their element-by-element rules. Conversions are the prelude's generic traits `from[T]` (`fn from(value: T) -> Self`) and `try_from[T]` (`fn try_from(value: T) -> result[Self, str]`), the only trait functions without `self`: a type called with one positional value, `T(x)` (`int(s)`, `Fahrenheit(c)`, `T(n)` under `[T: from[int]]`), converts it, giving a `T` or a `result[T, str]`. Builtin: every type from itself and to `str` (through `display`), `float` from `int`, and through `try_from` (so results) `int` from `float` or `str`, `float` from `str`, and `bytes` from `list[int]`; there are no `parse_int`/`parse_float`. `assert test` (or `assert test, msg`, `msg` a `str` evaluated only on failure) is a runtime error at `test` unless it holds, `assertion failed` plus `: msg`, or, for a single comparison, `: <left> <op> <right>` with both sides written as `print` writes them and strings quoted as in a list. A top-level `test "description":` block (`test` a keyword only there, before a string) holds checks that `stone run` and `stone build` never run; a test may not read a global, even through its calls, since tests run without top-level code. Every string literal interpolates with no prefix: `"{name} has {xs.len()}"` writes each braced expression (any expression, strings of its own included) as `print` writes it, `{{` and `}}` are braces, and a `:` ending a hole's expression starts a format spec, Python's mini-language (`{x:.2f}`, `{n:>5}`, `{n:08}`, `{x:e}`, `{n:,}`, `{n:#x}`), which writes CPython's text; fill, alignment, and width pad any value, and a value inside a spec (`{x:.{p}f}`) is not supported yet. `str(x)` takes any value, and the prelude trait `display` (`fn display(self) -> str`, automatic for every type, overridable by a struct as `eq` is) backs `print`, `str`, `x.display()`, and interpolation, wherever a value appears. Functions are values: a top-level function's name without parentheses (`apply(double, 3)`, `geo.area`, a generic one taking its types from its use) has the type `fn(int) -> int` (`fn(str)` for one without `->`), and any value of a function type is called (`f(x)`, `fs[0](x)`, `p.run(x)` for a struct field holding one); a lambda writes one in place, `|x| x * 2` or `|p: Point| p.x` (bars around the parameters, whose types are inferred from where it is used unless written, and one expression on the same line), and a lambda that uses variables around it (an enclosing function's parameters and variables, an enclosing lambda's parameters, globals) is a closure, which captures a copy of each where it is written (moving a variable its statement uses for the last time and mentions once), cannot change its copies, and may capture a value of a type parameter or a handle (a socket stays open while a closure holding it may be used); builtins, methods, and variants are not values, function values are never compared, and they print as their type (`type_text`), with the types of the copy that made them in generic code. Lists' methods `map`, `filter`, `any`, `all`, `sort_by_key` (changes the list), `min_by_key`, and `max_by_key` (options) take a function and are prelude functions (`stdlib::PRELUDE_METHODS`), as are `a.min(b)`, `a.max(b)`, and `x.clamp(lo, hi)` on every `ord` type (`stdlib::ORD_METHODS`; a struct's own method or a bound's of the same name wins), where the prelude's `clamp` returns `(in_order, value)`, a tuple so nothing is allocated, and both backends fail with `stdlib::CLAMP_RANGE` at the call when `in_order` is false (the interpreter's `call_method_of_struct`, lowering's `struct_call`). The `net` module (`use net`) makes TCP connections: `net.connect(host, port) -> result[socket, str]`, `net.listen(host, port) -> result[listener, str]` (port 0 picks one), and `net.resolve(host) -> result[list[str], str]`; `socket` (`send`, `read_line`, `read`, `read_all`, `close`) and `listener` (`accept`, `port`, `close`) are builtin types a signature names like `str`, handles rather than values (copies share the connection, they are never compared or map keys, and they print as their type), and each closes right after the last statement that uses it, at the same point in both backends. `net` is written in stone (`src/stdlib/net.stn`), finding addresses itself from `/etc/hosts`, `localhost`, and DNS servers in `/etc/resolv.conf` (`STONE_HOSTS` and `STONE_RESOLV_CONF` override the paths; a `nameserver` may give a port, as `127.0.0.1:5353`), so both backends agree; no TLS. Sockets also send and read `bytes` (`send_bytes`, `read_bytes(max)`, `read_exact(n)`, `read_all_bytes()`, sharing one buffer with the text reads), and `set_timeout(seconds: float)` on a socket or listener, or `net.connect_timeout(host, port, seconds)`, makes each wait give up with `err("timed out")` (milliseconds rounded up, `<= 0` or nan forever). `bytes` is a builtin type for data that is not text: literals `b"a\x00\xff"` (`\x00`-`\xff`, ASCII otherwise, no interpolation), `b[i]` an int, slices, `+`, `==`/`<`, `in`, `for` over ints, `sort`, printed as Python's repr (`stdlib::repr_bytes`), never changed or a map key; `s.bytes()`, `b.text() -> result[str, str]`, `bytes(xs: list[int])` (a result, `err("byte out of range (value 300)")`), and `fs.read_bytes`/`write_bytes`/`append_bytes`. See `examples/basics.stn` for a sample program.

## Philosophy

`docs/philosophy.md` is the source of truth; read it before designing a feature. In short: Python's simplicity with Rust's memory safety, speed, and error reporting, achieved by moving all complexity into the compiler, and compiled programs that depend on no libc (raw syscalls on Linux, the thinnest system layer on macOS and Windows) and no gcc, since `stone build` assembles and links itself. If the compiler can infer something (types, ownership, laziness, copies), the language never asks the programmer to write it, with one exception: function signatures are written, for readable contracts and errors at the place a mistake is made, and everything inside them is inferred, as in Rust; prefer changing semantics so the fast, safe choice is always valid over adding a keyword. stone has value semantics: assignment, argument passing, and storing in a list behave as copies, implemented with copy on write and in-place updates of uniquely owned values, so a function changes its caller's list only by returning it (`xs = f(xs)`, which both backends turn into an in-place update by moving `xs` into the call, as they move any value at its last use). When goals conflict, rank safety, then programmer simplicity, then clear errors, then speed, then compiler simplicity. Keep the page's "Status" notes current as work lands.

- Test: `cargo test`. Unit tests live in `#[cfg(test)]` modules in `src/lexer.rs`, `src/ast.rs`, `src/parser/tests.rs`, `src/checker/tests.rs`, `src/constant.rs`, `src/project/tests.rs`, `src/lift.rs`, `src/last_use.rs`, `src/unused.rs`, `src/lint.rs`, `src/lint/checks.rs`, `src/explain.rs`, `src/interpreter.rs`, `src/format.rs`, `src/codegen/ir/lower/tests.rs`, `src/codegen/ir/opt.rs`, `src/codegen/ir/opt/fold.rs`, `src/codegen/ir/inline.rs`, `src/codegen/ir/liveness.rs`, `src/codegen/regalloc.rs`, `src/codegen.rs`, `src/codegen/device.rs`, `src/codegen/gpu/ir.rs`, `src/codegen/gpu/kernel.rs`, `src/codegen/gpu/eval.rs`, `src/codegen/gpu/ptx.rs`, `src/codegen/gpu/compile.rs`, `src/codegen/gpu/cubin.rs`, `src/codegen/x64/gpu.rs`, `src/codegen/x64/gpu_windows.rs`, `src/codegen/gpu/image.rs`, `src/codegen/arm64/gpu.rs`, `src/codegen/asm.rs`, `src/codegen/asm/x64.rs`, `src/codegen/asm/arm64.rs`, `src/codegen/elf.rs`, `src/codegen/macho/tests.rs`, `src/codegen/pe/tests.rs`, `src/codegen/sha256.rs`, `src/codegen/x64.rs`, `src/codegen/arm64.rs`, `src/stdlib.rs`, `src/stdlib/os.rs`, `src/stdlib/math.rs`, `src/stdlib/random.rs`, `src/stdlib/time.rs`, `src/stdlib/fs.rs`, `src/stdlib/net.rs` (over loopback, timeouts included), `src/driver.rs`, `src/uninstall.rs`, and `src/update.rs` (which needs `--features self-update`). `tests/cli.rs` runs the binary to check error output and exit codes, that built programs need only the system (static on Linux; on macOS, `codesign --verify` passes and `otool -L` lists only libSystem), that `os.hostname()` and `os.cpu_count()` match between backends, that both backends resolve names alike through a fake DNS server on a free UDP port (`dns_reply`, through `STONE_RESOLV_CONF`) and give up connecting to an unanswered address after a timeout (skipping if the network refuses at once), and that they print and parse thousands of random floats exactly as the interpreter does. `tests/assembler.rs` assembles every golden program for both targets with the built-in assembler and with GNU as plus GNU ld at the same section addresses, and requires identical `.text`, `.rodata`, and `.data` bytes and `.bss` size (x86-64 at `v1`, `v2`, `v3`, and `v4`, and aarch64 at `v9`, for which GNU as gets `-march=armv9-a`) (needs `as`/`ld` for the host and `aarch64-linux-gnu-as`/`-ld` or `x86_64-linux-gnu-as`/`-ld` for the other target, skipping a target whose tools are missing). `tests/gpu.rs` writes every golden program's kernels as PTX for `sm_50`, `sm_75`, and `sm_120` and compiles each with `ptxas` when it is on PATH, skipping with a note otherwise (`pip install nvidia-cuda-nvcc-cu12` gives one in `nvidia/cuda_nvcc/bin`, no GPU needed)
- Golden-output tests: `tests/programs.rs` runs every `.stn` in `examples/`, `tests/programs/`, and `docs/examples/` through both `stone run` and `stone build`, comparing stdout with the sibling `.out` file. A program that should fail at runtime also has a `.err` file holding text its stderr must contain, read with the program's directory left out of every path (`without_directory`): the position line without the path (`:3:7: error: division by zero`), or the whole error with its `called from here` frames (the `call_chain*` programs), so both backends must point at the same place and show the same calls. A sibling `.stderr` file holds the exact stderr a run must write under every backend (for `eprint`; without one, a successful run's stderr is not checked). Each backend runs a program in a new empty working directory of its own (`<target tmpdir>/<backend>/<name>.cwd`), first filled with a copy of a sibling `.files` directory if there is one (`fs_fixture.files/` beside `fs_fixture.stn`, `main.files/` beside a `main.stn`), which discovery skips, so programs that write files never meet. A sibling `.in` file becomes the program's stdin (otherwise it is empty), a `.args` file holds its command-line arguments, one per line, and a `.env` file holds `NAME=value` lines that every backend adds to its environment (for `os.env`). A subdirectory of one of those directories is a program of several files, run from its `main.stn`, with `main.out` (and any `.err`, `.in`, `.args`, `.env`) next to it, as in `tests/programs/modules/`. Both backends must agree on everything the checker accepts, so `SKIPS` should stay empty. `stone build` targets the host, and a third pass (`build-aarch64` on x86-64, `build-x86_64` on arm64) cross-builds every program with `--target` and runs it under qemu-user when `qemu-aarch64`/`qemu-x86_64` is on PATH, skipping with a note otherwise; compiled programs are static, so qemu needs no target libc. Level passes (`Backend::Level` of a `Leveled` name and `LevelRunner`) build every program for a level and run it: `build-x86_64v3` on an x86-64 host (not macOS) that `reaches_x86_64_v3`, `build-x86_64v4` natively when `reaches_x86_64_v4` or else under Intel SDE (`sde64 -spr --`, Linux, when on PATH), and `build-aarch64v9` (Linux) natively when `reaches_sve2` or else under qemu-aarch64, whose default `max` processor has SVE2; `tests/cli.rs`'s `sve_code_runs_alike_at_every_vector_length` runs `packed_widths` under qemu at 128-, 512-, and 2048-bit vectors and expects the SVE2 error on `cortex-a72`, and `tests/cli.rs`'s `a_program_built_for_a_level_runs_only_on_a_processor_that_reaches_it` builds `v2`-`v4` and expects output or `level_missing` by `is_x86_feature_detected!`. Off macOS, `every_program_links_for_macos` builds every program with `--target aarch64-macos` without running it. Off Windows, a `build-x86_64-windows` pass (`Backend::Windows`, `WindowsRunner`) builds every program as an `.exe` and runs it through WSL interop (found from `/proc/sys/fs/binfmt_misc/WSLInterop*`, passing `STONE_LEAK_CHECK` and `.env` names through `WSLENV`, which cannot pass an empty value, so `os_env` is skipped there, and with its working directory under the Windows `%TEMP%`, since the WSL file share gives spurious sharing violations) or else `wine`, and otherwise only links it (`windows_compiler_matches_expected`); a program whose check reports `driver::unsupported`'s message (`net.connect_unix`) is skipped for Windows, as is any program in `NOT_ON_WINDOWS` (`gui_no_display`, which is about Linux display variables, and `os_run`, which runs `sh`), and every other backend skips the programs in `ONLY_ON_WINDOWS` (`os_run_windows`, `os_run`'s twin over `cmd`). A `windows-latest` CI job runs `cargo test` natively, so there the build pass runs every program as a PE, plus clippy and `scripts/test-install.ps1` under both PowerShells. CI's x86-64 job installs `qemu-user binutils-aarch64-linux-gnu`, a `ubuntu-24.04-arm` job runs everything natively and installs `qemu-user binutils-x86-64-linux-gnu`, and a `macos-15` job runs `cargo test` (so every golden program runs as a Mach-O) plus the fuzz crate's tests natively. Built binaries run with `STONE_LEAK_CHECK=1`, so a program that ends with any string or list still allocated fails (see "Memory" below). Add a program plus its `.out` to cover new behavior
- Fuzzing: the `fuzz/` crate (cargo-fuzz, nightly) has crash targets `lex`, `parse`, `format` (formatting its own output changes nothing), `interpret`, `codegen`, and `structured`, plus `differential`, which compares `stone run` with `stone build` on generated programs. Run one with `cargo +nightly fuzz run parse -- -dict=fuzz/stone.dict`. `cargo test --manifest-path fuzz/Cargo.toml` checks the program generator on stable, including that generated programs pass the checker and format stably, that 2,000 of them assemble and link for every target, and that 150 of them print the same under both backends and free everything, plus the same checks on longer inputs (`compound_sources`), which reach compound values more often. The generator writes strings too, keeping them from failing: only ASCII "words" of at least two bytes are indexed and sliced. It also declares structs (with `impl` blocks) and enums and works with them, options, maps, and lists of them through a type-directed `Generator::value` in `fuzz/src/compound.rs`, whose module doc lists the rules that keep those programs valid and from failing (no list shrinks, map variables only gain entries, bare `none` only where the type is fixed, no unreachable `case`). `STONE_FUZZ_TARGET=aarch64` makes that check (and `differential`) build for aarch64 and run under qemu, like the cross golden pass. Turn each crash into a regression test, as a unit test or a `tests/programs/` program
- Benchmarks: `cargo run --release --manifest-path bench/Cargo.toml -- [--runs 5] [--filter fib]` times each program in `bench/programs/` under `stone build`, `gcc -O2`, `gcc -O0`, and `python3`, after checking all four print its `.out` file, and prints a Markdown table (needs gcc and python3). Each benchmark is a `.stn`, `.c`, `.py`, and `.out` with the same stem, plus an optional `.args` holding the workload size, one argument per line, that every version runs with, and an optional `.np.py` that `--numpy PYTHON` (a Python that can import numpy, such as a virtualenv's) times too, as `vector` has. `cargo test --manifest-path bench/Cargo.toml` checks the runner and that every benchmark passes the checker. See `bench/README.md`

- Start a project: `cargo run -- init [path] [--lib] [--name NAME] [--no-git]` (`src/init.rs`, templates in `src/templates/`) writes `stone.toml`, `main.stn` (or `lib.stn`), and `.gitignore`, and runs `git init` outside a repository. A project's `main.stn` is the entry point: `run`, `build`, and `check` without a file use `driver::find_entry` (a file as given, a directory's `main.stn` or, for `check`, `lib.stn`, else the nearest root at or above the current directory from `driver::find_root`, written relative as `../main.stn`), and `test`, `clean`, `fetch`, `tree`, `add`, `remove` use `driver::program_dir`
- Interpret a file: `cargo run -- run examples/basics.stn [-- args...]` (or `cargo run -- examples/basics.stn`; program arguments go after `--`, and `main.rs`'s `with_dashes_tip` explains an undashed one). `default-run` picks the `stone` binary, since the workspace also builds `stone-lsp`
- Compile a file: `cargo run -- build examples/basics.stn [more.stn ...] [-o out] [--target x86_64-linux|aarch64-linux|aarch64-macos|x86_64-windows ...] [--gpu sm_75 ...] [--windows-gui]` writes `<output>.s` (and `<output>.<gpu>.ptx` per `--gpu`, see `src/codegen/gpu.rs` below), then assembles and links it itself into `<output>`: a static Linux executable that needs no libc, a signed arm64 macOS executable that needs only libSystem, or an x86-64 Windows console `.exe` that imports only from `kernel32.dll` and `bcrypt.dll` (plus `user32.dll`, `gdi32.dll`, and `dwmapi.dll` if it opens a `gui` window; `--windows-gui` makes it a GUI-subsystem program instead, `pe::Subsystem` through `driver::compile_module`, `codegen::link`, and `executable_of`, an error unless a target or the host is Windows) (no other tools needed). `driver::output_path` adds `.exe` for Windows, and `-o` is kept as written. Without `-o` (which needs one file and one target), the output is `driver::output_path`: `build/` next to the entry file (so `examples/build/basics`), named by `driver::program_name` (the stem, or for a `main.stn` the `[package] name` of a `stone.toml` beside it that parses without errors, else its directory's name), in `build/<target>/` for a target other than the host. `driver::prepare_build_dir` writes a `build/.stone` marker, and `stone clean [path]` (`driver::clean`) deletes only a `build/` that has it. The target defaults to the host (`Target::host`, an error on an Intel Mac), and every target builds from any machine. Mach-O output cannot run here, but LLVM's `llvm-objdump --macho --private-headers --chained-fixups --dyld-info` (unpack an `llvm-20` deb) and `rcodesign verify` (a prebuilt release; it complains only that an ad hoc signature has no CMS blob) inspect it
- Format: `cargo fmt`
- Lint: `cargo clippy --all-targets`
- Test: `cargo run -- test [paths...] [--build] [--filter TEXT] [-j N]` runs the `test "description":` blocks of every file with any under the paths (`src/testing.rs`; see Architecture). `tests/testing/` holds its fixtures, whose report `tests/cli.rs`'s `stone_test_*` tests compare with `tests/testing/report.txt` under both backends, in a copy of the directory
- Check a file without running it: `cargo run -- check examples/basics.stn [--deny warnings]`. Errors print as `file:line:col: error[E0005]: message` with the source line and a caret, and the exit status is 1; warnings as `warning[W0004]: message`, which `--deny warnings` (`lint::deny_warnings`) makes errors. `check` (and the LSP) also warn about unused names (`src/unused.rs`), which `run` and `build` never print
- Format: `cargo run -- fmt [paths...] [--check]` (`src/format.rs`; see Architecture). `tests/format.rs` fails unless every `.stn` in `examples/`, `tests/programs/`, `docs/examples/`, `src/`, and `bench/` is formatted (except its `UNFORMATTED` list), so run it after writing stone code
- Releases: `sh scripts/bump-version.sh <stone|vscode> <major|minor|patch|X.Y.Z>` bumps the version everywhere it is recorded (`vscode` sets the extension and `stone-lsp` to one version) and prints the commit and tag commands, and `sh scripts/test-bump-version.sh` tests it. Versions are bumped right after a release, so the recorded version is the next to release and its changes are listed under `## [Unreleased]` in `CHANGELOG.md` (stone) and `editors/vscode/CHANGELOG.md` (the extension and `stone-lsp`) as they land. Both release workflows check for and publish `scripts/changelog.sh release-notes <file> <version>` (the version's section, else `[Unreleased]`) as the release notes, `vscode.yml` dates the packaged changelog so the Marketplace shows the version, and a bump whose current version is tagged runs `scripts/changelog.sh release` to date `[Unreleased]` as that version with the tag's day (`sh scripts/test-changelog.sh` tests the script and that every heading and release tag has notes). Pushing a `v<digit>*` tag (`v[0-9]*`, so `vscode-v*` tags do not match) that matches `version` in `Cargo.toml` runs `.github/workflows/release.yml`, which builds `stone-<machine>.tar.gz` plus a `.sha256` for x86-64 and arm64 Linux (musl) and macOS, named by stone's target names (`x86_64-linux`, `aarch64-macos`, plus `x86_64-macos`), not rustc's and publishes them as a GitHub release. `install.sh` (POSIX sh) downloads the archive for the current machine into `~/.local/bin` and verifies its checksum. `sh scripts/test-install.sh` (after `cargo build`) tests it against a local `file://` release via `STONE_DOWNLOAD_URL`, and CI runs both test scripts plus `shellcheck scripts/*.sh`. Windows releases are `stone-x86_64-windows.zip` (`update::asset_name`; `self_update`'s zip features), which `install.ps1` (PowerShell 5.1 and 7, `irm ... | iex`, options from the environment or as parameters, failures thrown so they never close the user's shell) installs into `%LOCALAPPDATA%\Programs\stone\bin` and adds to the user `PATH`, tested by `scripts/test-install.ps1` with `STONE_NO_MODIFY_PATH`. `stone uninstall` on Windows renames the binary to `stone.exe.old` and starts a hidden, detached `cmd` loop that deletes it once stone exits (`uninstall::remove`)
- Update: `stone update [--check] [--version <tag>]` replaces the binary with a GitHub release. It lives in `src/update.rs` behind the `self-update` cargo feature (the `self_update` crate with `ureq` and rustls), which only release builds enable, so default builds, CI's main test run, and fuzzing never pull in an HTTP stack. Without the feature the subcommand explains how to upgrade instead. It picks `stone-<machine>.tar.gz` by exact name (`machine`, `pick_asset`), checks it against the release's `.sha256` asset and GitHub's per-asset digest, and runs the new `--version` before swapping it in. CI also runs clippy and the unit tests with the feature on. `stone uninstall [--yes]` (`src/uninstall.rs`, in every build) deletes the running binary after a `[y/N]` prompt, needs `--yes` without a terminal, and refuses a binary in `$CARGO_HOME/bin`, pointing to `cargo uninstall stone`
- Language server: `cargo test -p stone-lsp` runs its tests, and `cargo install --path lsp` installs `stone-lsp`. See `editors/vscode/DEVELOPMENT.md` to try it in VS Code and to release it. The extension's `npm test` (in `editors/vscode`) tests `server.js`, which picks the server: the `stone.server.path` setting, else a bundled `server/stone-lsp`, else `stone-lsp` on PATH. Pushing a `vscode-v*` tag matching `editors/vscode/package.json`'s version runs `.github/workflows/vscode.yml`, which packages a `.vsix` per platform bundling `stone-lsp` plus a universal one and publishes them to the VS Code Marketplace and Open VSX (the Marketplace through a Microsoft Entra ID app registration via `azure/login` OIDC and `vsce publish --azure-credential`, since global Azure DevOps PATs retire December 1, 2026; Open VSX through the `OVSX_PAT` secret), then a GitHub release with the `.vsix` files attached, created with `--latest=false` because `install.sh` and `stone update` read the Latest release (stone's releases pass `--latest`)

The `debug!` macro (defined in `src/lib.rs`) prints token dumps and parser traces to stderr only in debug builds with `STONE_DEBUG` set (e.g. `STONE_DEBUG=1 cargo run -- run file.stn`), and never under `cargo fuzz`.

## Workflow

- Practice TDD. Write the test first, run it and confirm it fails for the expected reason, then write the implementation that makes it pass.
- After every change, run `cargo fmt` and `cargo clippy`, and address what clippy reports.

## Architecture

The crate is a library (`src/lib.rs`) plus a thin CLI (`src/main.rs`, clap only). Pipelines are wired in `src/driver.rs`:

- **load** (`driver::load`, used by `run` and `build`): `project::link` (`Lexer` → `Parser` for the entry file and every module it uses, then linking) → `TypeChecker`, returning a `Checked` (the linked `Mod`, any warnings, which `run` and `build` print before going on, and the checker's `Calls` (`Analysis::calls`: the `Methods`, every function value with its printed type, and every call of a value), which `run_module` gives the interpreter) and a `SourceMap` for rendering diagnostics from any file
- **run** (`driver::run_module`): load → `Interpreter`. `driver::interpret` does the same for a single source string with no other files
- **build** (`driver::compile_module`, given the `Checked` and a `Target`): load → `Target::generator` (`X64Generator`, or `Arm64Generator` for the target's `Os`), given `Checked::analysis` through `set_analysis` so `Context::check` does not check the module again → `compile` (check, scan pass lowers to IR, inlines small leaf functions (`ir::inline`) and optimizes it (`ir::opt`), generate pass allocates registers and emits, then `codegen::link` writes the `.s` file, and `codegen::executable` encodes it with `asm::assemble` and links it with `elf::link` or `macho::link`)
- **fmt** (`format::format`, `main.rs`'s `fmt`): a token formatter, since every statement is one line (newlines end statements inside brackets too) and the AST loses comments, parentheses, and literal spelling. It lexes with `Lexer::keeping_comments` (comments recorded with their spans in `Lexer::comments`, tokens unchanged), parses as the prelude (so a variant may be `none`) to refuse what does not parse, groups tokens into `CodeLine`s by `Newline` with a level from `Indent`/`Dedent`, and writes each at four spaces per level, its tokens joined by `Spacer` (a stack of `Group`s: `Index` for a `[` after a value, whose `:`s stay tight, `Square` for others including a definition header's type parameters, `Paren` for `x=1` named values, `Hole` for a string's values; a `Kind` per token, `-` unary after anything that does not end a value) and literals copied from the source by span. A comment-only line takes the deepest level whose source width is at most its own, or the next level right after a block opener; runs of blank lines become one, none after a block opener. Before returning it lexes the result and requires the same token types and comment texts, else an error naming it a bug. `driver::stone_files` lists a directory's `.stn` files (skipping hidden and marked build directories) for the CLI and `tests/format.rs`, and the LSP's `features::formatting` answers `textDocument/formatting` with one whole-document edit
- **check** (`driver::check_program`): `project::link` → `TypeChecker` → `unused::find`, returning every `Diagnostic` instead of running. `driver::analyze_linked` is the entry point for editor tooling, and leaves unused warnings out, so `driver::check`, the checker tests, fuzzing, and benchmarks never see them

Key pieces:

- `src/span.rs`: `Pos` (1-based line and col, counted in chars), `FileId` (the entry file is `FileId(0)`, and the prelude `FileId::PRELUDE`, which `SourceMap::file` answers but `files` leaves out), and half-open `Span`, which holds a `FileId`. Every token and AST node carries one. `Span::new` puts a span in the entry file, and `Lexer::with_file` lexes another file.
- `src/prelude.stn`: the prelude (`stdlib::PRELUDE`), which `project::link` parses in `FileId::PRELUDE` and puts first in every linked module, keeping its names (`option`); the parser lets only it name a variant `none`. `Rewriter::prelude_variant` rewrites a bare `some`/`none` (not a local) to `option.some`/`option.none` with a zero-width span on the unwritten `option`, `pattern` does the same to `["some"]`, and a written `option.x` is an error. Code that parses without linking (unit tests through `driver::parse_program`, the `codegen` fuzz target) must link, or options do not exist. `none` parses to `ExprKind::Name`, since `Constant` has no `None`. It also defines `enum result[T, E]` (tags 0 `ok`, 1 `err`, which `stone.parse_int_result` and `stone.parse_float_result` make by tag), `enum ordering` (tags 0 `less`, 1 `equal`, 2 `greater`, which builtin `cmp` makes by tag), the traits `eq`, `ord`, `display`, `from[T]`, and `try_from[T]`, and `fn sort[T: ord]`, a stable merge sort in stone that `xs.sort()` uses for anything but int/float/str (`stdlib::PRELUDE_SORT`). Since a prelude enum's name never comes before a written variant, a value may take it (`result = []`): the linker writes the enum's name before a bare variant with an empty span, which `Expr::is_unwritten` recognizes and `Expr::children`, `last_use::expr_names`, `AssignmentCheck`, and `ParameterUse` skip, `checker::may_name_enum` tells the backends whether a name before a dot may be an enum (never a written prelude enum name), the checker's `value_enum` keeps only other enums' names from variables, and `Rewriter::globals` (the entry file's top-level names) and `locals` exempt a variable from the `result.ok` error. `stdlib::PRELUDE_VARIANTS` pairs each bare variant with its enum (`stdlib::prelude_variant`), which `prelude_variant`, `pattern` (a bare `PatternKind::Name` such as `case less:` too), and `prelude_qualified` use, and `prints_bare` covers `ordering`. `project::prelude` renames each prelude `fn` to `prelude.<name>` (`PRELUDE_MODULE`, so a root `prelude.stn` is an error); a prelude function calls no other, so nothing else is rewritten. `Context::types` skips prelude spans, so the unused `sort` body pulls in no runtime.
- `src/project.rs`: multi-file programs. The entry file's directory is the root, and `a/b.stn` is the module `a.b`; directories are only parts of names, so there are no barrel files. `use a.b` binds the module (called as `b.f()`), `use a.b.f` binds a `pub fn` of `a.b` (a module file wins over a function of the same path), and `as` renames. Library modules hold only `use`, `fn`, and `enum`, so importing runs nothing and cycles are fine, and their functions cannot see the entry file's names, types and traits included: the entry file's types and traits keep their plain names, so `checker::visible_type` (a qualified name, a prelude type or trait, or code in `FileId::ENTRY`) hides them from other files in the checker's `resolve_name`, `value_enum`, `value_struct`, `written_type`, `declare_type_params`, `bounds`, and `impl_trait`, and in both backends through `may_name_enum` and `may_name_struct`, so the prelude's local `keys` stays a variable beside a `struct keys`. `pub enum` is imported like a function (`use zoo.Animal`, `Target::Enum`, `public_enums`), and `Rewriter` renames enums to `<module>.<Name>` in signatures and variants (`type_expr`), in front of a variant (`name`, `qualified_enum` for `zoo.Animal.Fish`), and in patterns (`pattern`). `link` loads files through `Sources` (`FsSources`, or `MapSources` in tests), reports `use`/`pub` errors with the checker's wording, and merges every file into one `Mod` in which each library function is renamed to `<module>.<name>` and each use of it rewritten to that name, so the checker and both backends run unchanged (`fn.geometry.shapes.area` is a valid label). `link_in` picks another root, for editors. `pub struct` works as `pub enum` does: `public_types` lists a file's enums and structs together, `is_struct` tells `use geo.Point` to give `Target::Struct` rather than `Target::Enum` (both bind `Binding::Type`), and `module_member` rewrites `geo.Point(x=1)` to a call of the linked name `geo.Point`. `os`, `math`, `random`, `time`, and `fs` are builtin modules with no file (`stdlib::MODULES`, `Loader::resolve_builtin_module`, `Target::BuiltinModule`): `use math`, `use math.sqrt`, and `use math as m` work anywhere, calls are rewritten to linked names such as `math.sqrt` like library functions, and a `math.stn` (or `os.stn`, ...) in the root is an error. The checker reports any `use` left in the module, which can only be a nested one. Tests in `src/project/tests.rs`. An `impl` block must name a struct of its own file (`own_structs`; an enum or an imported struct is an error), is renamed like the struct in a library, and its functions are rewritten as `fn`s are (`Rewriter::function`) but keep their names, since their linked name is the struct's plus theirs; `report_method_collisions` reports a module function with the same linked name as a method. `Rewriter::set_type_params` keeps a generic definition's type parameters (and, for the functions of an `impl` block, its struct's, from `own_structs`) in `type_params`, which `type_expr` never renames, and reports one named like a type the file imports or, in a library, defines (the checker reports the rest). Traits: `public_types` lists `trait`s too, `use geo.Shape` gives `Target::Trait` (bound as `Binding::Type`), a library's traits are renamed `<module>.<Name>`, and `Rewriter::trait_name` rewrites bounds (`Rewriter::bounds`, from `function`) and an `impl` block's trait (`geo.Shape` through `module_type`). `impl Tr for Ty` must be in the file of `Ty` (a struct) or of `Tr` (`Rewriter::impl_type`, with `struct_params`/`trait_names` of every file, for an imported struct's type parameters and a builtin type), except a prelude trait on a builtin type, which the checker reports; `type_expr` never renames `Self`. `report_method_collisions` covers trait default methods (`Trait.m`). A module of `stdlib::SOURCE_MODULES` (only `net`, whose source is `stdlib::net::SOURCE`) is part of stone but written in stone: `Loader::module` adds its embedded source as the library module of that name, at the path `<net>` (`SourceFile::is_builtin`), so it links, checks, and runs like a user's library (functions `net.connect`, ...), `check_builtin_name` rejects a root `net.stn`, and `is_entry` never matches it. Such files, and only they (`Loader::own`), may `use` an internal builtin module of `stdlib::INTERNAL_MODULES` (`net_sys`, whose functions `stdlib::module` and `module_function` find but `MODULES`, the docs test, and editors do not list); anywhere else it is `no module named 'net_sys'`.
- `src/package.rs`: packages. `Manifest::parse` reads a `stone.toml` (`[package]` `name`, `version`, `stone` minimum; `[dependencies]` entries `{ github = "o/r", version }`, `{ gitlab = "g/p", version, host }`, or `{ path }`; `[lints]` levels, `Manifest::lints`) through `package::toml`, a hand-written TOML subset reader whose keys and values keep spans, and `package::version::Version` is semver with `class` (the major, or `0.minor` before 1.0) and `from_tag` (`v1.2.0` or `1.2.0`). `dependency_name_error` rejects builtin module, prelude, and builtin names. `package::resolve::select` is Go's minimal version selection over `Target`s (`Path(dir)` or `Remote(source, version)`, whose `identity` is the directory or the source plus class), asking a closure for each target's `Requirement`s, breadth first, the newest version named winning (`Selection::resolve`, `used`); it never lists releases. `package::store` is the store (`default_dir`: `$STONE_HOME/packages`, `~/.stone/packages`, `%LOCALAPPDATA%\stone\packages`; `package_dir`: `<store>/<host>/<path>/<version>`; `content_hash`: SHA-256 of `<file sha256>  <path>` lines of the kept files, `stone.toml` and `.stn`), and `package::lock::Lock` reads and writes `stone.lock` (`[[package]]` name, github or gitlab, host, version, `hash = "sha256:..."`, sorted). In `project.rs`, `Loader::load_packages` reads the root's `stone.toml` through `Sources` (so `MapSources` tests and the LSP see packages too; `Sources::store` gives the store, `MapSources::set_store` in tests, and `Sources::write` writes, which only `FsSources` and `MapSources`, recording `written`, do), runs `select` with `read_target` (a directory's or the store's manifest; a missing download is an error at the dependency's key and goes in `Linked::missing`; a release's manifest must give the version it was released as, and cannot use a directory), makes a `Package` (root, prefix, name, deps by key, `unavailable` names whose `use` is silent) per used target, and `check_lock` compares each used remote package's hash with `stone.lock`, an error at the locked hash if they differ, else noting `Linked::lock`, which `driver::load` and `check_program` write (`write_lock`) when linking found no errors. Each file records its package (`file_package`, public as `Linked::file_packages`, indexes into `Linked::packages`, whose `PackageInfo` has `root` and `prefix` too), and manifests and the lock are files of the `SourceMap` with no statements (`add_manifest`, `SourceFile::is_package_file`), so their errors render like any other. A dependency's modules link as `<name>.<class>.<path>` (`linked_module`; `geo.1.shapes`, `geo.1` for its `lib.stn`, a digit segment so no module of the program can collide, `.2` and on for two directories of one name and class), `resolve` sends a path whose first name is a dependency of the file's package to `resolve_in` that package (`use geo` is its `lib.stn`), and otherwise resolves in the file's own package root, so a package sees only its own modules and dependencies. `SourceFile::package` names a dependency's files (`is_dependency`), which `unused.rs` never warns about. Downloading is `package::fetch`, behind the `fetch` cargo feature (optional `ureq` with rustls, `flate2`, `tar`; release.yml and CI's feature runs turn it on): `Client` lists a source's releases (GitHub `{api}/repos/{repo}/releases`, GitLab `{api}/projects/{encoded}/releases`, read with `package::json`, a small JSON reader, since serde_json's `PartialEq` impls break `assert_eq!(x, [])` inference in tests), finds a version's tag (`release`, `newest` for a `package::edit::Wanted`), and `download`s `{api}/repos/{repo}/tarball/{tag}` or `.../repository/archive.tar.gz?sha={tag}` into the store through `unpack` (only kept files, nothing outside the archive's top directory, a `.partial` sibling renamed into place); `STONE_GITHUB_API`/`STONE_GITLAB_API` replace the APIs and `GITHUB_TOKEN`/`GITLAB_TOKEN` are sent. `fetch_missing(entry)` links the manifests (an empty entry source) again and again, downloading `Linked::missing`, until nothing is. `package::edit` parses `stone add` specs (`parse_spec`, `Wanted`) and edits `[dependencies]` in place (`set_dependency`, `remove_dependency`, `dependency_value`). The CLI is `src/deps.rs` (`add`, `remove`, `fetch`, `tree`, which prints `Linked::packages`, and `prepare`, which `run`, `build`, and `check` call unless `--offline`); without the feature, `add` and `fetch` explain how to get a build that downloads. `tests/cli/packages.rs` (feature only) runs the commands against a fake GitHub on loopback (`FakeGitHub`, tarballs made by hand in stored gzip). Golden program `tests/programs/packages/` uses packages in `tests/packages/`, and `tests/cli.rs`'s `a_package_from_the_store_runs_and_is_locked` uses a store through `STONE_HOME`.
- `src/unused.rs`: `find(linked, analysis)` warns about what a program defines and never uses, for `stone check` and the LSP only (nothing if linking failed). A symbol is read when it has a `Reference` that is neither its definition nor in `Facts::writes` (bare `Name` targets of `Assign` and `For`, and pattern bindings; `x += 1` and a change's root count as reads), and a function, method, or type is used when a reference lies outside its own definition (and, for a struct, its `impl` blocks), so recursion alone is no use. Never reported: names starting with `_`, `self`, lambdas, the prelude and builtin source files, `pub` definitions and a `pub struct`'s methods (`Facts::exempt`, in every file, since the LSP checks an unused library as an entry file), and the functions and parameters of a trait or an `impl Trait for T` block. Imports come from `project::Import::used`, which the linker sets from `Rewriter::binding`, the one lookup of `use` bindings that records each name it finds. The LSP keeps the warnings in `Document::unused` and tags them `DiagnosticTag::UNNECESSARY`.
- `src/diagnostic.rs`: `Diagnostic` (severity, span, message, and `details`, an `Option<Box<Details>>` so a plain one stays small: a `code`, `Label`s at other spans, notes, and `Help`, possibly with a `Suggestion` to replace a span; built with `with_label`, `with_note`, `with_help`, `with_suggestion`, `with_code`, read with `labels()`, `notes()`, `help()`, `code()`) with `render` (one file) and `render_in` (a closure giving each `FileId`'s path and source, which `SourceMap::render` passes) for the CLI, rustc's layout: marked lines in order (`^` for the span, `-` plus text for a label, texts hung by `|` when several share a line, a lone line between two shown, `...` for more), a `::: file:line:col` block per other file, `= note:`/`= help:` lines, then each suggestion's rewritten line with `~` (`+` for an insertion). A plain diagnostic renders exactly as `location` plus `excerpt`, which runtime site records use. `Diagnostics` returns several as one error. Every stage's errors convert to it.
- Error codes: `src/explain.rs` has `Code`, one per kind of error (`Code::ALL`, numbered `E0001` on in that order and never reused), each with an `Explanation` (`id`, `title`, `text`, a `failing` and a `fixed` example as `(path, source)` files, and a `target` for one only a build reports). Every compile-time error is made with one, `Code::Mismatch.error(span, message)` (which is `Diagnostic::error` plus `with_code`): the checker's `Inference::error(code, span, message)`, `require(code, ..)` and `Constraint::code` (`require_ordered` is always `Unordered`), the `written_type` error vector of `(Code, Span, String)`, the parser's `syntax_error` (`Syntax`), `LexError::code` (`Literal`, or `FormatSpec` in `lex_format_spec`), the linker's and package reader's sites, and `driver::unsupported`; runtime errors (`interpreter::located`, compiled sites) never have one, and warnings have a lint's id instead (see Lints below). The checker tests' `errors` requires a code on every error, and `explain`'s `every_error_before_running_is_made_with_a_code` rejects a bare `Diagnostic::error(` outside the interpreter, `format.rs`, and tests. `stone explain CODE` (`main.rs`'s `explain`, `explain::find`, `explain::text`) prints one, `explain::hint` is the `For more about this error, try ...` line `check` and `with_program` print after coded errors, the LSP sets each diagnostic's `code_description` to `explain::docs_url`, and `docs/reference/errors.md` is `explain::markdown()`, which `tests/docs.rs`'s `error_codes_page_is_current` compares (rewrite it with `STONE_UPDATE_DOCS=1`), while `every_error_code_has_examples_that_behave` checks each failing example's first error has its code and each fixed one passes `stone check` with no warning. `explain::hint` names only errors' codes (a denied lint's included).
- Lints: `explain::Lint` (`Lint::ALL`, ids `W0001` on in that order, never reused, each with a `LintExplanation`: snake_case `name`, `title`, `text`, `failing` and `fixed` examples) is every kind of warning, made with `Lint::LostChange.warning(span, message)` (the id as the diagnostic's code, rendered `warning[W0004]`); `explain`'s `every_warning_is_made_with_a_lint` rejects a bare `Diagnostic::warning(` outside `diagnostic.rs`, `explain.rs`, and tests. `explain::find` gives a `Topic` (`Error(Code)` or `Lint(Lint)`) from `E0005`, `5`, `W0004`, `w4`, or `lost_change`, `explain::text` prints either, `docs_url` sends `W` ids to `LINTS_PAGE`, and `docs/reference/lints.md` is `explain::lints_markdown()` (`LINTS_INTRO`, then each lint), compared by `tests/docs.rs`'s `lints_page_is_current`, while `every_lint_has_examples_that_behave` checks each failing example warns with its id first and each fixed one gets no warning. Five lints come from elsewhere: `UnusedName` and `UnusedImport` (`src/unused.rs`), `ListRepetition`, `LostChange`, and `UnreachableCase` (the checker). The rest are `lint::find` (`src/lint/checks.rs`), one walk over the checked module that `driver::add_lints` runs after the checker, in `check_linked` and `analyze_linked`, only when nothing failed, with the `SourceMap` for the text of suggestions (`Finder::text`, `joined`, which refuses a rewrite that would lose parentheses): `UnreachableCode` (`exits`: `ret`, `break`, `cont`, an `if`/`match` all of whose branches exit, `while true:` without `breaks`; the first statement after it that `is_definition` does not cover, marked on its first line, with a label at the exit), `IgnoredResult` (an expression statement of type `result`), `UselessExpression` (an expression statement that is no call or `?`, suggesting `x = 1` for `x == 1`), `IdentityConversion` (`Analysis::conversions` with source equal to target, builtin, not to a trait, whose recorded source is the coerced type), `BoolComparison`, `SelfComparison` (int, bool, str, bytes only), `SelfAssignment` (never `self = self`, which `gui`'s `app.update` writes to change `self`), `DuplicateKey` (keys through `constant::evaluate` over `Analysis::constants`), `RepeatedCondition` (an `if`/`elif` chain, `if_chain`), and `AlwaysFails` (`/`, `%` by a constant zero, a shift by a constant outside 0..=63, on int or float). `same` compares two expressions written alike that call nothing, and `reads_variable` keeps literals alone (`1 == 1`, `int(5)`, `elif false:`, `1 / 0`) from `SelfComparison`, `RepeatedCondition`, `IdentityConversion`, and `AlwaysFails`. Levels: `lint::Level` (`Allow`, `Warn`, `Deny`) and `lint::Levels` (each lint's, then `warnings` for the rest, with key spans), read by `Manifest::parse` from a `[lints]` table into `Manifest::lints` (an unknown name an error at its key with `did you mean`), put in `Linked::lints` from the root manifest only, and applied by `lint::apply(diagnostics, levels, sources)`, which drops every warning in the prelude, a builtin source file, or a dependency, drops an allowed lint's, and makes a denied lint's an error with a note naming the setting. `driver::check_linked` (so `run`, `build`, `test`), `driver::check_program`, and the LSP's `Document::new` (its analysis and its unused warnings) apply it; `stone check --deny warnings` then runs `lint::deny_warnings`. A lint is a warning rather than an error when the code may be right or may never run; `lint::checks`'s `stones_own_modules_get_no_warnings` keeps the prelude and `SOURCE_MODULES` free of them.
- Rich checker errors: `FunctionInfo` keeps `name_span`, `param_spans` (each parameter's written type, or its name without one; `written_spans`), and `ret_span`, so `expect_because` (behind `expect`, with `mismatch_help` for int and float) and `expect_args` label a parameter's type, `arity_error_at` the definition, a `ret` mismatch the `-> T`, and a reassignment the symbol's first span; `labelable` drops spans in the prelude or written by linking. `AssignmentCheck::first` labels the assignment a maybe-unassigned read skips past, `VALUE_NOTE` explains value semantics on `Outside::Global` and `lost_change`, `undefined` and `method_names` give `did you mean` help through `diagnostic::similar` (optimal string alignment `distance`, which the MCP's `stone_docs` shares), and an untyped parameter's error suggests `: T` as code. Tests render through `rendered` in `src/checker/tests.rs`.
- `src/token.rs`: `Token`/`TokenType` and `RESERVED_KEYWORDS`. `Keyword` and `Operator` hold `&'static str`s (the lexer hands out the entry of `RESERVED_KEYWORDS` or its operator table), so `expect(TokenType::Keyword("fn"))` allocates nothing. The lexer (`src/lexer.rs`) emits Python-style `Indent`/`Dedent`/`Newline` tokens, and `->` as `Arrow`, lexes a string with values as `StringStart(text)`, each value's own tokens, `StringMiddle(text)`, ..., `StringEnd(text)` (`lex_text`, with a `holes` stack of bracket depths so `}` ends a value only at depth 0, and errors for `{}`, a lone `}`, a depth-0 `:`, and a newline inside a value), a string without as `String`, and reads string escapes (`\"`, `\'`, `\\`, `\n`, `\t`, `\r`, `\xhh` up to `\x7f`, never `\x00`, since compiled strings are null-terminated). `Lexer::lex` stops at the first error; `Lexer::lex_recovering`, which `project::Loader::add` uses, records each error, skips the rest of its line (closing any open values), and goes on, and `Loader::add` drops parser errors on a line the lexer cut short, so an unfinished value such as `print("{xs.` keeps the rest of the file analyzed. `context::escape` writes other control characters into `.string` directives as three octal digits, which `asm::parse_string` reads.
- `src/ast.rs`: AST (`Mod`, `Stmt`, `Expr`, `Constant`, `ParserError`, `TypeExpr`, a type written in a signature, which `Arg::annotation` and `FunctionDef`'s `returns` hold, …), modeled on the ASDL in `docs/grammar/stone.asdl`. `ExprKind::JoinedStr { values }` is a string with values (`parse_string`; `parse_strings_loop` joins adjacent literals and their text pieces), each value a `Constant::Str` text piece or a hole expression; a string without values stays a `Constant`. `ExprKind::Tuple` is a tuple of two or more values (`(1, "a")`, ctx `Load`) or, as an `Assign` or `For` target, names to unpack into (`q, r` or `a, (b, c)`, ctx `Store`), whose names `target_names` collects; `TypeExprKind::Tuple` is `tuple[int, str]`. `constant_int` reads an int literal, possibly negated. `Expr` and `Stmt` are structs of a `kind` (`ExprKind`/`StmtKind`, the ASDL variants) plus a `span`, so match on `&expr.kind`. A method call such as `xs.len()` is a `Call` whose `func` is an `Attribute`; attributes mean nothing outside a call. A slice `xs[a:b:c]` is a `Subscript` whose `slice` is an `ExprKind::Slice` (each bound optional), which appears nowhere else; `stdlib::slice_indices` turns its bounds into Python's `slice.indices` for both backends. An augmented assignment `target op= value` is its own `StmtKind::AugAssign`, not rewritten to `Assign`, because an element's indexes are evaluated once: indexes, then the old element (an index out of range fails before the value runs), then the value. The checker records the operation's type at the statement's span; the interpreter's `augmented` and `element` compute it, and `Lowerer::aug_assign` lowers a name target as the equivalent `Assign` (so `a += b` writes over `a` in place) and an element as a borrowed `ListLoad`, the operation (`Lowerer::binary` or `elementwise_tree`), then `store_element`. `StmtKind::EnumDef` holds `Variant`s (name and field `TypeExpr`s), and `StmtKind::Match` holds `MatchCase`s, each a `Pattern` (`PatternKind::Wildcard` for `_`, `Name` to bind, or `Variant` with a `path` such as `["Shape", "Circle"]`, or `["some"]` and `["none"]`, which linking turns into `["option", "some"]`, and field patterns; `Pattern::names` lists what one binds) and a body. Any written type other than `int`/`float`/`bool`/`str`/`list`/`tuple` is `TypeExprKind::Named` (an enum, maybe dotted, or `option[T]`). Variant values need no new expression kind: `Shape.Circle(1.0)` is a `Call` of an `Attribute` and `Shape.Empty` an `Attribute`, which the checker, interpreter, and lowering recognize because the name before the dot is an enum. `StmtKind::StructDef` holds `Field`s (name and `TypeExpr`). `ExprKind::Call` has `keywords`, the named values (`Keyword`) after the positional ones, which only a struct takes; the checker reports them anywhere else. An `Attribute` outside a call is a struct's field, and as a target (ctx `Store`) a change. Parser tests build expected trees with `.into()` and compare them through `without_spans`. `StmtKind::ImplDef` holds an `impl` block's `FunctionDef`s (`parse_impl_def`, `parse_methods`, which hints at `pub fn`). `FunctionDef::type_params`, `StructDef::type_params`, and `EnumDef::type_params` hold the `TypeParam`s of a generic definition (`parse_type_params`, after the name); a use of `T` in a signature is a plain `TypeExprKind::Named`. `ExprKind::Try { value }` is `value?` (`PrimaryOp::Try`, a fourth alternative in `parse_primary_loop0`, so it chains like a call), and `Expr::without_try` strips it, so a statement's or assignment's call is still found through `x = f(x)?`. `StmtKind::TraitDef` holds `FunctionDef`s whose `body` is empty when written without one (only `parse_trait_def` makes such), `ImplDef::trait_name` is the trait before `for`, and `TypeParam::bounds` the `TraitName`s after a colon (dotted for `geo.Shape`).
- `src/parser.rs`: hand-written recursive-descent PEG parser. Rules fail constantly while it backtracks, so failing allocates nothing: `ParserError` is a rule name and a span (`error_here`), `expect` compares before cloning, and an `Expected` holds a `Wanted` token or static text that only `syntax_error` describes. A statement tries only the alternatives its tokens allow (`parse_compound_stmt` by `compound_keyword`, `parse_simple_stmt` by a leading `ret`/`use`/`break`/`cont` and by `assignment_shapes`, a `=` or augmented operator outside brackets); a statement that fails is parsed again with `exhaustive` set, trying everything, so its error is what the full grammar reports, and `shortcuts_parse_every_program_alike` and `shortcuts_report_errors_alike` in the parser tests check both modes agree (and that no rerun succeeds, `rescued`). Syntax errors come from the furthest token any rule failed at: `expect`, `expect_name`, `expect_block_start` (the `:` that opens a block, never quiet, though `Colon` elsewhere is), and `record_expected` note what was wanted there, and "quiet" expectations (operators, keywords, and other optional continuations) only show when nothing else was expected. A rule that recognizes a common mistake notes a `hint` at the token where it stopped, which replaces the message if parsing fails there: values separated by commas without parentheses (`x = 1, 2`, `ret a, b`; `parse_expressions` parses one expression and hints at a comma list), `()`, `(x,)`, `a, = t`, `tuple[int]`, `none` as a type, `Circle()`, and a literal as a pattern. `parse_enum_def` and `parse_match_stmt` read their own `NEWLINE INDENT ... DEDENT` blocks of variants and of `case pattern ':' block`s (`parse_pattern`); `case` is the one keyword besides `in` that is not a quiet expectation. `parse_struct_def` and `parse_fields` read a struct's `NAME ':' type` lines, `parse_args` reads `NAME '=' expression` as a keyword (`parse_kwarg`, looking ahead for `=`) and hints at a positional value after one, and `parse_target_with_star_atom` accepts `t_primary '.' NAME` as a target. `parse_tuple_or_group` parses `'(' expression` once and then decides, so nesting stays linear, and `parse_star_targets` takes names separated by commas, nested in parentheses through `parse_star_atom`. The struct, token helpers, and `parse()` entry are here; rules live in `src/parser/expressions.rs` and `src/parser/statements.rs` as `pub(super)` methods so siblings can call each other. Functions mirror rule names in `docs/grammar/stone.gram` (derived from CPython's grammar), e.g. `parse_t_primary`, `parse_star_targets`, `*_loop0` for repetition. Keep the `.gram`/`.asdl` docs in sync when changing syntax. Traits: `parse_trait_def`, `parse_methods(in_trait)`, `parse_function_def_in(in_trait)` with `parse_function_body` (a `NEWLINE` instead of `':' block` in a trait), `parse_impl_def` with `parse_trait_name` and `parse_impl_target` (`for` is a quiet expectation after the first name), and `parse_type_param` for `T: A + b.B`.
- `src/checker.rs`: `TypeChecker::analyze` infers types (`int`, `float`, `bool`, `str`, `list[T]`, tuples, enums and `option[T]` as `Type::Enum`/`Ty::Enum` with type arguments, structs, and functions, possibly generic) by unification, taking each function's parameter and return types from its signature (`declare_function`, `Inference::written`; no `->` is `Type::Unit`, no value, which `infer` reports anywhere but an expression statement: `'f' returns no value`). The parser accepts a parameter without a type so editors keep working, and `finish` reports it, and a value returned from a function without `->`, suggesting the type inference found, resolves names Python-style (a function's params and assigned names are local, other names are globals or top-level functions, which are visible before their definition), and returns an `Analysis`: sorted diagnostics, the `Type` of every expression keyed by span, and `Symbol`s with every `Reference`. It only accepts what both backends run identically, e.g. conditions must be `bool` (`if 1 or 0:` is an error), arithmetic never mixes `int` and `float` (convert with `int()` or `float()`), even element by element, `==` cannot compare function values or handles, even inside a list, map, tuple, struct, or enum (`equalities`, which `finish` settles through `check_equality`; `uncomparable` finds the function or handle and the struct field holding it, for the error), `range` only appears as a `for` iterable, functions must be top level, a method must be called (`xs.len`, without parentheses, is an error), and top-level code and functions must assign a variable on every path before reading it (`AssignmentCheck`). Since lists are values, a change (`xs[i] = v`, or a method that `stdlib::changes_receiver`, i.e. `append`) is a statement of its own, made to a variable or an element of one (`check_change`; `place` and `place_root` split such a target), and a function cannot change a global. `lost_change` warns when a function changes a parameter it never otherwise reads, and `collect_changed` lists the variables a body changes, for lowering. A change that returns a value (`pop`, or a method that changes `self`) may be anywhere in an expression: `check_changing_call`/`note_changing_call` record each in `changing_calls`, and `check_stmt` (around `check_stmt_kind`) reports any other use of what an inner one changes in the same statement's own expressions (`Stmt::exprs`, `place_mentions`, `first_conflict`, overlapping field paths from `changed_path`), unless it is another changing call's receiver or the call is a statement or the whole value of an assignment (`statement_call`, `assigned_call`); `collect_changed`, `ParameterUse`, and `block_changes_self` find changing calls anywhere in a statement through `Expr::visit`. Arithmetic works on numbers or, element by element, on `list[int]`/`list[float]` with a number broadcast to every element, so an operator becomes an `Arithmetic` that `solve_arithmetic` settles once its operands are known to be lists or numbers, and `finish` forces the rest (an unknown operand becomes a number); meanwhile `Bound`s on its unknown operands (`n` in `n * 2` is `int` or `list[int]`) make `unify` reject a wrong argument at the call, as before. `[x] * n` warns, since Python would repeat it. A tuple (`Type::Tuple`, `Ty::Tuple`, `Kind::Tuple`; `Type::leaves` flattens nested tuples and `field_leaves` finds a field's) is indexed only by a constant in range (`tuple_field`; `subscript_of` returns what it `Indexed`), only once its type is known, except that a constant index into a global a function reads before the code assigning it is checked is settled in `finish` (`DeferredIndex`). Tuples never change (`TUPLE_CHANGE`, also for a list inside one, through `indexed_tuples` in `check_change`), cannot be ordered, iterated, converted, or used in arithmetic or conditions, and unpack into names only, each once, as many as the tuple has values (`check_unpacking_names`, `unpack`, which records each nested pattern's type). A list element may hold at most `MAX_ELEMENT_VALUES` values (`check_element_width`, on list literals and written types). Enums: `declare_enums` registers every top-level `EnumDef` before functions (names first, so variants can hold any enum), with `SymbolKind::Enum` and `SymbolKind::Variant` symbols (a variant's `scope` is its enum, and `visible_at` hides it); `option` is the prelude's enum like any other (`OPTION` names it for the builtins that return one; tag 0 `none`, tag 1 `some`, which `stdlib`'s prelude test pins), declared from its `EnumDef` in `FileId::PRELUDE`, where `declare_enum_names` and `declare_type_params` skip the reserved-name checks; `prints_bare` makes its variants print and appear in errors alone, and `variants`/`variant_display` give any enum type's variants and printed names from `Analysis::enums`. `add_reference` ignores zero-width spans, the names linking wrote. `infer_variant` checks `Shape.Circle(...)` and `Shape.Empty`, and so `option.some(x)` and `option.none`, and `is_some`/`is_none`/`unwrap`/`unwrap_or` are option methods. Reserved names go through `stdlib::is_reserved` (`BUILTINS` plus `PRELUDE_VARIANTS`). `check_match` checks each `Pattern` against the subject (`check_pattern`, `variant_of_pattern`; names bind through `check_target`, and `collect_assigned` collects them, so they are ordinary variables), and `finish` runs `check_cases`, Maranget's usefulness check over `Space`s (`useful`, `missing`, `specialize`), for a missing pattern (an error naming it) and unreachable cases (a warning). Enums and options cannot be converted with `str`, iterated, or used as conditions; a match whose cases all exit `always_exits`. Structs: `declare_types` declares every enum's and struct's name before any variants or fields (`declare_struct_names`, `declare_fields`), so they can name each other, with `SymbolKind::Struct` and `SymbolKind::Field` symbols (a field's `scope` is its struct, and `visible_at` hides it), then reports a struct that `reaches` itself through fields and tuples alone (it may hold itself through a list or enum). A struct is `Type::Struct { name, args }`/`Ty::Struct`, nominal; `Analysis::structs` (`Structs`) holds each one's fields, which `Type::leaves` and `Type::struct_field` (a field's leaf range and type) need, since structs flatten like tuples (`Type::is_flat`), and `values`/`check_element_width` count their leaves. `infer_struct` checks `Point(x=..., y=...)` (every field once, named, no positional values) and records a reference on each keyword's name, `field_of` checks `p.x` (deferred like a tuple index for a global a function reads before its assignment, `DeferredField`), and `struct_display` is the printed name without the module. Places are steps (`Step::Index`/`Step::Field`): `place` splits `ps[i].x` into `ps`, the index `i`, and the field `x`, `place_spans` gives a span per step, and `check_change`, `collect_changed`, and `ParameterUse` treat a field target as a change to its root variable, so a function owns a struct parameter whose field it assigns. Methods: `declare_methods` declares each function of an `impl` block in `functions` under `<struct>.<name>` (`signature` gives a first untyped `self` the struct's type and reports `self` anywhere else), with a `SymbolKind::Method` symbol whose `scope` is the struct, and `struct_methods` records whether it has `self` and, from `find_changing_methods`, whether it changes `self` (a fixpoint over the bodies that types places in `self` from the fields' written types alone). `infer_associated` checks `Point.origin()` (`struct_named`), and `infer_struct_method` a method on a struct, before any builtin method of the same name, applying `append`'s rules (`check_change_of`) to one that changes `self`; a receiver of unknown type is settled in `finish` (`DeferredMethod`, after `DeferredField`s). Every resolved call goes in `Analysis::methods` (`Methods`, a `Method` per call span), which `changed_receiver`, `collect_changed`, and `lost_change` take so a changing method counts as a change. Generics: `declare_type_params` gives each type parameter a `TypeParamInfo` (`Inference::type_params`, indexed by the rigid `Ty::Param`, which unifies only with itself) and a `SymbolKind::TypeParam` symbol scoped to its function, and puts it in `scope_params` while `written_type` reads the signature; `FunctionInfo::type_params` lists them. `Kind::Param` is in no constraint set, `solve_arithmetic` treats it as a known non-number, `check_equality`/`uncomparable` reject it, and `infer_method` reports any method on it. `infer_call` instantiates a generic callee with fresh variables (`substitute`) and records a `PendingInstance` (call span, caller, args); `finish` runs `check_instances` (a cycle through a call that nests a type parameter, found over (parameter -> parameter) edges, is an error; then every concrete instantiation is walked to check list elements and map entries in the generic bodies' `expr_types` against `MAX_ELEMENT_VALUES`) and `check_captured_params` (a global whose type holds a type parameter), then gives lowering `Analysis::instances` (an `Instance` per call span, whose args may be the caller's own `Type::Param`) and `Analysis::type_params` (names by generic function, struct, or enum). Generic types: `Ty::Struct` carries type arguments like `Ty::Enum`, and `EnumInfo`/`StructInfo` hold `type_params`; `declare_types` declares every type's parameters after all names, then fields and variants with them in scope (`enter_type_params`), then `check_growing_types` reports a type that holds itself with nested type arguments (`enum Bad[T]: X(Bad[list[T]])`). `own_type` is a type with its own parameters as arguments (`self` in its `impl` block, whose methods' `FunctionInfo::type_params` are the struct's), `field_type`/`field_types` and `ty_variants` substitute a type's arguments, construction and variants start from `fresh_args`, and `instantiate` fills in a callee's type parameters for every call, function or method, recording the instance. `reaches`, `values`, and `uncomparable` look through type arguments; `stored`/`held_width` and `check_variant_widths` check list elements, map entries, and generic enum variants against `MAX_ELEMENT_VALUES` once filled in. Publicly, `Type::Struct { name, args }`, `Analysis::structs` holds a `StructDef` (`params`, `fields`) and `Analysis::enums` an `EnumDef` (`params`, `variants`); `Type::struct_fields`, `Type::leaves`, `Type::struct_field`, and `variants` substitute arguments, through `Type::substitute`. A method's own type parameters (`fn map[U](self, ...)`, an associated function's, or a trait method's) are declared by `declare_method`/`declare_traits` after the struct's (or `Self` and the trait's), scoped to `<owner>.<key>`, with bounds, so `FunctionInfo::type_params` is `[struct's, own]` (`[Self, trait's, own]`); `instantiate` and `complete_candidates` give each call fresh variables for them through `complete_type_args`, `check_implemented_signature` requires an impl to write as many with the trait's bounds (`type_params_text` for the hint), and `implementation_of`, `Method::resolve(ty, trait_args, own)`, the interpreter's `implementation`, and lowering's `bound_function` carry them after the trait's arguments. Lowering sends a method to `generic` when `Analysis::type_params` has its own key. Traits: `declare_trait_names` (in `declare_types`; each trait gets a `TypeParamInfo` named `Self` whose symbol is the trait's and whose bounds are the trait), `declare_traits` (each method a function `<Trait>.<m>` generic over `Self`, `self` first; a body-less method's parameters get symbols here, for editors), then `declare_methods`, which declares every block's own functions (`declare_method`, which also reports `eq`/`cmp` outside their trait's block, a builtin method's name on a builtin type, and a signature unlike the trait's, `check_implemented_signature`) before giving each type the defaults it keeps (`MethodInfo::default`, whose `function` is the trait's); `impl_trait` and `report_missing_methods` check the block. `impls` maps (trait, type key) to each method's function, a type key being a struct's linked name or `int`/`float`/`bool`/`str` (`ty_key`, `builtin_key_type`), which share `struct_methods`. `TypeParamInfo::bounds` come from `bounds` (functions and methods only; structs and enums report them). `find_changing_methods` also runs over default bodies, forces a type's method to change `self` when its trait's does, and reports one that changes it when the trait's does not. A call on a `Ty::Param` goes through `infer_trait_call` (the one bound with the method, or an error naming both), recorded as a `Method` whose `implementations` maps each implementing type to its function, plus an `Instance` with the receiver's type as `Self`; `method_function` gives a default's `Self` instance for a call on a known type, and `check_method_args`/`check_changing_call` are shared. `check_instances` runs `check_bounds` (`satisfies`) and follows a trait method to the type's own through `implementation_of`. `infer_try` types `?` from `FunctionScope::ret`: a result's error type must unify with the function's, an option needs an option-returning function, and anything else (top level, no `->`) is an error; `infer_method` picks the result rules for `unwrap`/`unwrap_or` only once the receiver is known to be a `result` (as `pop` does for maps), else the option rules, and `RESULT` names the enum. `DISPLAY` names the prelude's `display`, which `satisfies` makes automatic for every type, `str` accepts any value, and `infer_method` treats as a builtin method on any receiver (a `Ty::Param` included, before `infer_trait_call`) unless the struct has its own. `EQ`/`ORD`/`ORDERING` name the prelude's: `satisfies` makes `eq` automatic for comparable types (and `uncomparable` accepts a struct with an `eq` impl and a `T: eq`), `ord` automatic for int/float/str, `require_ordered` (a `Constraint` with `ord`) lets `<` and `sort` take an `ord` struct or `T: ord`, and the builtin methods `eq` and `cmp` (a struct without its own `eq` falls through to the builtin). `Method::resolve` (public) gives the function and copy types a call through a bound makes for a receiver type, and `Analysis` has `bounds` (by type parameter symbol) and `implemented` (traits by type key) for lowering and the LSP.
- Lambdas: `TokenType::VBar`, `ExprKind::Lambda` (`parse_lambdef`, from `parse_expression`, with hints for a body on the next line, a `:` after the bars, and Python's `lambda x:`), which only code that parses without linking sees: `Loader::add` runs `lift::lift_lambdas` on every file right after parsing, turning each lambda into a `FunctionDef` named `ast::lambda_name` (`lambda.<line>.<col>`, renamed `<module>.lambda.<line>.<col>` in a library; `ast::is_lambda` recognizes both) with an empty `name_span` and a body of one `ret`, placed before the top-level statement holding it, inner ones first, and the lambda into a `Name` of it, so everything after linking sees a function named as a value. A capture its statement (an assignment, expression, or `ret`) uses for the last time and mentions once moves into the closure: lowering's `closure_moves_of` and `closure` mark the counted local moved instead of retaining it, and the interpreter's resolver makes it `code::ExprKind::Take`. Lowering's `holds_handle(.., functions)` counts function values in `release_handles`, so a variable holding a closure that may hold a handle is released at its last use, and the interpreter's `Value::drops_early` looks into a closure's captures. `FunctionInfo::captures` drops the capture parameters from a function value's type and its symbol's. `check_function_values` words its rule for a lambda. The interpreter's `Value::Function` holds a `FunctionRef`, the function's id plus a closure's `captures`, which `call_value` passes first. The LSP leaves `is_lambda` functions out of the outline, completion, and `Document::function`.

- Generic traits: `TraitDef::type_params` (`parse_type_params` after the name) and `TraitName::args` (`parse_trait_name` reads `from[int]`, in bounds and `impl` blocks, its span the name's alone). - Operator traits: `checker::OPERATOR_TRAITS` (`ADD` ... `NEG`, also each trait's method name), `operator_trait` (operator to trait) and `trait_operator` (back), and the public `builtin_operator(ty, trait, args)`. `solve_arithmetic` sends a left operand that is a `Ty::Struct` or `Ty::Param` (or an unknown left beside one, once forced, unified with it) to `solve_operator`: a struct's `candidates_where` its methods' `trait_` is the trait, or a `Candidate` per bound of a type parameter naming it, waiting while several fit and the right operand is unknown, then `call_candidate` at the operator's span (an `AugAssign`'s statement span) with an empty name span, so the `Method` (and its `Instance`) is recorded with no reference; `arithmetic` puts no `Bound` on an operand beside a struct or type parameter, a number left of a struct with the trait is its own error, and `satisfies`/`satisfies_bound` give numbers and strings their builtin impls (`impl_trait` reports an impl for a builtin type, which `project.rs` leaves to it like `eq`). `declare_function` lets a function share a prelude trait's name, and `declare_trait_names` words a clash `already defined by the prelude`. - Conversions: `infer_call` sends a call of a builtin type's name, a struct's with one positional value and no keywords, or a type parameter of the function being checked (`conversion_target`) to `infer_conversion`, which settles at once or, for an unknown source, in `finish` (`PendingConversion`, `settle_conversion`): the checker's `builtin_conversion` (and the public `checker::builtin_conversion` over `Type`, which both backends use), else `impl_conversion` (an impl of `from`/`try_from` for the target's key through `impl_for`, recorded as an instance at the call, or a type parameter's bound). `conversion_conflict` and the orphan check in `impl_trait` reject a conversion a type already has, `impl from[X] for str` (use `display`), and one of both traits for one source. `Analysis::conversions` (`Conversion`: target, source, `fallible`, the impl's `function`, or `implementations` through a bound) and `Conversion::resolve` (`Converter::Builtin` or `Function` with copy arguments) drive the interpreter's `eval_conversion`/`convert` (`result` for `try_from`) and lowering's `conversion` (`builtin_conversion`, `float_to_int_result` with two float comparisons, `bytes_result` building `stdlib::BYTE_RANGE`'s text with `stone.str_concat`, `user_call` of the impl, a bound's through `request` and `dispatched`).
- Trait values: a visible trait written as a type is `Ty::Trait`/`Type::Trait`/`Kind::Trait` (the trait's linked name; one counted pointer, so `reaches` stops there, `values` is 1, never a map key, uncomparable). `check_trait_types` rejects a trait with type parameters or a method that lacks `self`, has its own type parameters, or names `Self` outside the receiver (`trait_value_error`, `Code::TraitValue`). `expect_value` (with `coerce`, `infer_expecting`, and `literal_hint` for literals) replaces `expect`/`unify` at arguments, `ret`, fields, variant values, assigned places, `append`/`insert`, and literal elements: a concrete value meeting a trait value records a `PendingCoercion`, settled by `check_coercions` into `Analysis::coercions` (`Coercion`, by the value's span, whose type in `Analysis::types` becomes the trait's) and `Held::TraitValue`; `Shape(x)` is a conversion through `conversion_target`. Compiled, it is an enum-shaped object (`RcKind::Enum`) whose tag is `stone.table.<trait>.<type>`, a table in `.text` (`context::tables`, `Program::tables`) of `jmp`/`b` entries `TABLE_ENTRY` (8) bytes apart: `TABLE_PRINT`, `TABLE_PRINT_NESTED` (`Helper::TraitPrint`, `trait_printer`), then `TABLE_METHODS` on (`Helper::TraitMethod`, `trait_method_thunk`, a changing one rebuilding the object), so no executable needs data relocations; lowering boxes at a coerced span (`coercion`, `coerce`, `trait_value`, with `uncoerced` overriding `span_type` there) and calls with `enum_tag`, `add`, and `Callee::Value` (`trait_value_call`). Patterns: `PatternKind::As` (`parse_as_pattern`), and on a trait value `Circle(r=..)`, `Circle()`, or `int(n)` is a type pattern (`check_type_pattern`, `Analysis::type_patterns`, `Space::Type` in `check_cases`, which needs a catch-all), lowered by comparing the tag with the table's address (`type_test`) and by the interpreter's `Pattern::Type`. Golden programs `trait_values*`, `call_chain_trait_values`, `trait_value_modules/`.
- Function values: the checker's `Ty::Fn`/`Kind::Function` (`Type::Function`, written as `TypeExprKind::Function`) unify part by part, are uncomparable (`uncomparable`), and never map keys. `infer_kind` gives a `Name` that resolves to a function `function_value` (through `instantiate` at the name's span, so a generic one records an instance there), recorded in `Analysis::function_values` (span to linked name), and `check_function_values` in `finish` rejects one whose type holds a `Ty::Param`. `infer_call` sends a variable or any non-name, non-attribute callee to `infer_value_call`, and `infer_struct_method` and `settle_method` a struct field of a function type to `field_call` (a method can never share a field's name); each such call's span goes in `Analysis::indirect_calls`. `project::Rewriter::module_member` rewrites `geo.area` outside a call too. `last_use::GlobalReads` treats a call of a value (`Names::calls_a_value`: a called local, a non-name callee, or a method named like a field that may hold a function, `value_fields`) as a call of every function named as a value anywhere (`of_values`). The interpreter's `Value::Function(Arc<FunctionValue>)` (linked name and printed type, from `Calls::function_values`) is called by `call_value`, which moves arguments into it like a direct call. Compiled, every function value is one counted pointer to an object laid out as an enum value (`RcKind::of` gives `RcKind::Enum`, and `contains_enum` is true, so `stone.free_enum` frees it): its tag is the address of its code, a thunk `stone.fn_value.<label>` (`Helper::FunctionValue`, `function_value_thunk`) that takes the value first and then the arguments, reads a closure's copies from its slots (`FieldGet`), retains what the function owns, and calls the function's copy. A call through a value (`value_call`) reads the tag (`EnumTag`) and calls it with the value first (`Callee::Value`, `call value v3(v2, v4)`), borrowing every argument. A function value that captures nothing is `Inst::FunctionStatic` (`v1 = fn_static stone.fn_value.double`), which writes the thunk's address into the immortal `stone.fn_value.double.static` (`context::function_static`, emitted by `function_statics` from `Context::function_statics`) at each use, since a `.quad` of an address would need relocations the Mach-O linker does not make, and gives it borrowed; a `Closure` makes a new object with `stone.enum_new` (`Lowerer::closure`, `closure_of`, `new_object`), its tag from `FunctionAddress`. Lowering types a lambda's capture parameters in `variables` from `Analysis::types` at their spans, since their symbols are the outer variables'; `print_flat` writes a function's `type_text` as a literal, and `mangle` writes `fn1_int_int`. A call that passes a function by name, or a parameter a copy binds, to a parameter the callee never assigns (`specialized_label`) calls a copy of the callee (a `Request` of an `Instance` plus `BoundFunction`s, labeled `apply..fn0.double`) that takes no argument for it and calls it directly (`Lowerer::constants`). A `Closure` passed so binds too: `BoundFunction::captures` holds its copies' types, the copy takes their values in the parameter's place (`bound_captures`, `bound_values`), and calls the lambda with them first (`user_call_after`), so nothing is allocated; passed on, the copies go along, and used as a value, the copy makes the closure from them. x64 calls a value through r11 (in the argument moves, `call r11`), arm64 through x17 (`blr x17`), both checking the call depth. The prelude's list helpers are checked as calls of their prelude function with the receiver first (`infer_prelude_method`, recording a `Method`, so both backends call them as methods), except `sort_by_key`, which changes its list as `sort` does through the prelude (the interpreter's change path and lowering's `changing_call`, which requires the function to own its receiver); `project::prelude` runs a `Rewriter` over the prelude's functions so they can write `some`/`none`.
- `src/interpreter.rs`: evaluates programs over runtime `Value`s, walking not the AST but the tree `src/interpreter/code.rs` makes of each body once, when it is defined (`code::Resolver`: a function's in `Interpreter::define`, the program's in `define_all`, which runs enum and struct definitions before functions so construction and variants resolve): every variable is a `code::Var`, a slot of the running call's `Frame` (a `Vec<Option<Value>>` laid out by the function's `Layout`, parameters first, then `collect_assigned`'s names) or a global's id, and every call a `code::Call` saying what it calls (`User` by function id, `Builtin` by name, `Struct`, `Method` with its `Rc<Method>`, `Value`, `Conversion`, `Change` for `stdlib::changes_receiver`, `BuiltinMethod`), so running a body hashes no span or name. Functions, globals, structs, and enums live in `Vec`s by id (`Interner` gives a name an id the first time code mentions it, so a call resolved before its callee is defined still finds it), and `StructDef` keeps the ids of its `display`, `eq`, and `cmp` functions. (`Value::Tuple` is an `Rc<[Value]>`, which `assign_target` unpacks after the whole value is evaluated; lists are `Rc<Vec>` values that a change copies first through `Rc::make_mut` if anything else shares them; `eval_place` evaluates a change's indexes and `place_list` walks to the list it changes, counting in `copies` each shared list a change copies, which tests check; after each statement it drops the list variables the statement used for the last time (`code::Stmt::last_uses`, from `LastUses` when the body is resolved), and the statement's top call carries `code::Move`s (the resolver's `top_call` and `moves`) that take its arguments from them first, so a list nothing else holds changes in place); `ControlFlow` carries break/continue/return, and a function sees only its own frame and the globals. An enum value is `Value::Enum(Rc<EnumValue>)` (its printed name, tag, and fields), made by `Interpreter::variant` from the `enums` table that `EnumDef`s fill before anything runs, and matched by `pattern_matches`, and compared by `Value::equals`, which fails with `stdlib::COMPARE_DEPTH` past `MAX_PRINT_DEPTH` nested enum values as compiled code does; `EnumValue`'s `Drop` empties uniquely held values into a worklist, so a long chain drops without recursion. `Value::write` prints values, failing with `stdlib::PRINT_DEPTH` past `stdlib::MAX_PRINT_DEPTH` nested enum and struct values, and offering each struct to a `custom` hook first; `Interpreter::write_value` is the hook that runs a struct's `<linked>.display`, and serves `print` (which builds its whole line, so a failing print writes nothing), `str`, `display`, and `JoinedStr` (every value evaluated first, then written), while `Value::display` (no hook) serves error messages. `Value::Unit` is what a call without a value gives. A struct value is `Value::Struct(Rc<StructValue>)`, its `StructDef` (printed name and field names) filled from `StructDef` statements before anything runs; changes walk `PlaceStep`s through `walk_place` (`place_value`, and `place_list` for a list), copying a shared struct with `Rc::make_mut` (only list copies count in `copies`), `read_place` reads an augmented target's old value, `take_field` moves a field such as `b.items` into a call that replaces it, and `drop_values` frees enum and struct values with one worklist. Arithmetic goes through `Interpreter::arithmetic`, which computes operations on two numbers at once and leaves those with a list operand as a `Lazy` tree that `elementwise` checks for equal lengths and then evaluates one index at a time, which defines the order of runtime errors for compiled code too. `Limits` bounds fuel (loop iterations plus calls), total evaluation depth, and active calls (`max_calls`, the language's `stdlib::MAX_CALL_DEPTH`), and `print` writes to an injectable writer, `input`/`eof` read an injectable `BufRead`, and `args` returns injected arguments (`driver::interpret_with_io`; `interpret_with` gives empty input and no arguments). It flushes the writer before reading, so prompts show first. The driver runs it on a thread with `Limits::STACK_SIZE` of stack so 1,000 nested calls fit. `with_calls` takes the checker's `Calls`, one table for the whole run (`resolved`). `call_method_of_struct` calls a resolved method: an associated function or a method that does not change `self` like any call, and one that does by `eval_place`, the arguments, taking the receiver out of its place (a clone if it is a global the method may read), `invoke(.., keep_self)`, which returns what the method left in `self`, and storing that back. Traits: `StructDef::linked` is the type key, a trait's default methods are functions `<Trait>.<m>` (body-less ones are not defined), and `call_through_bound` runs a call through a bound as the receiver's type's method (`implementation`, from the `Method`'s table), with `eq.eq`/`ord.cmp` on a type without its own falling back to the builtin `call_method`. A `?` that finds an `err` or `none` returns `Err(Propagate(value))`, which `located` passes through and `eval_stmt` turns into `ControlFlow::Return`; `is_result` tells a result's `unwrap` from an option's by the variant's printed name. `values_equal` and `order` replace `Value::equals`/`compare` for `==` and `<`, calling `<struct>.eq`/`<struct>.cmp` when defined; `ordering`/`ordering_of` make and read the prelude's orderings; `sort` of struct values calls `stdlib::PRELUDE_SORT` on a copy of the list.
- Runtime errors must match between backends, and print like checker errors (`file:line:col: error: message`, the source line, and carets) under both. The interpreter turns an error into a `Diagnostic` at the innermost expression that raised it (`interpreter::located`, in `eval_expr` and `arithmetic`; a change's index points at its subscript, `checker::place_spans`), and compiled code prints the same text: lowering records the span of every instruction (`Block::spans`, `term_span`), and each backend's `fail_here` asks `Context::fail_at` for a stub that stores a site record (the location and excerpt `SourceMap::site` renders, in `.rodata`) in `stone.site` before jumping to `stone.fail`. A call to one of `context::FALLIBLE_ROUTINES` stores its site first, for the routine's own siteless `fail_label`s. `recursion is too deep` points at the call, so each call to a stone function checks `stone.call_depth` before calling, and the prologue only counts. Without sources (`AssemblyGenerator::set_sources`, which `driver::compile_module` calls), failures print only `error: message`. A message with `{}` holes (`stdlib::INDEX_RANGE`, `STRING_INDEX_RANGE`, `LENGTHS_DIFFER`) gets ints written into them: the interpreter through `stdlib::fill`, and compiled code by putting them in the backend's `FAIL_VALUES` registers, from `Terminator::Fail`'s values (`fail "...", v1, v2`) or, for the inline list index check, setup lines that a `Context::fail_at_after` stub runs first, then jumping to `stone.fail_detail`, which writes the pieces of text (`Failure::pieces`) and the ints in turn without allocating. The interpreter's error message is what compiled code prints after `error: ` (e.g. `division by zero`, `integer overflow in division`, `recursion is too deep (more than 1000 nested calls)`, `'x' is used before it is assigned`, `list index out of range (index 5, length 2)`, `cannot convert float to int (nan or out of range)`), with exit status 1. Floats follow IEEE 754 except that dividing by 0.0 is `division by zero`, as in Python. Golden programs check them with `.err` files.
- Call chains: a runtime `Diagnostic` keeps the calls that led to it (`Details::calls`, innermost first, `push_call`, `calls()`), which `render_in` writes after the excerpt as `location` + `diagnostic::CALLED_FROM` + ` (N times)` + excerpt per frame, consecutive equal spans as one (`diagnostic::frames`), at most `MAX_FRAMES` (20) frames, then `more_calls` (`... and N more calls`). `SourceMap::render` keeps only calls `SourceMap::shows_call` (line above 0, not the prelude, not a builtin source file), which lowering's classification shares. The interpreter's `here` mirrors lowering's span (saved and restored by `eval_expr` and `eval_stmt`), and `invoke_body` pushes the span it was entered from onto a `Diagnostic` its body returns, so implicit calls (`display`, `eq`, `cmp`, operators) show at their expression's span, and a `stone test` entry (a default span) shows none. Compiled, `ir::Origin` (a span plus `inlined`, an index into `Function::inlined`, a list of `InlinedCall { call, parent }`) is what `Block::spans` and `term_span` hold, `inline::splice` records each call it splices and remaps the callee's own, and `Function::inlined_calls` gives an instruction's chain, which the emitters put in `Context::inlined`. A site record (`Context::site_label`, `site_lines`) is `.long text - .`, `.long n`, then n (`CallKind`, `.long text - .`) pairs, a text being the `.string` location and excerpt (`SiteText`); the site recorded before a helper call leaves the chain out, since the walk finds that call's return entry. After each call of a stone function, a value, or a helper, the emitters write the label `Context::return_label` gives, an entry of `stone.calls` (a `.quad` count, then `.long ret - .`, `.long kind`, `.long site - .`), its `CallKind` being `Frame` (a stone function at a shown span, always written), `Helper` (a helper at a shown span, written only if a stone function was entered below it), `Entered` (a stone function at an unshown span), or `Silent` (only its inlined events count). `main` stores its frame pointer in `stone.main_frame`, and `stone.fail`'s `walk_calls` (x64 `rbp`, arm64 `x29`) writes the site's inlined frames, then follows each frame's return address up to `main`'s (stopping at a null or lower one too), collapsing a repeated record by pointer unless it has inlined calls, allocating nothing. `asm.rs`'s `.long` takes an int or `label - .` (an `X64Rel32` fixup). Golden programs `call_chain*`; the walk and table cost about 1.3 KB per executable plus 12 bytes per call.

- `src/codegen/macho.rs`: the built-in Mach-O linker for arm64 macOS. `link(object, identifier)` writes a PIE `MH_EXECUTE` at `BASE` (`0x1_0000_0000`) with 16 KiB pages: `__PAGEZERO`, `__TEXT` (headers, `__text` on a 64-byte boundary, `__stubs`, `__const` from `.rodata`), `__DATA` (`__got`, `__data`, `__bss`), and `__LINKEDIT` (chained fixups, an export trie of `__mh_execute_header`, the symbol and indirect symbol tables, strings, then the signature), each at the same file offset as in memory except `__LINKEDIT`, which follows `__bss`. It loads `/usr/lib/dyld` and `/usr/lib/libSystem.B.dylib`, enters at `_start` through `LC_MAIN`, and requires macOS 12 (`LC_BUILD_VERSION`) for chained fixups. Each `bl` to a name in `SYSTEM_FUNCTIONS` (undefined in the object) resolves to a stub that jumps through a GOT slot holding a `DYLD_CHAINED_PTR_64_OFFSET` bind; nothing else holds an absolute address, so nothing is rebased. The `LC_UUID` is a hash of the contents, so builds are reproducible, and the file ends with an ad hoc, linker-signed code signature (SHA-256 of each 4 KiB page) because arm64 macOS runs only signed code. Tests in `src/codegen/macho/tests.rs` parse the output back.
- `src/codegen/pe.rs`: the built-in PE32+ linker for x86-64 Windows. `link(object)` writes a console image at `BASE` (`0x1_4000_0000`), sections on 4 KiB in memory and 512 bytes in the file: `.text` (code on a 64-byte boundary, then an 8-byte thunk `jmp QWORD PTR [rip + slot]` per imported function), `.rdata` (`.rodata`, then the import directory, lookup tables, address table, and names, per DLL of `IMPORTS`: `KERNEL32.dll`'s functions and `bcrypt.dll`'s `BCryptGenRandom`), `.data` (with `.bss` as virtual size past its bytes), and `.reloc` (one empty block, since nothing holds an absolute address). A `call` of a name in `IMPORTS` (undefined in the object) resolves to its thunk; anything else undefined is `undefined label 'X'`. The headers are a conventional image's (an MZ stub with its DOS program, `DYNAMIC_BASE`, `HIGH_ENTROPY_VA`, `NX_COMPAT`, OS version 6.0, a timestamp hashed from the contents, and the `CheckSumMappedFile` checksum), since Windows Defender's machine learning flagged a bare image as `Program:Win32/Contebrew.A!ml`, and the stack is reserved and committed at 8 MiB (`STACK_SIZE`), so no frame needs `__chkstk` probes. Tests in `src/codegen/pe/tests.rs` parse the output back, and `every_function_the_runtime_calls_is_imported` checks that `IMPORTS` lists exactly what the shims call.

- `src/codegen/ir.rs`: a small IR between the AST and assembly. A `Function` is blocks (in layout order) of `Inst`s over vregs, each ending in a `Terminator`; it is not SSA, so each stone local is one vreg for the whole function. `Display` prints a readable dump (`v1 = add v0, 1`, `br_lt v1, v0 -> b2, b3`), which tests compare and `STONE_DEBUG` prints. `Inst::Call` writes several `dsts` and `Terminator::Return` returns several values when a stone function returns a tuple (`v2, v3 = call divide(v0, v1)`, `ret v0, v1`), and `Inst::defs` lists what an instruction writes. `Retain` and `Release` (`retain v1`, `release_str v1`, `release_enum v1`) adjust a string's, list's, or enum value's reference count (`RcKind`, whose `codes` writes the 2-bit kinds of slots), and `ListStore` can return the element it replaces (`v3 = list_store v0, 1, v2`). `ListUnique` (`v0 = list_unique v0`) gives a list nothing else refers to before it changes, copying it if its count is above 1; `maybe_null` (`list_unique_or_null`, which only the optimizer makes) lets a null list through. `Terminator::Fail` (`fail "math domain error"`) stops the program with a runtime error, which each backend emits as a jump to a `fail_at` stub, and `FloatSqrt` is `sqrtsd` or `fsqrt`. `ListGet` and `ListSet` read and store a slot known to be in range, `offset` slots past `index` (`list_get v0, v4 + 3`), `ElementSlot` (`v5 = element_slot v0, v3, 7`) is the one checked step that gives where element `v3` of a list of `7`-slot elements starts (failing with `stdlib::INDEX_RANGE`), `DepthCheck` is the call-depth check of a call that was inlined, `ListData` loads a list's element pointer, and `Packed` (`v9 = packed v5, v3, fadd(fmul([v6], v2), [v7])`) runs a `Kernel` over pairs of elements with SIMD, writing the position where it stopped. `FunctionAddress` is a function value, and `Callee::Value` calls one, its operand read after the arguments. `EnumTag` (`v1 = enum_tag v0`), `FieldGet` (`v2 = field_get v0, 1`), and `FieldInit` read an enum value's tag and slots, and `VariantStatic` (`v3 = variant 0`) is the static, immortal value of a variant without values, `stone.variant_<tag>`, which every enum shares by tag (`context::variant_statics`). A `Function` with `helper` is one lowering made, named by its label and called through `Callee::Helper`, which neither counts toward nor checks the call depth, and records the caller's site for its siteless `Fail`s.
- `src/codegen/ir/lower.rs`: `lower` turns a checked AST into a `Program` (every function, then `main`, plus the global names), resolving names like the checker (`checker::collect_assigned`). Tuples are never stored as one value: each value of a tuple variable `t` is a variable of its own, `t.0`, `t.1`, ... across nested tuples (`ir::leaf_name`, `ir::variable_of`, `Lowerer::leaf_names`), a local or a global (`g.t.0`, of which only the first is checked before a function reads it), so counting, moves, and releases work per value, while liveness stays keyed by stone names. `expr_flat` lowers any expression to its values (one, or one per value of a tuple), `tuple_field` picks `t[k]`'s, `user_call` passes a tuple argument as its values and receives a tuple result as several `dsts`, `assign_tuple` copies local values first so `a, b = (b, a)` swaps, `ret (s, s)` gives a local's own reference only once, and `print_flat` prints a tuple, and a list holding one (`print_elements`), a value at a time, with strings quoted. An element of a list of tuples is `width` slots read with `ListGet` and written with `ListSet` at `position * width + field` after one `ElementSlot` (`element_slot`; `element_values`, `store_values`, `load_slots`), which the backends expand inline, comparing the index and then its first slot with the slot count and dividing by the width only for the failure message; `pairs[i][0]` reads only its slot. Evaluation is left to right, so runtime errors happen in the interpreter's order. `x = <expr>` writes `x`'s vreg directly, unless `x` is counted. A global that one top-level statement (not in a block) assigns an int, float, or bool literal, that nothing else assigns or calls a method on (`method_receivers`), and that no earlier statement can call a function reading (`constant_globals`, through `GlobalReads::of_statements`), reads as an immediate, with no load and no check, so `% modulus` divides like a literal. `if`/`while` tests go through `Lowerer::cond`, so comparisons, `and`, `or`, and `not` become `CmpBranch`/`Branch` terminators instead of materialized bools. A `for` loop counts with hidden vregs that the body cannot assign, and copies a variable bound or list first. It also places every `Retain` and `Release` (see "Memory" below), which needs each variable's type, so it takes the checker's `symbols` as well as `types`. A change evaluates its value, the indexes (`place_indexes`), and any arguments, then `unique_place` makes each list from the variable down unique with `ListUnique`, writing it back to the local, the global (only in `main`), or the parent slot, before the store or `stone.list_append`. A function owns the parameters it assigns or changes (`owned_params`), and `give_references` gives each such argument a reference before the call: a temporary's, a retained one, or, for a variable in `movable` (the variables the statement uses for the last time, `Lowerer::last_uses`, from `last_use::live_after`, plus an assigned target), the variable's own, which moves it in so the callee sees a count of 1. `take_from` moves a variable the same way into `ys = xs` or `rows.append(row)` at its last use. A moved variable that its statement does not assign again is left null (`clear_moved`), so releasing it later does nothing. A global moves only into a function that cannot read it, directly or through its calls (`last_use::global_reads`). Enums: `Lowerer::variant` makes a value with `stone.enum_new(tag, kinds, slots)` and `FieldInit`s each value of its fields (taken like a list literal's elements), or `VariantStatic` for one without values (and `none`), and `option_value` lowers `unwrap` (a `Fail` on tag 0) and `unwrap_or`. `match_stmt` evaluates the subject once (through a copy if it is a variable, since a case may assign it), holds a temporary subject in `held` so `ret`, `break`, and `cont` release it (`release_held`), then per case runs `pattern_test` (`EnumTag` and `CmpBranch` down the variants the pattern names) and `pattern_bindings`, retaining every bound value before assigning any. Printing an enum, or a list or tuple holding one (`holds_enum`), calls a helper per enum type, `stone.print_enum.<type>` (`Helper::Print`, `Helper::label`, `enum_printer`), which `lower` makes after every function until none is left asked for (`Lowerer::helper` asks), passing `print_depth` on and failing past `MAX_PRINT_DEPTH`. Structs lower like tuples: each struct variable is leaf variables (`leaf_names`, gated by `is_flat`), `construct` evaluates a struct's keyword values in written order and gives its leaves in field order, and `struct_field` reads a field's leaves (only its slots, for a list element). A change through a field goes through `locate`, which walks a place's steps to a `Location` (a variable's leaves, or slots of a list made unique on the way, each index checked against the element count), then `store_location` or, for `p.x += v` and `ps[i].x += v`, `aug_assign_place`; `unique_place` uses it for any place with a field, and a field assigned the result of a call is movable, so `p.items = f(p.items)` moves the list in. Structs print through a helper per struct type, `stone.print_struct.<name>`, taking the leaves and the depth, since a struct can hold a list of itself; struct values count toward `MAX_PRINT_DEPTH` in both backends. `==` and `!=` on tuples, structs, enum values, lists, and maps (`is_compound`) compare their leaves in turn, stopping at the first that differs (`equal_branch`, `equal_leaves`: `CmpBranch`, `stone.str_eq` for strings, and for an enum value, list, or map a helper per type (`Helper::Equal`): `stone.eq_enum.<type>` (`enum_comparer`), which compares tags and then the variant's slots, `stone.eq_list.<elem>` (`list_comparer`), lengths then elements, and `stone.eq_map.<type>` (`map_comparer`), which closes both up, compares lengths, then finds each left key in the right with `stone.map_find`; each passes `compare_depth` on and fails past `MAX_PRINT_DEPTH` with `stdlib::COMPARE_DEPTH`, which the interpreter's `values_equal` counts the same way, one level per enum value, list, or map); `compare` writes 1 or 0, and `cond` branches on a single one directly, releasing temporaries on both ways out. `lower` takes the whole `Analysis`. A non-generic function or method from any file but the entry file (the prelude, a library, `net`, `gui`) is lowered only once lowered code reaches it: `lower` keeps such bodies in `deferred`, and its worklist scans each newly lowered function for `Callee::User` calls and `FunctionAddress` labels (`referenced_functions`), so unused library code, and the runtime routines only it calls, is never emitted. Generic functions are never lowered as themselves: `lower` collects them, and `user_call` asks `callee_label` for the label of the copy a call needs (the call's `Analysis::instances` args with the current copy's types filled in), which queues an `Instance` in `Context::requested`; the loop that makes helpers also lowers each requested copy with `Lowerer::new_instance`, labeled by `instance_label` (`first..list_int`, the function then each `mangle`d type after `..`). The functions of a generic struct's `impl` block are collected the same way, as `<struct>.<method>`, and `changing_call` labels its callee through `callee_label` too. Helpers are per type with arguments (`mangle` writes `Pair.int_str`). A copy's `Lowerer` has `name` (the label), `base` (the stone name, for `owned_params`, `global_reads`, and variables), `substitution`, and `instance_variables` (its symbols' types filled in, with leaves); every type read goes through `span_type`/`fill`, so counting, flattening, and printing see concrete types. Functions of `impl` blocks lower as functions named `<struct>.<name>`; a method that owns `self` (`returns_self`, since it changes it) returns its values after its result from every `leave`. `struct_call` lowers a resolved call: `user_call` for an associated function or, with the receiver first, a method that borrows `self`, and `changing_call` for one that changes it (`place_indexes`, the arguments through `give_references` from parameter 1, `locate`, then the receiver's values moved into the call, or retained if it is a global the method reads, and `store_location` of the returned values). Traits: `lower` collects a trait's default methods as generic functions over `Self`, and `struct_call` resolves a call with `implementations` from the copy's receiver type (`Method::resolve`), requesting the copy (`request`) and leaving its label in `dispatched` for `callee_label`, or lowers `eq.eq`/`ord.cmp` on a type without its own as the builtin method. `==` is structure-aware: `compared` splits a type into values and structs that implement `eq` (`Compared`, `implements` reading `Context::implemented`), which `equal_leaves` (also in `enum_comparer`) compares with `compare_call` (a call of `<struct>.eq`, retaining what it owns); `compare` orders an `ord` struct by its `cmp`'s tag, and `cond`'s compound fast path is for `==`/`!=` only. The builtin `cmp` (`ordering`) branches to the static variant of each tag, floats by `float_key`'s order (nan checks, then compares, then zeros' sign bits as ints), and `sort` of anything but int/float/str is a `changing_call` of `prelude.sort`'s copy.

- `assert`: `StmtKind::Assert { test, msg }` (`parse_assert_stmt`, a keyword shortcut of `parse_simple_stmt`), checked as a condition plus a `str` message. A test passes on a clean end or `os.exit(0)`; a failure with nothing on stderr gets `error: the test exited with status N`.
- `?`: `Lowerer::try_values` evaluates the operand, branches on `EnumTag` (the `err` or `none` tag from `tag_of`), and on the way out releases every other entry of `owned` (without removing it, since the way on still owns it) and of `pending` (references `Assign` took for a target whose indexes it is still evaluating), then returns the found value itself (an `err` is laid out the same whatever the `ok` type) through `leave`, saving and restoring `moved_locals`, which `leave` empties. The way on copies and retains the payload as `option_value` does. A map literal is owned from its allocation so a `?` in a later entry frees it, and `is_stone_call` looks through `?`, so `x = f(x)?` moves `x`. `option_value` (`unwrapped`) serves `unwrap`, `unwrap_or`, and `unwrap_err` of options and results, and `ok()`/`err()` go through `option_if`. A failed `unwrap`/`unwrap_err` of a result writes `stdlib::UNWRAP_ERR`/`UNWRAP_OK`, `: `, and the other variant's value into a text (`print_flat`, as the interpreter's `unwrap_failure` does with `write_value`) and calls `stone.fail` itself with it, which is in `FALLIBLE_ROUTINES` so the call records its site.
- Maps: the lexer's `LBrace`/`RBrace`, `ExprKind::Dict { keys, values }` (`parse_dict`), and `TypeExprKind::Map`. The checker's `Type::Map`/`Ty::Map` requires `MAP_KEYS` of the key through a `Constraint`, indexes a map in `subscript_of` (`Indexed::Map`, recording `indexed_maps`, and deferring an index into a global a function reads before its assignment through `DeferredIndex::index_ty`), iterates its keys in `for` (`MAP_PAIRS` for `for k, v in m`), gives `keys`/`values`/`items` lists and `pop(key)` an option in `infer_method`, and lets a change step through an entry like a list index, since `place`'s `Step::Index` is a key when the value indexed is a map; `check_entry_width` bounds an entry at `MAX_ELEMENT_VALUES`. The interpreter's `Value::Map(Rc<MapValue>)` keeps entries in a `Vec<Option<_>>` with a `HashMap<MapKey, usize>` of positions: `MapValue::remove` leaves a hole, and `close_up` removes the holes once they are more than half, so `pop` is constant time on average; `iter` skips holes. Its `PlaceStep::Index` holds the evaluated `Value`, which `walk_place` and `read_place` use as a list index or a map key by what they step into (a missing key fails at the step's span), `store_at` stores into either, and `change_map` runs `pop` on a map. Compiled, a map is a list object (`RcKind::List`) whose elements are entries, the key then the value's leaves (`Lowerer::element_kinds`), plus a hash index at `[p + 40]`, a slot every list header now has (48 bytes, 0 unless a map), which `free_list` frees and `list_copy` leaves 0 so a copy rebuilds it on first use. `builtins::map_runtime` (both backends, `context::MAP_ROUTINES`) has `stone.map_find` (first slot of a key's entry or -1; a map with no index and at most `1 << context::SMALL_MAP` entries, which none were ever taken from, is scanned instead, pointers before `stone.str_eq`, and `map_add` builds no index until it would pass that many), `stone.map_add` (reserves an entry's slots at once and zeroes the values, retaining a string key, growing the open-addressing index at half load), `stone.map_take` (marks a key's entry removed and returns its first slot: its index slot becomes -1, which probing passes, and the index's count of removed entries grows, the index being `[capacity, removed, string keys, slots...]`), `stone.map_settle` (closes up when removed entries are more than half), `stone.map_compact` (closes up: `.Lmap_squeeze` moves every entry whose key still finds it, a removed string key being zeroed, over the removed ones, then `.Lmap_rebuild`), and `stone.map_holes` (removed entries not closed up yet, which `len` subtracts); `map_add` closes up before growing, `list_copy` before copying a map (when the program calls `stone.map_take`), and `free_list` skips the zeroed slots, and `stone.map_missing_str` (in `parse_runtime`, a `FALLIBLE_ROUTINES` entry) fails through `stone.fail_quoted`. Lowering: `map_values` (reads, failing per key type through `fail_missing_key`), `map_store`/`map_put` (sets, through `place_indexes` and `unique_place`), the `Dict` literal, `contains`, `map_pop` (`stone.map_take`, the values moved out and the counted slots zeroed, the key released, then `stone.map_settle`), `close_up` (a call of `stone.map_compact` before anything reads a map as a list: `for`, `keys`, `values`, `items`, and printing, only when `Context::shrinks_maps`, from `pops_maps`), `map_column` (`keys`/`values`, a loop of `ListSet`s), `items` (the map itself, retained, since its entries are laid out as a list of tuples), `for k in m` (the flat loop, taking slot 0), and `print_entries` for printing. `locate` steps into a map's entry (`unique_location`, `map_find`, `fail_missing_key`, then the entry's value slots), and `unique_place` and `aug_assign` take that path whenever `through_map` (or `has_field`) says a place goes through one, so `m[k] += v` is `aug_assign_place`. `place_indexes` keeps the keys it evaluated to owned strings in `place_keys`, which `stmt` releases after the statement. `stone.fail_detail1` takes a message with one hole, `stone.fail_detail` two.
- Sets: `ExprKind::Set { elts }` (`parse_dict` goes to `parse_set_rest` when a `,` or `}` follows the first value) and `TypeExprKind::Set`. The checker's set is `Ty::Map(elem, no_value())`, so every map rule (`len`, `in`, `for`, copies, `==`, places, the runtime) holds, and `show`, `type_text`, `Type`'s `Display`, and both `mangle`s write `set[T]`/`set_T`. What keeps maps and sets apart: `require_map_values` (indexing, `settle_index`, `get`, `keys`/`values`/`items`, a map's `pop`) reports a set and puts `Bound::Present` on an unknown value, which `admits` keeps from becoming `no_value`, and `require_set` (each `SET_METHODS` call) unifies the receiver with a set, failing for a map; `instantiate` and `fresh_args` bound every type argument `Present`, so a set never fills `map[K, T]`. The interpreter's set is a `MapValue` whose values are `Value::Unit`, which `Value::write` prints without values and `equals` compares as equal; `change_map` has `add`/`remove`, `call_method` the operations, and `convert` the conversions. - Arithmetic on lists: `Lowerer::elementwise` lowers a list-typed `BinOp`/`UnaryOp` tree (`fused` evaluates its other operands once, left to right, into a `Fused` tree), checks the lengths (`fail_unless`), takes the result from `stone.list_reuse` when an operand is in `movable` (its last use, or the assigned variable) so `a = a * 2.0 + b` writes in place, else `stone.list_new`, and loops with `ListGet`, the ordinary `Binary`/`FloatBinary`/`Neg`/`FloatNeg`, and `ListSet`. When `Fused::packable` (int `+ - *` and negation, float `+ - * /` and negation; ints wrap, so a vector multiply matches) and small enough, a `Packed` instruction does whole groups first and the scalar loop starts at its `done`. The backends expand `Packed` in registers no vreg uses: SSE2 in `xmm3`-`xmm15` (with `rax`/`rcx`/`rdx`), at x86-64 `v3` AVX2 four at a time in `ymm3`-`ymm15` (`packed_operation`, three-operand forms, `vpbroadcastq`, and a `vzeroupper` after the loop's `stop` label, since everything else is legacy SSE), at `v4` AVX-512 eight at a time in `zmm3`-`zmm15` (numbers broadcast straight from general registers, `vpmullq`, `vcmppd k2` and `kortestb` for zero divisors) and then a masked tail (`bzhi` and `kmovb k1`, `{k1}{z}` loads, a `{k1}` store, `Packing::tail`), so `done` is the length; NEON in `v16`-`v31`; and with SVE (`packed_sve`) a vector-length-agnostic `whilelo`/`incd` loop over `z16`-`z31` under `p0`, the last group partial, `fdiv`/`fdivr`/`movprfx` for the destructive division, SVE2's unpredicated `mul`, and `fcmeq p1` plus `ptest` for zero divisors. A backend with no vector int multiply (SSE2, AVX2, NEON) writes `done = 0` for a kernel that `Kernel::multiplies` ints. A float division stops before a group with a zero divisor so the scalar loop reports it at the interpreter's element, and FMA is never used. `pop` and `insert` check their index in IR (`list_position`), then call `stone.list_pop`/`stone.list_insert`; slices call `stone.list_slice`; all of these, `stone.list_extend`, and `stone.list_reuse` are `context::LIST_ROUTINES`, emitted by each backend's `builtins::list_methods` only when called.
- Text: `print`, `str` of anything but int/float/bool/str (`Lowerer::display`), builtin `.display()`, and `JoinedStr` (`Lowerer::joined`, which evaluates every value before writing) all write through the same `print_flat` into a text builder (`text_runtime` in both backends' `builtins.rs`): `stone.text_begin` returns the outer text, every `stone.print_*` routine appends to `stone.text` through `stone.text_append`, and `stone.text_print(outer)` writes the line plus a newline with `stone.write_out` (a short-write loop, also for `input`'s prompt), or `stone.text_eprint(outer)` to stderr for `eprint` (emitted only when used; both share `.Ltext_write` and the loop's `.Lwrite_fd` entry, which takes the file in `rdi` or `x3`), which the interpreter mirrors by flushing stdout before writing to its `errors` writer (`Interpreter::with_errors`), so `2>&1` keeps program order while `stone.text_end(outer)` turns the block, laid out as a string, into one without copying. - `src/codegen/ir/layout.rs`: how compiled code stores each enum type (`Layouts`, built in `lower` from `Analysis::enums`, `structs`, and `held_types`, cached by type with its arguments filled in, in `Context::layouts`). `EnumLayout::Boxed` is the counted object below; `EnumLayout::Flat(FlatLayout)` keeps the value as leaves like a tuple's: the tag (an int) first, then slots grouped by `RcKind` (uncounted, strings, lists, counted objects, `GROUPS`), each group as wide as the variant needing most of it, `variant_slots[tag]` saying which leaves hold that variant's values in order, and 0 (null for a counted slot) in the slots a variant leaves unused, so `option[str]` is `[tag, str]` and `ordering` `[tag]`. A type is boxed if it `reaches` itself through variants, tuples, and structs (not lists or maps), has type parameters, is wider than `MAX_FLAT_SLOTS` (8), or is `forced`: `Layouts::new` boxes, to a fixed point, every flat enum inside a value the program holds in another (`Analysis::held_types`, a `Held` per concrete type: a list element, a map entry, a boxed enum's variants, a closure's copies, recorded by the checker's `check_instances`, `check_variant_widths`, and `check_closures`) that would hold more than `MAX_ELEMENT_VALUES` with it flat. `Layouts::leaves`, `field_leaves`, `struct_field`, and `is_flat` replace `Type::leaves` everywhere lowering flattens, so tuples and structs hold flat enums inline. In `lower.rs`, values of a flat enum go through `expr_flat`/`tuple_values` (variants made by `make_variant`/`variant_into`), and are read through `tag_value` and `variant_values`, which serve both layouts (an `EnumTag` and `FieldGet`s for a boxed one); `match_stmt`, `pattern_test`, `pattern_bindings` (the subject's leaves, each owned one held with its kind in `held`), `option_value`, `is_some` and the others, `ok()`/`err()`, `enum_printer`, `enum_comparer` (taking every leaf of both sides, as `equal_leaves` passes them), and `compare_link` (a flat `cmp` result is its tag) take leaves. A builtin that makes a flat enum deep inside `method` or `call` hands its leaves over through `flat_out` (`flat_result`, at `self.span`, taken by `flat_enum` when `allow_flat` let `expr_into` reach it; `enum_dsts`, `branch_variant`, and `enum_done` for `option_if`, `input`, `float_to_int_result`, and `bytes_result`), except that a flat enum of its tag alone is just that operand. Runtime routines always build boxed enums with boxed enums inside (the ABI), so `flat_enum` and `tuple_values`' conversion arm turn their object into the program's leaves with `unbox_runtime` and `runtime_view`, retaining the leaves and releasing the object (`differs_from_runtime` says when that is needed). `try_values` returns the `err` or `none` it found as it is when the found type is the function's result type (`Context::returns`, by linked name) or both are boxed, and otherwise makes the function's own value from the payload. The runtime tolerates the null slots: `stone.retain_slots`, `stone.list_copy`, `stone.free_list`, and `stone.free_enum` skip a 0 in a counted slot, as the inline `Retain` and `Release` do. Golden programs `enum_layout` and `enum_layout_depth`; bench `options`.
- `src/codegen/ir/inline.rs`: `inline` splices calls of small functions (`MAX_INSTS`, `MAX_BLOCKS`) that call no stone function (`Callee::User` or `Value`), bottom-up so a function whose calls were all inlined is inlined in turn. `splice` splits the block at the call: a `DepthCheck` at the call's span (so `recursion is too deep` stays the interpreter's), copies of the arguments to renamed parameters, the callee's blocks (vregs renamed past the caller's, `loop_depth` added, spans kept, so its runtime errors point at its own lines), each `ret` turned into copies to the call's `dsts` and a jump to the rest of the block. Out-of-line copies stay, since function values take their address. Runs before `opt`.
- `src/codegen/ir/opt.rs`: `optimize`, run by `Context::lower` after inlining, over each function: `fold::fold_constants` (`opt/fold.rs`, sparse conditional constant propagation: constants substituted into `Copy`, arithmetic, `Compare`, `CmpBranch`, and `Return` operands, which both backends take, and an instruction of constants folded by `fold::evaluate` exactly as the interpreter computes, never one that would fail or give nan, whose sign bit the processor picks) with `cfg::simplify_cfg` (`opt/cfg.rs`: same-way branches become jumps, empty jump-only blocks are skipped unless they lead to a loop header, a block absorbs its successor when it is the only way in, unreachable blocks are dropped and the rest renumbered in order); `counters::coalesce_counters` then deletes a `for` loop's `v2 = copy v5; v5 = add v5, 1` when nothing else reads the count, reading `v5` for `v2` and adding 1 at the end of each latch (all jumps), when neither is live at an exit; `place_before` puts blocks a pass adds (`version`, `hoist_checks`, `hoist_data`) right before their loop rather than at the function's end, since an interval has no holes and a far block stretches every shared vreg across calls; `hoist_unique` moves a `list_unique` of a variable out of a natural loop (`loops`, from `dominators`, innermost first; the loop needs a `preheader` ending in a jump) that never writes the variable otherwise, calls out, retains, or releases it, as `list_unique_or_null`; `hoist_checks` checks before a call-free loop each `element_slot` whose list and index the loop never writes that every turn reaches from the header before anything that `may_fail`, in a guard block appended after a copy of the header's test (so it fails exactly as the first turn would, and not for a loop that never runs), turning the ones in the loop into copies; `eliminate` is an available-facts dataflow (`Fact::Slot`, `Fact::Unique`; `transfer` kills on any call, a retain, a release, or a write of a named vreg, but `list_unique` of a list keeps its slots) that turns a repeated `element_slot` into a copy and drops a repeated `list_unique`; `fold_offsets` rewrites a slot that is a constant past another vreg (or a copy of one) in the same block into `ListGet`/`ListSet` `offset`s; `remove_dead` drops removable instructions nothing reads; `rotate_loops` copies a header that only tests onto the end of each latch, so a turn takes one branch; and `hoist_data` gives a loop that calls nothing, makes no list unique, releases nothing, and never writes a list's vreg a block on its one way in that loads each such list's `ListData` once, turning its `ListGet`/`ListSet` into `DataGet`/`DataSet`. `hoist_checks` also hoists an invariant `list_load` in a loop that stores into no list (`a[i]` in `for k: a[i][k]`), and `eliminate` reuses a repeated `list_load` (`Fact::Loaded`, killed by any store, release, or `list_unique`). The IR is not SSA, so every fact names vregs and dies when one is written.
- `src/last_use.rs`: liveness over the AST, shared by both backends: `global_reads` (a `GlobalReads` of the globals each function, including each function of an `impl` block, may read, through its calls too; a call `x.m()` counts as a call of every method named `m`), `live_after` (the variables code after each statement may read, keyed by statement span, iterating loops to a fixed point; nothing is live after `ret` but the `exit` set, `kept_at_exit`, which keeps a method's `self` to the end, and `break`/`cont` see where they jump), and `last_uses` (what each statement mentions that is dead after it). `functions` and `is_method` include trait methods, and `expr_names` counts `==`/`!=` as calls of every method named `eq`, `<` and the others and `.sort()` as calls of `cmp`, `print`, `str`, and `JoinedStr` as calls of `display`, so a global an `eq` or `cmp` reads never moves into a call that compares.
- `src/codegen/ir/liveness.rs`: `analyze` computes live-in/live-out sets, then one interval per vreg (no holes). Each block gets a start position, then each instruction an even position where it reads and the odd one after where it writes. Intervals carry a spill weight (`10^loop_depth` per access) and whether they cross a call.
- `src/codegen/regalloc.rs`: target-independent `linear_scan` (Poletto-Sarkar, spilling the lighter interval) with `Hint`s for preferred registers (`hints` computes them from a function and its argument registers), and `parallel_moves`, which orders simultaneous moves and breaks cycles through a temporary. `float_vregs` finds the vregs that hold floats (float arithmetic, comparisons, and conversions, joined through copies) and are never used as ints, pointers, or indexes; `linear_scan` gives such a vreg one of the backend's `VECTOR` registers when its interval crosses no call and no packed loop (`Interval::touches_vector`), all of them caller-saved, and otherwise a general register as before.
- Returning a tuple: the first values come back in `RESULT_REGS` (x64 `rax`, `rdx`, `rcx`, never allocated; arm64 `x0`-`x7`) and the rest in an area the caller reserves just above the arguments it passes on the stack, which the callee writes at `[rbp + 16 + 8 * (stack params + j - 3)]` or `[x29, #16 + 8 * (stack params + j - 8)]` (`Frame::stack_params`; arm64's `outgoing` covers both). Only stone functions return several values.
- `src/codegen/x64.rs`: `X64Generator`, emitting GNU-as Intel syntax (`.intel_syntax noprefix`). `assemble` runs the checker first and lowers with its types, e.g. to pick a `print` routine per argument. Top-level statements always go in a synthesized `main`, which `_start` (`builtins::start_runtime`) calls with `argc`, `argv`, and `envp` as C would, then makes the `exit_group` syscall with its status. Globals live in `.bss` as `g.<name>`, and user functions are `fn.<name>`, so they cannot collide with runtime labels. String literals are interned and emitted in `.data` with an immortal reference count (`builtins::immortal_string`). Runtime errors jump to a `fail_at(message, span)` stub that records its site and calls `stone.fail`.
- `src/codegen/x64/system.rs` and `src/codegen/x64/windows.rs`: x64's system layer. Every system call goes through `system::system_call(gen, Sys)`: on Linux `mov eax, N` and `syscall`, as before, and on Windows (`X64Generator::for_os`, `target()`) a `call stone.sys_<name>` to a shim that `windows::windows_shims(gen, text)` emits for the calls the text makes (plus `Sys::CpuCount`, which Linux reads from `/sys`). A shim keeps the Linux call's contract: only rax, rcx, and r11 change (it saves rdx, rsi, rdi, r8-r10, and the low halves of xmm0-xmm5, aligns the stack, and leaves 32 bytes of shadow space), its arguments are Linux's (Linux's `open` flags, `OpenFlags` being Linux's for Windows), and a failure is `-errno` with a Linux number: `.Lwin_errno` maps `GetLastError` through `stdlib::fs::WINDOWS_ERRNO`, and `.Lwin_path_errno` adds the path rules of `stdlib::fs::windows_errno` (a missing path through a file is `ENOTDIR`, a denied directory `EISDIR`); an unknown code is `WINDOWS_ERROR_BASE` plus it, which `.Lfs_err` and `error_message` print as `os error N` with Windows' number. Descriptors 0-2 become `GetStdHandle`'s, a write to a console is `WriteConsoleW` of the UTF-8 converted in 8 KiB chunks (`CONSOLE_CHUNK`), paths and names convert through `.Lwin_wide` into `.bss` buffers (`WIDE_PATH_CHARS`), `mmap`/`munmap` are `VirtualAlloc`/`VirtualFree` (`mremap` allocates, copies, and frees), `openat` is `CreateFileW` or, with `O_DIRECTORY`, `FindFirstFileW` of `path\*` (an empty path being `ENOENT`, where `\*` alone is the drive's root), whose entries `getdents64` hands out one per call, `uname` fills the host name from `GetComputerNameExW`, the clocks are `GetSystemTimePreciseAsFileTime` and `QueryPerformanceCounter`, `nanosleep` is `Sleep` rounded up to milliseconds, and `getrandom` is `BCryptGenRandom`. `windows::start_runtime` is Windows' `_start`: it splits `GetCommandLineW` by Rust std's rules and builds `argv` and `envp` in UTF-8 (`WideCharToMultiByte`, `VirtualAlloc`, so the leak check never counts them), then calls `main(argc, argv, envp)` as on Linux; `stone.getenv` compares names ignoring ASCII case there, `os.platform` is `"windows"`, and `os.cwd` skips the leading-`/` check. `os.run` is `process_windows.rs` there (`stone.os_run` over `CreateProcessW`, picked in `fs_runtime`): it searches `PATH` by `stdlib::os::windows_candidates` (a command with `\` or `/` is the only path, else each `;` directory, `.exe` added to a name without an extension, `.bat`/`.cmd` refused as `ERROR_BAD_EXE_FORMAT`), writes the command line as `stdlib::os::windows_command_line` (Rust's `make_command_line`), gives the child `NUL` and two inheritable write ends of overlapped named pipes (`\\.\pipe\stone.<pid and count>`), drains both with overlapped `ReadFile` and `WaitForMultipleObjects`, and takes the status from `GetExitCodeProcess`. `net.rs` is shared: its system calls are `Sys` shims too (`Socket` through `CloseSocket`, `Sys::is_socket`, plus Windows-only `Lookup`), whose Windows versions (`socket_body`, `socket_helpers` with a lazy `WSAStartup` and `.Lwin_wsa_errno`) call `ws2_32.dll`: families 10 and 23 swapped both ways, `SO_REUSEADDR` a no-op, `SO_ERROR` mapped, `F_SETFL`'s `O_NONBLOCK` and `MSG_DONTWAIT` as `ioctlsocket(FIONBIO)`, `poll` of one socket as `select`, and `Lookup` as `GetAddrInfoW` writing `stdlib::net::lookup`'s records; `.Lnet_receive` reads with `recvfrom` there (no descriptors), the shared-memory and received-descriptor slots are never closed, and `enum_runtime(sockets, windows)` dispatches `.Lfree_handle` by `WINDOW_TAG` when a program has both kinds of handle. `net.stn` asks `net_sys.lookup(host, name)` (bytes of a length then an address each, none for an unknown host) when `net_sys.on_windows()`, folded like `gui_sys.on_windows()`, and neither `STONE_HOSTS` nor `STONE_RESOLV_CONF` is set. Windows retries a refused connection for about two seconds. `driver::unsupported` (`WINDOWS_UNSUPPORTED`: only `net.connect_unix`, outside builtin files) rejects what Windows cannot run yet, in `compile_module` for a Windows target and in `run` and `check` on a Windows host. On the host side, `stdlib::os` calls kernel32's `GetComputerNameExW` and `GetActiveProcessorCount` on Windows so both backends agree, `stdlib::fs::io_message` maps Windows error codes through `windows_errno`, `stdlib::os::run` on Windows follows the compiled search (`GetFileAttributesW` first, then `Command`), `stdlib::net`'s `net/system.rs` serves Unix and Windows (`Raw`/`raw_of` over `AsRawFd` or `AsRawSocket`, `poll_one` over libc's `poll` or ws2_32's `WSAPoll`, `Stream::Unix` and `connect_unix` Unix-only), with a `net/unsupported.rs` of uninhabited `Socket`/`Listener` for other systems, `tests/cli/windows.rs` checks `os.run`'s argument quoting and the resolver on Windows (WSL or native), and `tests/cli/unix.rs` holds the cli tests only Unix runs (networking, X11, Wayland), while `tests/cli/windows_gui.rs` drives Win32 windows through `windows_gui.ps1` (PowerShell P/Invoke: finds the window, checks a pixel, posts input, resizes, closes) natively or through WSL's `powershell.exe`, and runs a `--windows-gui` program through `Start-Process` so it has no standard handles, which the runtime already tolerates since `stone.write_out` stops on a failed write and a failed read is the end of input.
- `src/codegen/x64/emit.rs`: instruction selection from allocated IR. Vregs that cross a call get callee-saved `rbx`/`r12`-`r15` (saved in the prologue only if used); others may also use `rsi`, `rdi`, `r8`-`r11`. `rax`, `rcx`, `rdx`, and `xmm0`-`xmm2` are never allocated and serve as scratch, for `idiv`, spilled operands, and wide immediates. `hints` asks for arguments to be computed in their argument registers, parameters to stay where they arrive, and copies and two-address results to share a register. The first six arguments go in registers via `parallel_moves`; arguments past the sixth are pushed, first deepest, and the callee reads them from `[rbp + 16 + ...]`. Each function counts itself in `stone.call_depth`, which each call checks against `MAX_CALL_DEPTH` first, and each global has a `g.<name>.set` flag that `StoreGlobal` sets and that functions check before reading a global, since only top-level reads are checked statically. A float that `float_vregs` picks lives in one of `xmm3`-`xmm15` (`VECTOR`, `Value::Xmm`), where SSE arithmetic, `sqrtsd`, negation (`xorpd` with the sign bit), conversion, and element loads and stores (`movq`) work on it directly (`float_source`, `store_xmm`); any other float travels as its bits in general registers and spill slots like every other value, moving into `xmm0`-`xmm2` for each operation. `mov` moves between the two files with `movq`. The runtime routines reached without a call (free routines, `list_copy`) use only `xmm0`-`xmm2`, which a packed loop shares with `xmm3`-`xmm15` for its own, so a float live at one stays in a general register. Division checks for zero and `MIN / -1` before `idiv`, except that an immediate divisor other than 0 and -1 skips the checks, a power of two becomes shifts (`divide_by_constant`, and `remainder_by_constant`, which subtracts the shifted quotient, in both backends), and any other constant a multiplication by its magic number (`codegen::magic_signed`, Hacker's Delight 10-4, applied by each backend's `magic_quotient` with one-operand `imul` or `smulh`). `%` shares those checks but gives 0 for a divisor of -1. `**` is an inline square-and-multiply loop (`power_loop`) that matches `stdlib::int_pow` and `stdlib::float_pow` operation for operation, and float `%` uses x87 `fprem`, so neither calls libc. List indexing is inline (`list_slot`): it counts negative indexes from the end, checks the result against the list header's length, and jumps to a `fail_at` stub when out of range. `Retain` is an inline `inc`, and `Release` an inline `dec` that calls `stone.free_str` or `stone.free_list` only when the count reaches 0. Those routines preserve every allocatable register, so neither instruction counts as a call for register allocation.
- `src/codegen/arm64.rs` and `src/codegen/arm64/emit.rs`: `Arm64Generator`, emitting GNU-as for AArch64 Linux from the same allocated IR, with the same labels, runtime failures, and `.bss` globals as x64. Arguments go in `x0`-`x7` and past the eighth at the bottom of the caller's frame (`[x29, #16 + 8k]` in the callee). Vregs that cross a call get `x19`-`x28`; others may also use `x0`-`x7` and `x12`-`x15`. `x8`-`x11`, `x16`, `x17`, and `d0`-`d2` are scratch, and `x18` is never used. A float `float_vregs` picks lives in `d3`-`d7` or `d16`-`d31` (`VECTOR`, `Value::Freg`; `d8`-`d15` would need saving), where `fadd`, `fsqrt`, scalar `fneg`, `scvtf`, and `ldr`/`str` of elements work on it directly (`float_operand`, `float_target`). `sp` stays 16-byte aligned at every instruction, so `push_frame`/`pop_frame` save registers in pairs and a frame reserves its spill slots and outgoing arguments once, addressing them from `sp`. Immediate forms of `add`/`sub`/`cmp` read register 31 as `sp`, so their first operand comes from `base`, never `xzr`. Behavior that differs from x86 is checked explicitly: `sdiv` never traps (zero and `MIN / -1` are tested first), `fcvtzs` saturates (the float is range-checked first), and float `%` calls `stone.fmod` (`arm64/floats.rs`), an exact remainder on the floats' bits, as musl's `fmod` computes it, that preserves every allocatable register. Float comparisons use `fcmp` with `mi`/`ls`/`gt`/`ge`/`eq`/`ne`, which are false on nan except `ne`. `src/codegen/arm64/builtins.rs` and `src/codegen/arm64/floats.rs` port every routine of `x64/builtins.rs` and `x64/floats.rs` under the same label and contract; the free routines take the object in `x9`. Every call into the system goes through `builtins::system_call` with a `Sys`: on Linux `mov x8, #n` and `svc #0`, and on macOS a `bl` to a shim `stone.sys_<name>` (`system_shims`, emitted for the calls the text makes) that saves `x1`-`x17` around the `libSystem` function, so only `x0` changes, as with `svc`. libSystem reports failure as -1 (null from `getcwd` and `opendir`) with `errno`, so each shim turns that into `-errno` through `__error` (`ERRNO_FUNCTION`), as Linux returns, and the `*at` calls' shims drop the directory in `x0`; `open`'s shim stores the mode on the stack, since Apple's arm64 convention passes variadic arguments there, and `readdir`'s clears `errno` first so the end of a directory returns 0. The rest of the macOS runtime differs only where the systems do: `_start` is called by dyld as C calls `main`, `MAP_ANON` is `0x1002`, there is no `mremap` (large blocks move to a new mapping), `CLOCK_MONOTONIC` is 6, `os.platform` is `"macos"`, and `os.hostname`/`os.cpu_count` read `sysctl` (`kern.hostname`, `hw.activecpu`) as macOS's `gethostname` and `sysconf` do.
- Memory: compiled strings, lists, and boxed enum values (function values included, laid out as enum values; see `layout.rs` above for the enums kept flat) are reference counted (the interpreter's `Rc` values need nothing more, the checker's occurs check rules out cycles, and enum values never change). An enum value (`builtins::enum_runtime`, emitted when `Context::needs_enums`) is an object with its tag at `[p]`, the 2-bit kinds of its slots at `[p + 8]`, and its slots from `[p + 16]` (`ir::FIELDS_OFFSET`); `stone.free_enum` queues dead values on `stone.free_pending`, linked through their tags, and frees the queue in a loop guarded by `stone.freeing`, releasing strings and lists directly, so freeing never recurses through enum values, and `free_list` hands kind-3 elements to it. `stone.free_list` does the same for lists: a dead list joins `stone.lists_pending`, linked through its capacity slot, and the outermost call frees the queue in a loop guarded by `stone.freeing_lists`, so a struct holding a list of itself a million levels deep frees in constant stack. Every object `p` has its count at `[p - 8]`, and `stone.alloc` (`builtins::memory_runtime`) allocates one with a count of 1. Memory comes from the runtime's own allocator (`builtins::allocator`: `stone.mem_alloc`, `stone.mem_free`, `stone.mem_realloc`, which clobber only scratch registers), not libc: blocks of a power of two from 32 bytes to 64 KiB, with the exponent in an 8-byte header, are kept on a free list per size and cut from 1 MiB regions mapped with `mmap`, and larger blocks get a mapping of their own, grown with `mremap`. The constants are in `context.rs` (`SMALLEST_CLASS`, `LARGEST_CLASS`, `HEAP_REGION`). Strings stay null-terminated `char*`, and a string also holds its length in bytes at `[p - 16]`, so `stone.str_len` reads it rather than scanning (`stone.cstr_len` scans a C string, such as an argument, or a pointer into a string). Every string is made by `stone.str_new` (length, then count, then bytes and terminator), and `immortal_string` writes the same header for literals. A `+` chain on strings or bytes (`Lowerer::string_sum`, `is_string_sum`, which `Assign` adds to the cases that set `movable`) evaluates every operand first and then calls `stone.str_append(sum, piece)` whenever this code owns the sum (a temporary, or the leftmost variable moved from `movable`), else `stone.str_concat`; `str_append` writes in place when the count is 1 and the two differ, growing the allocator block to at least twice its usable size (`mem_realloc`), and otherwise concatenates and releases. Short copies in the string routines go through `x64::builtins::copy_bytes` (`movsb` up to 32 bytes, since `rep movsb` starts slowly). The interpreter's `Value::Str` is an `Rc<String>`, and its `s += t` on a variable pushes onto it through `Rc::make_mut`. A list is a 40-byte header `{len, cap, data, kinds, width}`: `len` and `cap` count 8-byte slots, each element is `width` slots (1, or one per value of a tuple, stored side by side), and `kinds` says, two bits per value of an element, whether it is counted (0 no, 1 strings, 2 lists, 3 enum values) so `stone.free_list` can release them; `stdlib::MAX_ELEMENT_VALUES` (32) bounds the width. `stone.list_new` makes a list of width 1 and `stone.list_new_wide` any other; `free_list`, `list_copy`, `list_extend`, and `list_slice` handle wider elements (the last three through `stone.retain_slots`), while appending, inserting, and popping an element of a list of tuples are `width` calls to the slot routines at the slot where it starts (`Lowerer::add_element`, `pop_element`). `lower.rs` keeps counts exact: variables and list slots each own a reference, expressions are borrowed (variables, globals, literals) or owned temporaries (call results, list elements, which are retained when read) that whatever uses them releases or moves into storage, parameters are borrowed unless the function assigns or changes them, in which case the caller gives them a reference, `ret` releases locals and the lists of enclosing `for` loops, and the end of `main` releases every global. A row in `a[i][k]` is borrowed rather than retained when the index makes no calls (`Lowerer::list_operand`). Before a change, `ListUnique` is an inline count check that calls `stone.list_copy` (in `list_runtime`; it preserves every allocatable register, so it is not a call either) only when the count is above 1, and the copy retains counted elements and drops the original's count by one. `stone.live` counts allocated objects, and `stone.leak_check`, called at the end of `main`, exits with `error: N objects were never freed` when `STONE_LEAK_CHECK` is set.
- Builtins: `BUILTINS` in `src/stdlib.rs` lists function names shared by both backends (`print`, `eprint`, `range`, `int`, `float`, `str`, `input`, `eof`, `args`; `some` is the prelude's variant, not a builtin). `input` returns a `result[str, str]`, `err(stdlib::END_OF_INPUT)` once the input is over: the interpreter's `read_line` gives `None`, and compiled `stone.input` returns 0, which `Lowerer::call` turns into the `err` with an immortal literal, and `BUILTIN_DOCS` documents each for hover and the LSP's builtins reference. `METHODS` (`len`, `append`, `pop`, `insert`, `extend`, `strip`, `split`, `splitlines`, `join`, `find`, `rfind`, `count`, `replace`, `lower`, `upper` (ASCII letters only), `startswith`, `endswith`, `abs` and `floor` (on ints and floats, lowered as `math.abs`/`math.floor` of the receiver), the option methods `is_some`, `is_none`, `unwrap`, `unwrap_or`, the result methods `is_ok`, `is_err`, `unwrap_err`, `ok`, `err` (plus `unwrap` and `unwrap_or`), the map methods `contains` and `get`, and `stdlib::SET_METHODS`) and `METHOD_DOCS` do the same for builtin methods, which are called on a value (`xs.append(1)`, `s.len()`) and are not reserved names. `src/codegen/x64/builtins.rs` (and its port, `src/codegen/arm64/builtins.rs`) emits the hand-written runtime via `&mut dyn AssemblyGenerator`: `stone.print_*` routines (emitted if the program prints), the float runtime in `src/codegen/x64/floats.rs` (`stone.format_float`, shared by `stone.print_float` and `str`'s `stone.str_float`, takes the shortest digit count the way Rust's Dragon `format_shortest` does, then rounds the exact value half to even to that many digits, matching `stdlib::format_float`, which prints floats like Python's `repr`; `stone.decimal_to_float`, behind `float(str)`, multiplies or divides by an exact power of ten for up to 15 digits and 22 places, and otherwise divides two bignums exactly; both work on a small bignum library of 64-bit limbs in `.bss`, `bignum_runtime`), and the string and list runtimes (emitted if the program uses those types). Other routines are emitted only if the lowered IR calls them (`Context::uses`, over `Callee::Runtime` labels): `io_runtime` (`input` and `eof` over a 64 KiB buffer that the `read` syscall fills, `STDIN_BUFFER`), `args_runtime` (from `stone.argc`/`stone.argv`, which `main` saves on entry), `env_runtime` (`stone.getenv`, which walks the `stone.envp` that `main` saves, for `os.env` and the leak check), `parse_runtime` (`stone.parse_int_result` for `int(str)` with an overflow-checked accumulator, `stone.parse_float_result` for `float(str)` checking the grammar then calling `stone.decimal_to_float`, both mirroring `stdlib::parse_int`/`parse_float` and building `ok` or an `err` of a message built at runtime, plus `stone.fail_quoted` for `stone.map_missing_str`), `conversion_runtime`, and `string_methods` (the `context::STRING_METHOD_ROUTINES`: `strip`/`split`, mirroring `stdlib::strip`/`split_whitespace`/`split`; `stone.str_at` and `stone.str_slice_of` behind `s[i]` and `s[a:b:c]`, mirroring `stdlib::str_at`/`str_slice`, which index bytes and fail with `stdlib::CUT_CHARACTER` rather than cut a character outside ASCII, `stone.str_at` returning an entry of a table of 128 immortal one-byte strings; `stone.str_cmp` behind `<` on strings, which compares its -1, 0, or 1 with 0; `stone.str_char`, which a `for` loop over a string calls for the character at each position, stepping by its length; `join`, `find`, `startswith`, and `endswith`; `stone.str_splitlines` (mirroring `stdlib::splitlines`), `stone.str_lower`/`stone.str_upper`, `stone.str_rposition` (behind `rfind`, -1 for none), `stone.str_count`, and `stone.str_replace`, whose two passes count the matches to size the result and then copy, `replace` without a count passing -1, which as unsigned never stops it; an empty text matches at every character boundary, as Rust's `replacen` and `matches` find it in the interpreter). A string inside a printed list prints as `stdlib::repr_in_list` writes it, like Python's `repr`, through `stone.print_str_quoted`. Whitespace is the ASCII set C's `isspace` uses (`stdlib::is_space`). Compiled programs call no libc: on Linux the runtime makes syscalls itself, and on macOS it calls only libSystem's syscall wrappers through `system_call` shims, which run on the 16-byte aligned stack arm64 always keeps; on x64 the stack needs no realigning, since generated code does not keep it aligned. `input` and `args` copy their text into counted strings. The builtin modules' functions are builtins too: `stdlib::MODULES` lists each `BuiltinModule` (its name, doc, and `DOCS` by linked name, such as `os.env`, from `src/stdlib/os.rs`, `math.rs`, `random.rs`, and `time.rs`, which also hold the functions the interpreter calls), and `stdlib::is_builtin` and `stdlib::module_function` accept them. `math` lowers to plain IR in `Lowerer::math` (compares, branches, and loops, with `Terminator::Fail` for its errors, and `FloatSqrt`), matching `stdlib::math` to the bit. Trigonometry (`math.sin` ... `math.atan2`, plus the constants `math.pi`, `math.tau`, `math.e`, which `stdlib::module_constant` gives and lowering reads as immediates) follows `src/stdlib/math/trig.rs`, a musl port within one ulp whose kernels are generic over an `Arith` (floats for the interpreter, IR for lowering), with the medium reduction's second and third rounds tested separately and `atan2` corrected for its quotient's rounding (`quotient_correction`); huge arguments reduce through the prelude's `rem_pio2_large` (Payne-Hanek), which compiled code calls through `Inst::ReducePio2` (`stone.reduce_pio2`, saving every float register). `Lowerer::trig` pushes one `Inst::Trig` per call (`TrigFunc`), and `Context::lower` then runs `ir::trig::share` (an available-facts pass that turns a repeated call into a `Copy` and fuses a `sin` and a `cos` of one vreg into `Inst::SinCos`, the earliest call surviving so errors stay where the interpreter's are) and `ir::trig::expand` (splices each into blocks through a `Builder`, cold blocks placed before the code after the call, never at the function's end, since liveness has no holes and a far block stretches every interval across the function) before inlining. They use `Inst::FloatAbs`, `BinOp::DivUnchecked` (IEEE division, no zero check, compiler-made only), and `FloatToInt { checked: false }` (also `int()` after its range compares); both backends read float constants from a `.rodata` pool (`Context::float_constant`, `.Lf64_<bits>`, written by `Context::emit_constants` after everything else; x64 also takes 16-byte `vector_constant` masks for `andpd`/`xorpd`, `.Lv128_<bits>`), arm64 through `adrp x16` and `ldr d, [x16, :lo12:..]` unless `fmov d, #imm` encodes the value (`asm::arm64::float_imm`) or it is zero (`load_float`). The others lower to the runtime call `context::MODULE_ROUTINES` names (`stone.os_env`, `stone.time_sleep`, ...), except `random.randint` and `random.choice`, which check their arguments in IR and then call `stone.random_below`, and `os.env`, whose `stone.os_env` gives 0 for a variable that is not set. Builtins that may find nothing (`find`, `pop()` without an index, `get`, `os.env`) return an option, which `Lowerer::option_if` builds: `some` of the values on one branch (`new_variant`), the static `none`, retained, on the other. `random_runtime` keeps xoshiro256** state in `.bss` and draws exactly what `stdlib::random::Rng` draws, so seeded programs agree, seeding from `getrandom` (macOS `getentropy`) on first use otherwise; `time_runtime` makes `clock_gettime` and `nanosleep` calls. The `os` routines are emitted by `os_runtime` in both backends (`src/stdlib/os.rs` holds `unsafe` code for libc's `gethostname` and `sysconf`, as do `stdlib::net`'s `poll` and, third, `src/stdlib/gui/windows.rs`'s Win32 calls) from the syscalls behind the libc calls the interpreter makes (`uname` for the host name, `/sys/devices/system/cpu/online` for the processor count, as glibc reads it; `sysctl` on macOS). An `os` routine that differs by system branches on `gen.target().os`. The `fs` routines (`src/codegen/x64/fs.rs`, `src/codegen/arm64/fs.rs`, emitted by `fs_runtime` for the `stone.fs_*` labels) borrow their string arguments and build the whole result themselves with `stone.enum_new`, as `stone.parse_int_result` does, so lowering is the plain `module_routine` call: `ok` of a string, list, or int, or `err` of a message from `.Lfs_err`, which words an error number from the same tables as the interpreter (`stdlib::fs::errors`, per `Os`, with `INVALID_TEXT_CODE` and `NULL_IN_PATH_CODE` for stone's own two errors) or as `os error N` through `stone.str_int`; `Context::lower` adds `stone.str_int`, and `stone.list_sort_str` for `fs.list_dir`, to what is emitted. Files are read whole into a doubling `stone.mem_alloc` buffer and checked by `.Lfs_utf8` (UTF-8 with no null byte, `stdlib::fs::is_text`); flags differ by system and, for `O_DIRECTORY`, by architecture (`context::OpenFlags`). Linux lists a directory with `getdents64`, and macOS with `opendir`/`readdir`. `os.run` is `stdlib::os::run` in the interpreter (Rust's `Command` once per path of `stdlib::os::candidates`, which both backends search in the same order with `execvp`'s error rules, so neither depends on a libc's search) and `stone.os_run` compiled (`src/codegen/x64/process.rs`, `src/codegen/arm64/process.rs`), which `emit_io_runtime` passes to `fs_runtime` rather than `os_runtime` so it shares `.Lfs_err`, `.Lfs_check_path`, and `.Lfs_utf8`: it forks (`clone` with `SIGCHLD` on arm64 Linux, libSystem's `fork` on macOS), the child moves `/dev/null` and two pipes onto fds 0-2 and tries each path with `execve`, writing the final error number to a close-on-exec pipe (`pipe2` flags on Linux, `fcntl` on macOS), and the parent drains both pipes with `poll` (`ppoll` on arm64 Linux), reaps with `wait4`, and builds `ok` with `context::OUTPUT_KINDS`, the status being minus the signal's number for a killed child. Under `cfg(fuzzing)` the interpreter's `os::run` runs nothing. `os.exit` makes the interpreter return the error `interpreter::Exit`, which `driver::run_module` and `main` turn into the exit status without printing anything, and compiled code makes the `exit_group` syscall, skipping the leak check. Adding a builtin means updating `BUILTINS` and `BUILTIN_DOCS`, its type rule in `Inference::infer_builtin`, the interpreter's `Interpreter::call`, and its lowering in `Lowerer::call` (plus an IR instruction and its emission in both backends if it is not a runtime call), plus a program in `tests/programs/`. A function of a builtin module follows the same steps with that module's `DOCS` (a new module also goes in `stdlib::MODULES`), plus either IR lowering or a `MODULE_ROUTINES` entry and a routine in each backend's runtime for the module. Its golden programs cannot be named after a builtin module, so `tests/programs/math_module.stn`, not `math.stn`. A method follows the same steps with `METHODS`, `METHOD_DOCS`, `Inference::infer_method`, `Interpreter::call_method`, and `Lowerer::method`, and both backends evaluate the receiver before the arguments. A method that changes its receiver is also listed in `stdlib::changes_receiver`, and runs through the interpreter's `place_list` and the lowering's `unique_place` instead, evaluating the receiver's indexes, then the arguments, then making the change.

Language server (`lsp/`, crate `stone-lsp`, depends on `lsp-server`, `lsp-types`, `serde_json`):

- `src/lib.rs`: `run(connection)` does the initialize handshake (preferring UTF-8 positions, falling back to UTF-16), keeps open documents with full-text sync, and dispatches requests through `Server::answer`. On every open/change/close it reanalyzes every open document (`Server::reanalyze`), reading files through `Workspace` (open documents' text over the disk), and publishes each one's diagnostics, the changed document first, then each `stone.toml`/`stone.lock` of their programs (`features::package_diagnostics`, merged across documents, with `Server::published` clearing a file no program has anymore). If the client offers dynamic registration, it registers (`watch_packages`) a `workspace/didChangeWatchedFiles` watcher of `**/stone.toml` and `**/stone.lock`, whose events reanalyze everything, so a manifest edit or `stone fetch` (which writes the lock) takes effect.
- Packages in the LSP: linking puts a dependency that cannot be read in `diagnostics` once, at the manifest's key, and an error at each `use` of it in `Linked::unavailable` (from `Loader::failed`, the reason `read_target` gave, plus the hint to run `stone fetch` for a missing download), which only `features::diagnostics` shows. `program_of` takes the nearest directory with a `main.stn` or a `stone.toml` as the root, its `main.stn` or else `lib.stn` as the entry, so a file of a library (or of a downloaded package opened from the store) links with its own dependencies. `hover` and `completion` (wrapping `hover_at`/`completion_at`) and diagnostic messages go through `project::shown_names`, which writes a dependency's prefix (`geo.1`) as its name wherever it starts a name, unless two packages share the name. `Document::package_owning` (a dependency's file, or any file under `Sources::store`) refuses rename. `use_completion` offers the file's package's dependency keys (`package geo 1.2.0`) and, after `geo.`, that package's directory and its `lib.stn`'s functions, linking a one-line `use` program if the program does not load it yet.
- `src/features.rs`: one pure function per request (`diagnostics`, `hover`, `definition`, `references`, `prepare_rename`, `rename`, `document_symbols`, `completion`) over a `Document`, which holds the text, the `stone::driver::analyze_linked` result of the whole program it belongs to (`Document::in_program`: the nearest `main.stn`, or `stone.toml` with its `lib.stn`, at or above it, or the file alone if that program does not use it), its `FileId`, the `SourceMap`, the program's imports, and a `LineIndex`. Spans in other files become locations through `Document::location`, and a library function's symbol is named `<module>.<name>`, which `Document::local_name` shortens. An enum hovers with its variants and outlines with them as children, a variant hovers as `Shape.Circle(float)`, and completion after an enum's name and a `.` offers its variants (`enum_variants`). A struct hovers with its fields and outlines with them as children, a field hovers as `Point.x: float` and renames everywhere, including `x=` in a construction, and completion after a variable holding a struct and a `.` offers its fields (`struct_fields`). Builtins have no stone source, so `run` writes `stdlib::builtins_reference()` (comment-only, documenting each builtin type from `stdlib::TYPE_DOCS`, then each builtin from `stdlib::BUILTIN_DOCS`) to `<temp>/stone-lsp-<version>/builtins.stn`, and `definition` of a builtin jumps to its line there (`Builtins`). A builtin type's name not followed by `(` (`builtin_type_at`) hovers and leads to its type's line, so `int` in `x: int` is the type and in `int(x)` the conversion, except `fn`, which is the type `fn(T1, ...) -> R` (in `TYPE_DOCS`) only when followed by `(`. `Document::tokens` (from `lex_recovering`) feed `Document::in_code`: in a string's text (strictly inside a string token's span, so a value's contents and the spot before its `}` are code) or after a `//` outside one, `hover` shows only the expression's type, `definition` gives nothing, and `completion` offers nothing. `completion` asks `slot` whether a type (`Slot::Type`: after `->`, a definition's or lambda's `name: `, a struct field's line, a variant's parentheses, or the brackets of a type, found from the line's tokens before the word, so a string's text counts for nothing, and `headers`, the lines opening its blocks) or a bound (`Slot::Bound`, after `[T: ` in a definition) comes next, and `type_completion` offers `TYPE_DOCS`, type parameters of the enclosing function and its struct or trait, `Self` in an `impl`/`trait` block, and the file's, imports', and prelude's structs and enums (or traits). After a `.`, a variable's type comes from its symbol and any other receiver's (`xs[0].`, `f(x).`, `p.items.`) from `receiver_type`, which checks the program again through an `Overlay` of `Sources` with the line minus the `.` and the member (then with a `}` there, for an unfinished string value) and takes the type of the expression ending at the dot that starts last, skipping a version with an error on that line; `member_completion` then offers the type's members, always with `display`. `use_completion` offers `SOURCE_MODULES` too, analyzing `use net` on its own for `use net.` before the program uses it. It writes `stdlib::PRELUDE` beside it as `prelude.stn`, where `definition` of `some`, `none`, or `option` goes (`Builtins::prelude_location`); `Document::location` gives nothing for a prelude span, and its symbols cannot be renamed. It writes each of `stdlib::SOURCE_MODULES` there too (`net.stn`), where `definition` of a name in such a file, or of `use net`, goes (`Builtins::builtin_location`), and those names cannot be renamed either. When an editor opens one of those written files unchanged (`Builtins::written`, a `Written::Prelude` or `Written::Module`), `Server::reanalyze` builds its `Document` with `Document::builtin`, which links a program that uses it and points `file` at `FileId::PRELUDE` or the module's builtin file, so it has no errors and `Document::location` keeps its own spans. Add a feature here with unit tests in `src/features/tests.rs`, then wire it into `Server::handle_request` and `capabilities`. A method or associated function hovers as `fn Point.shift(self, dx: float)` (`function_signature`), outlines under its struct after the fields (`struct_methods`, `function_outline`), and completion offers a struct value's methods with `self` (`has_self`) after its fields, and a struct's associated functions after its name and a `.`. A trait hovers with its methods' signatures and outlines with them (`trait_methods`, `SymbolKind::INTERFACE`), a bounded type parameter hovers as `(type parameter) T: Shape` and signatures show bounds (`bounds_of`, from `Analysis::bounds`), completion after a value of a bounded `T` (or `Self` in a default) offers its traits' methods (`bound_methods`) and after a struct value the defaults of the traits it implements (`Analysis::implemented`), and `method_applies` offers `eq`/`cmp` on builtin types.
- `src/mcp.rs` and `src/mcp/tools.rs`: `stone-lsp --mcp` (`main.rs` reads the flag), a Model Context Protocol server for coding agents over stdio (newline-delimited JSON-RPC, `serve`/`serve_in` with a `Context` of the working directory, the `Builtins`, and a snippet's `fuel` and `timeout`; `initialize` with `PROTOCOL_VERSION` and instructions to read `stone_guide`, `ping`, `tools/list`, `tools/call`, an unknown tool `-32602`, a failing tool a result with `isError`). The tools (`TOOLS`) are `stone_guide` (`docs/agents/stone.md` through `include_str!`), `stone_diagnostics` (a file or every `stone_files` file of a directory, each a `Document::in_program` from `FsSources`, rendering `Document::problems`, which `features::diagnostics` shares, and its manifests' errors as `stone check` does), `stone_check_snippet` (`Document::new`), `stone_run_snippet` (`driver::load` and `driver::run_module_with_errors` on a detached thread with `Capped` stdout and stderr), `stone_hover`, `stone_definition`, `stone_references`, `stone_symbols`, `stone_rename` (writes every file of the `WorkspaceEdit` once all are worked out), and `stone_docs` (`BUILTIN_DOCS`, `METHOD_DOCS`, `TYPE_DOCS`, `MODULES`, with similar names for an unknown one). A position is a 1-based `line` plus `symbol` (`find_symbol`, its first whole-word appearance) or `column`, and answers write `file:line:col: <line>` relative to the working directory (`shown_location`). Tests in `src/mcp/tests.rs`, plus a `--mcp` run in `tests/stdio.rs`. The VS Code extension's `mcp.js` offers it through `vscode.lm.registerMcpServerDefinitionProvider` (the `mcpServerDefinitionProviders` contribution, VS Code 1.101+, skipped on older ones), and the repository's `.mcp.json` runs `target/debug/stone-lsp --mcp` for Claude Code.
- Rich diagnostics in the LSP: `lsp_diagnostic` writes each diagnostic through `Diagnostic::map_texts(doc.shown)`, its labels as `related_information` (`span_location`, through `Document::location` with the document's own `file_uri`, so none in the prelude or a builtin module), its notes and help as `note:`/`help:` lines after the message, and its code as the LSP code. `code_actions` (`textDocument/codeAction`, `CodeActionProviderCapability::Simple`) offers each suggestion of a problem the range touches as a preferred `QUICKFIX`. The MCP's `render` uses `render_in` over the program's files.
- `src/line_index.rs`: converts stone's 1-based char positions to LSP's 0-based UTF-16 or UTF-8 positions.
- `src/uri.rs`: converts between `file://` URIs and paths.
- Tests: unit tests for features and positions, `tests/server.rs` over an in-memory connection, and `tests/stdio.rs` against the real binary.
- `driver::analyze_linked` recovers from syntax errors statement by statement, in blocks too (`Parser::parse_recovering`, `parse_statements`), so features keep working around a typo, and it hides type errors until the syntax and `use` errors are fixed.

## Style

These apply to code, comments, docs, and commit messages.

- Never use em dashes.
- Never use emojis.
- Always use American English (e.g. "initialize", "color", "behavior").
- Doc comments (`///`, `//!`) are written in full sentences, and should include examples wherever practical:

  ```rust
  /// Rounds a frame size up to the 16-byte stack alignment required by the System V ABI.
  ///
  /// For example, `align16(20)` returns `32` and `align16(32)` returns `32`.
  fn align16(size: i32) -> i32 {
  ```

- Inline comments (`//`) start lowercase and are almost never full sentences, e.g. `// globals live in main's frame`, not `// Globals live in main's frame.`

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:

- When graphify-out/graph.json exists, run `graphify query "<question>"` before your first grep, search or source-file read for a codebase question, and put this rule in every subagent prompt that explores code. Read raw files only for lines the graph or an earlier read already located. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
- A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected. Do not flag it as churn or suggest skipping the graph rebuild or its hooks.
